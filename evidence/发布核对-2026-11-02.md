# 发布核对 · 2026-11-02（本地 1.17.1 vs registry 1.16.0）

> 目的：把「发版差什么」变成一份**可核对的事实表**，并把命令写到能直接复制执行的程度。
> 只读核对（`npm view` / `npm pack --dry-run` / `git tag`），**未执行 publish、未打 tag、未 push**。

## 事实

| 项 | 值 |
|---|---|
| 本地 `package.json` | `dsh-gokifu-compact@1.17.1` |
| registry `latest` | **1.16.0**（`npm view dsh-gokifu-compact dist-tags` ⇒ `{ "latest": "1.16.0" }`） |
| 本地多出的版本 | **1.17.0、1.17.1 均未发布** |
| git tag | 共 8 个，最后一个 **`v1.16.0`**（无 `v1.17.*`） |
| `check-maintenance` | **通过 8 · 警告 0 · 失败 1** —— 失败项即「当前版本没有 tag」 |
| `npm pack --dry-run` | **128 files / 2.8 MB**，shasum `a8b973e4…`，integrity `sha512-hiNSbrKT…` |
| 包内容可复现性 | `node scripts/pack-check.mjs` → **包内文件全部来自 git 跟踪**（可从任意 commit 复现） |

## 差额（按影响排序）

1. **registry 落后 2 个版本**：所有 `npm i dsh-gokifu-compact` 的用户拿到的是 1.16.0 ——
   1.17.0/1.17.1 的机器级层自愈（C27）、doctor 三态化、`/gokifu/api` 版本对齐等**全部到不了用户手里**。
2. **没有 `v1.17.0` / `v1.17.1` tag** ⇒ `check-maintenance` 永久红；也意味着「某个 commit 对应哪个发布」不可查。
3. 两个版本各自的内容已在 `CHANGELOG.md` 与 `HANDOFF.md` 里逐条记过，无需再整理。

## 要执行的三条（需主人授权；本会话**不执行**）

```bash
# 1) 打 tag（本地，可回滚：git tag -d v1.17.1）
git tag -a v1.17.1 -m "1.17.1: 机器级层自愈 + 图体检/落盘不变量"

# 2) 发布（外部不可逆 —— npm 支持 72h 内 npm unpublish，但会留审计记录）
npm publish

# 3) 核对
npm view dsh-gokifu-compact version            # 期望 1.17.1
node scripts/check-maintenance.mjs            # 期望 失败 0
```

**风险与回滚**：

| 步 | 可逆性 | 回滚 |
|---|---|---|
| `git tag` | 可逆 | `git tag -d v1.17.1` |
| `npm publish` | **不可完全逆** | 72h 内 `npm unpublish dsh-gokifu-compact@1.17.1`（会留痕），或 `npm deprecate` 后发 1.17.2 |
| `git push --tags` | 可逆（远端） | 删除远端 tag（**本会话硬约束禁止 push**） |

## 判定

- **发布不是「代码没准备好」**：七道门禁 + `verify-install 19/19` + 两轮独立审查闭环，代码侧已就绪；
- **发布是「需要人拍板的外部动作」**：与铁律 6 的「安装/重启只能作为终点」同性质 —— 我不代拍。
- 若主人同意，**先重启 DSH**（这样发布的就是已经跑过 live 验证的同一份代码），再按上表三步走。
