### 根因（宿主随包代码，`app.asar` 实读）

1. `workspaceRegistry.archiveSession()` 只做 `setState({...state, archivedSessionIds: [...state.archivedSessionIds, id]})`
   —— 会话**仍在 live store**（`dsh-workspace/lib/index.js`）。
2. `session/disposed` **全仓只有一个 emit 点**：`SessionStore.emitDisposed()`，
   唯一调用者 `detachEntered()`，唯一调用者 `enter()` 返回的 disposer
   ⇒ 只在会话**真的被移出 store**（agent teardown / 应用退出）时发（`dsh-session/lib/index.js`）。
3. 归档实现的是**闸门**不是销毁：`ArchivedSessionGate` 只 `reject` `agent/pre-step`
   ——「归档会话仍然活着、还可能提出下一步」（`dsh-api-session-controller`）。

三条合起来：**「归档」这条路上没有任何一个我们监听得到的事件**。C210 的契约前提是错的。

> 补充旁证：live 上 3 个会话（`ce5dbb93` / `19e0a2c0` / `92873146`）确实有 `closeout`，
> 但时间戳是 06:35/06:39/06:42Z —— 那是宿主**销毁**这些会话的时刻，不是归档时刻。
> 也就是说 `disposed` 钩子本身是好的，只是**触发的不是归档**。

## 七、修法（C216 · 1.17.6）与复验步骤

### 改了什么

| 位置 | 改动 |
|---|---|
| `src/engine.mjs` | 新增 `ctx.on("domain/changed")`：只认 `domain="workspace"` / `table=""` / `operation="put"`，用 **`change.value.archivedSessionIds`**（不回读 registry，见下）与上一次集合差分，挑出**刚被归档**的会话 → 走同一段收尾（full 落盘 → 记 `closeout` → 够长就异步 `trigger:"archive"` 折叠） |
| 同上 | `closeout.source` 记录来源（`archive` / `disposed`）；两个信号撞车时 10s 内只收尾一次；只对「本进程真的处理过事件」的会话收尾（历史归档不许白跑模型） |
| `scripts/doctor.mjs` | 新增「归档收尾（closeout）」：已归档 + 有棋谱 + 没有 closeout ⇒ `warn` 并点名（**这次失败以前完全看不见**） |
| `test/engine-harness.test.mjs` | 新增 4 例；其中「registry 落后一拍」那例做过变异检查（改回 registry 优先 ⇒ 必红） |
| `scripts/handoff-check.mjs` | 补上漏掉的 `loadSessionGraph` import —— 在此之前它**每张图都读不出**、且 ERROR 不计入 fail/warn ⇒ 长期假绿（真实是 FAIL 3 / WARN 11） |

**为什么不许回读 registry**：`global.set()` 里 `emitChanged(...)` 是在 `registry.state = state`
**之前**同步发出的（`dsh-storage-domain` 的 `global.set` + `dsh-workspace` 的 `setState`），
所以 `domain/changed` 回调里读 `registry.archivedSessionIds` 拿到的是**写入前的旧值** —— 差分为空，
收尾照样不会触发。宿主自己的 `WorkspaceFeed` 就是只用 `change.value`、从不回读。
