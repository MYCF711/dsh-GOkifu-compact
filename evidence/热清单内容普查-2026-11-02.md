# 热清单内容普查（2026-11-02，离线渲染 live 图）

> 目的：回答候选 #17（G-2 `derivable` 不可推导性标记）**到底有没有落点**。
> 方法：离线读取 live `graph.json`，用本仓 `renderLedger` 在多个预算下渲染，按 `measureLedgerSections` 分段统计字符数，
> 逐段确认注入内容里**是否存在可再取的「工具输出体」**。
> 生成方式：一次性离线脚本（tmp 下，未入库；等价调用：`fromJSON(读 graph.json)` → `renderLedger(g,{maxTokens})`）。

## 逐段看「注入了什么」

| 段 | 内容形态 | 是否含可再取的输出体 |
|---|---|---|
| root / constraints | **用户原话逐字**（`verbatim`） | 否（这是意图/约束，按 G-2 明令永不标 derivable） |
| failures | 边 id + intent + action 摘要 + **错误原因片段** + seq + `↑later-ok:eNN` / `↻k` | 否（错误原因是**结论/验证信号**；action 只留调用签名） |
| unverified | 未结算边的一行摘要 | 否（是状态，不是载荷） |
| path / options / other | 节点/边 id 链、可选出口、图例 | 否 |
| **工具返回的 stdout / 文件正文 / grep 命中列表** | **完全没有** | — |

## 结论（负结论，已入库）

1. **热清单不注入任何工具输出体** —— 它注入的是失败原因、约束原文、未验证状态与路径。
2. **摘要指令（`facts-prompt.mjs`）也不注入输出体** —— 只有 ROOT / CONSTRAINTS 逐字块与 FAILED_ATTEMPTS 行。
3. 因此 G-2 的"渲染时先降级"在本插件**没有落点**：没有可降级的输出体，加 `derivable` 字段只会变成
   **没有消费者的死数据**（违反本仓「每个指标必须有 live 消费者 + 必须自身被验证」的两条教训）。
4. 若未来要在摘要侧省 token，需要动的是"摘要请求的输入是整段 surface"（C20 实测 input/遮蔽 = 1.36–1.81），
   那是**折叠触发点/保留比例**的取舍，不是 derivable 标记能解决的事。
