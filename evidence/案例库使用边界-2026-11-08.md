## 3. 核心结论

- **PILOT ONLY**：本案例库不可作为正式 benchmark，只能做 pilot / smoke。
- **7 个 P1 只够 smoke，不够 formal**：7 < 8（每类下限），7 ≪ 50（总量）；且 7 个片段只来自 **5 个根会话**，独立单位是 5 而不是 7。
- **48h 窗口内 formal 50/50 不可能由真实案例库独立凑齐**：全库 35 个根会话 / 52 个片段；可用片段（P1+P2+P3）28 个 < 50；selected 20 条也只来自 11 个根会话。
- **P2 不能直接补 formal**：P2 缺归档/约束/测试之一、`outcome` 未标；即使全部升级（7+18=25 < 50）仍不够，且会把题型分布拉向失败/更新类。
- **单工作区（W01）**：没有工作区 holdout，不能声称跨项目泛化。
- **AI 暂定标注不可冒充人工金标**：状态机 `UNLABELED → AI_PROPOSED → HUMAN_REVIEWED → HUMAN_ADJUDICATED`，只有 `HUMAN_ADJUDICATED` 算金标。
- **只报告不抵分**：压缩比、token、延迟、成本、结构不变量、95% CI、reader-limited 都只报告；不存在「压缩比高就抵消任务红」的换算。

## 4. 关键算术

| 量 | 值 | 含义 |
|---|---:|---|
| 正式 N | 50 | K-27 冻结 50 题 |
| 总门槛 | 45/50 = 90% | `Acc_compact ≥ 0.90` |
| 每类门槛 | 8/10 = 80% | 五类各 10 题 |
| P1 片段 / 根会话 | 7 / 5 | 独立单位是 5 |
| 可用片段 | 28 | P1 7 + P2 18 + P3 3 |
| 全部片段 / 根会话 | 52 / 35 | 48h 窗口 |
| selected / 根会话 | 20 / 11 | 首批候选 |

- `6/7 = 85.7% < 90%`：7 个案例时错 1 题就低于总门槛；`7/7 = 100%` 是唯一能过的结果。
- `7 < 8`：每类下限在 7 个案例下结构上不可达；`7 < 10`：ABS 10/10 不可达。
- 1 题 = 14.29 pp（n=7）vs 2.00 pp（n=50）；n=7 的 95% Wilson 区间宽度是 n=50 的 2.08 倍。
- 设计效应：50 题来自 5 个根会话（m=10），`n_eff` = 9–26（ρ=0.1–0.5）；只有 1 题/案例才等于 50 个独立单位。
- McNemar 两侧 p<0.05 至少需要 6 个不一致对；n=7 时只有 6/7 或 7/7 同向才显著。
- 48h 内 35 个根会话 ≈ 17.5 会话/天；要 50 个独立根会话至少约 69h，取整 72h（外推，不是保证）。
