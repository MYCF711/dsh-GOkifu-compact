# 回滚预案（2026-11-02）— 新代码上真机后出问题怎么办

> 用途：本轮循环把 1.17.1 之后的一大堆改动堆到了磁盘，**重启后第一次真正跑**。
> 这份预案回答一个问题：**如果重启后行为不对，怎么在 10 分钟内退回去。**
> 铁律 3：**不要手改** `home/profiles/*/cordis.patch.yml`（运行中写它会整树热重载 → 事故）。
> 所有切换走**设置 UI** 或**文件系统层**（改仓库 checkout / 装已发布版），不碰 patch 文本。

## 零、先判断「要不要回滚」

| 症状 | 严重度 | 建议动作 |
|---|---|---|
| doctor 报「运行实例 build unknown」 | 低（只是没新 buildId） | 不回滚；重启没生效而已 |
| 新字段（`renderErrors` / `skipReasons` / 归因三键）**一直不出现** | 低 | 不回滚；等第一次 fold |
| 某次 fold 失败，但下一轮自动恢复 | 低 | 不回滚；看 `foldFailures` 与 `lastFoldError` |
| **压缩完全不发生**（上下文只涨不压） | **高** | 回滚 ①（设置里换回官方 basic） |
| **节点丢失 / 索引指向不存在节点** | **高** | 回滚 ① → 再跑 `graph-audit --repair`（只增不删） |
| **DSH 启动失败 / 白屏** | **高** | 回滚 ②（换成已发布的 1.16.0） |

## 一、回滚 ①：设置里禁用本插件（最快，30 秒）

1. 打开 **设置 → 插件**（或 preset 选择处）；
2. 把 `dsh-gokifu-compact` 对应的压缩后端从 preset 里**取消勾选** / 切回官方 `compaction-basic`；
3. 设置 UI 内部是**串行 + 失败回滚**的，比手改 patch 安全。

**影响面**：压缩退回官方行为；**棋谱数据不会被删**（`home/chess-context/` 原样保留）。
**可逆性**：完全可逆（再勾回来即可）。
**注意**：这条**不需要重启**（设置 UI 会热生效，正是它被设计出来的用途）。

## 二、回滚 ②：换成 registry 上已发布的 1.16.0（需要网络）

```bash
# 1) 看当前是链接还是装包（profile 里应该是 link 到本地仓库）
node -e "const p=require('D:/DeepSeek Harness/home/profiles/desktop/node_modules/dsh-gokifu-compact/package.json');console.log(p.version)"

# 2) 装已发布版本（覆盖链接 —— 会改 profile 的 node_modules，不改 patch）
cd "D:/DeepSeek Harness/home/profiles/desktop" && npm i dsh-gokifu-compact@1.16.0 --no-save

# 3) 让宿主重新加载（桌面点「重启」；本会话不代劳）
```

**可逆性**：再 `npm i dsh-gokifu-compact@link:...` 或重新走安装脚本即可回到本地链接。
**风险**：npm 安装会改 `profiles/desktop/node_modules/` 与 lockfile —— 这是**文件系统层**，不是 patch 文本，不触发铁律 3 的事故路径。

## 三、回滚 ③：仓库 checkout 回上一个发布点（最彻底，但要重启生效）

```bash
cd "D:/主工作区/repos/dsh-GOkifu-compact"
git status --short            # 先确认没有未提交的在制品（本轮已全部提交）
git tag --list 'v1.16.0'      # 确认 tag 存在
git switch --detach v1.16.0   # 工作树切到 1.16.0
# 之后桌面点「重启」，插件即为 1.16.0 代码
# 要回来：git switch - （回到原来的分支/提交）
```

**可逆性**：`git switch -` 即可回到原提交；**数据不受影响**（`home/chess-context/` 不在仓库里）。
**风险**：切换期间**新旧代码混跑**（运行进程仍是旧内存），所以必须**重启后才算切换完成**。

## 四、数据侧的回滚（只增不删，别反着来）

| 情况 | 动作 | 说明 |
|---|---|---|
| 缺 `nodes/<id>.md` | `node scripts/graph-audit.mjs --repair --dry-run` → 去掉 `--dry-run` | 只补写缺失的派生视图，**不删任何文件** |
| 怀疑某个会话图坏了 | `node scripts/graph-audit.mjs` | 只读体检，先看清「哪一类、哪几个会话」 |
| 图真的坏了（悬空边/索引） | **先整目录备份** `home/chess-context/`，再考虑修复 | 备份是回滚路径；**不要在没备份时跑任何会写的命令** |
| 旧版本图（`version` 不符） | **停窗备份后再升级/降级** | 引擎读到版本不符会重建空图，`full` 落盘会覆盖 `graph.json` |

## 五、明确**不要**做的三件事

1. **不要手改** `cordis.patch.yml`（铁律 3：热重载 → idle 子代理读到已撤销的 inbox → host exit(1)）；
2. **不要**为了「让新代码生效」杀掉进程再拉起（铁律 1：重启只能由用户在桌面点）；
3. **不要**在没备份的情况下跑任何会写 `home/chess-context/` 的命令。
