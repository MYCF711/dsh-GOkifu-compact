## 六条线各自解决了什么

### 1) 压缩质量与成本（14 条含「热清单/成本/保真」）
- 成本从 447 → **415**（−7.2%），每一步都有 bench 基线与 DRIFT 门禁；
- 保真度三探针：**召回**（约束/失败边丢没丢）、**幻觉**（编造的 id）、**越界**（存在但不属于本段）；
- 去年那种「模型把约束丢了没人知道」现在是 `constraintRecall<1 ⇒ 门禁红`。

### 2) 边界与越权审计（10 条含「审计/边界」）
- `boundary-audit` 从 2 条规则长到 **6 条**（行为指导 / 英文 retry / 认知指令 / 祈使短句 / 恢复时机 / 工具治理）；
- 每一次扩规则都因**真实漏网文本**（其中 2 条由外部专员审计发现）；
- 现规则集 **0 findings**，并禁止「用事实口吻写的指令」（如 `treat as unproven`、`需要时按 seq 回读`）。

### 3) 落盘与回滚（C110–C114 打底，C133/C136–C137/C142/C149/C151 补到 9 条）
| 层 | 问题 | 现状 |
|---|---|---|
| C110 | 热清单省略行指向的 `nodes/<id>.md` 可能不存在（空指针） | doctor 检查 + 计数 |
| C111 | 陈旧 md（写了又回滚） | `tree` 落盘时自愈清理（C145 起 **firstWrite 也清**；C142 起空图/重建图**不清**；C144 提供 `--repair`） |
| C112 | 回滚后 `index.md` 还停在回滚前 | 回滚后改 `tree` 落盘 |
| C113 | 回滚后 delta 记账没清 ⇒ 下次 load 把恢复的节点再删一遍 | `restoreFromSnapshot`（图 + dirty） |
| **C142** | **回滚把「还没落盘的变更」一起清了** ⇒ 节点永远写不下去（P0，独立审查抓到） | 快照**连 dirty 一起拍**、回滚后**回填** |

| **C151** | `index.md` 说存在、图里没有（P0 的表征） | `graph-audit` 查三方一致性 |

收口文档：`docs/落盘与回滚不变量.md`（6 条不变量 + 允许现象 + 改动检查清单）。

### 4) 发布与共存（打包 / 安装 / 多插件）
- `pack-check`：包内文件数**以当次输出为准**（C190 起不再写死，避免每加一个文件就漂移）—— 全部来自 git 跟踪（可从任意 commit 复现）；
- **C155/C159**：`src/rooms/*.mjs` **全部进包**（新房间漏白名单 = 用户端 404）+ **真 tarball** 解包后 `import` 子路径可用；
- `cli-routing`：用户装完第一条命令（`npx … doctor`）的路由有测试（历史 ENOENT 事故）；
- `patch-manifest`：引擎行必须 = `<包名>/engine` × 4 个 preset；
- **发现并登记**：`dsh-design-studio:preset-design` 自带 `compaction-basic`（该模式不走棋谱压缩）；
- 新增共存检查：第三方面板 preset 用原生压缩（C94）、preset 覆盖唯一性（C95）、insert id 唯一性（C96，撞到本插件判 error）。
