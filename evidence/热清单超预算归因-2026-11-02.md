# 热清单 over-budget 归因（2026-11-02，含一次被否决的 L6 实验）

> 现象：重启后 `ledger-budget.json` 里 **over-budget 19 / 263 次渲染（7.2%）**，最大超 **117 tokens**。
> 结论先说：**这是设计内的诚实超限，不是 bug；"再降一档丢更多失败边"的方案经实测否决。**

## 1. 离线复现（19 张 live 图 × maxTokens=500）

| 指标 | 值 |
|---|---|
| 超预算图数 | **1 / 19**（`session-d70b7c2f`，574/500，超 74） |
| 该图 sections | root 95 / constraints 276 / failures 898 / options 40 / unverified 78 / path 13 |
| 失败边行数（L3） | 7 条（含标记图例 4 行 ≈ 200 字符） |

线上 19/263 高于离线 1/19，原因：引擎按**当时**的图渲染，图在 fold 前更大；离线只能看到当前快照。

## 2. 成本结构（谁在吃预算）

| 块 | 能否裁剪 | 说明 |
|---|---|---|
| ROOT USER | 只可 clip（L0 900 → L3 168 字符） | 用户原话，任务语义来源 |
| CONSTRAINTS | 只可 clip（≤220 → 120 字符） | 约束丢一条 = 任务变了（合同红线圈） |
| LEARNED（失败边） | L4 只列 20 / L5 只列 10，其余进省略行 | 每条带 id/原因/出处/省略指针，可回查 |
| 标记图例 | 每行都有用（`failed/novel/blocked:*` 的语义） | 4 行 ≈ 200 字符 |
| path / options / unverified | 已按档位折叠 | 见 C-17 |

**超预算的成因**：约束与失败边都**不可再裁**（再裁就要么改任务语义、要么丢失败记忆），
而根目标 + 约束 + 最少失败边的下限在个别会话里已经 > 500 tokens。

## 3. 被否决的方案：加 L6（3 条失败边 + 关标记）

实测数据（`session-d70b7c2f`）：

| 档位 | tokens | 结果 |
|---|---|---|
| L3（现状兜底） | 574 | over-budget 74 |
| L6：3 条失败 + 关标记图例 | **472** | fallback none（装下了） |

**看上去赢了，但实测触发三条已记录的不变量，最终否决**：

1. **M2 不变量**（`test/ledger.test.mjs`）：兜底裁决必须「预算内选最省」，
   否则 L6 永远最省 ⇒ 即使 L5 装得下也被 L6 顶掉 —— bench 夹具 **447 → 238（白丢 209 token 失败记忆）**。
2. **L5 契约**：兜底必须列最近 **10** 条、省略数必须真实（`omitted = 30`）；
   L6 列 3 条与它冲突。
3. **既有设计原则**（`test/ledger.test.mjs` 注释原文）：**「诚实超限 > 静默省略」**。

**决定**：不引入 L6。保持「宁可超预算也不丢约束/失败边」，用 `fallback: over-budget` + `overBudgetBy`
把超限做成**可见的诚实状态**（doctor 告警 + `ledger-budget.json`），而不是默默删信息。

## 4. 什么时候要重新考虑

- over-budget **占比持续 > 20%**，或 `maxOverBudgetBy` 持续 > 200 tokens；
- 或出现「约束本身 > 预算」的会话族（那时要讨论的是约束分级，不是删失败边）。

以上任一出现，再开「约束分级 / 更早 fold」方案，并带 bench A/B。
