# 棋路（user-kifu）判据：`source.rpcId` 的实测依据

> 2026-11-19 · 树：`main@89debc5`（C668 合并后） · 机器：本机 DSH home
> 结论一句话：**「`source.kind ∈ {user,prompt,human}`」不足以判定是使用者手打的字；`source.rpcId` 才够。**
> 所有数字都在本文件里给出**可复现命令**，不引用任何推算值。

## 一、为什么原来的判据不够

`keeper.isHumanMessage` 只看 `source.kind`。而**父代理发给子代理的任务书，`kind` 也是 `"user"`**。

### 实测（400 个真实会话，`kind ∈ {user,prompt,human}` 共 403 条）

| 分类 | 条数 | 占该集合 |
|---|---:|---:|
| 无 `rpcId`，内容为委派任务书（含「你是/孙代理/你只做/任务：/目标：/工作目录」） | 377 | 93.5% |
| 无 `rpcId`，仍是委派口吻（「负责 40_foogallery 的全文读穿」「You are a WordPress plugin security auditor」） | 22 | 5.5% |
| **有 `rpcId`（GUI 交互发送）** | **4** | **1.0%** |

样本（逐字）：
```
[lack rpcId] "你是 37_404-solution 审计的孙代理，只负责 spelling 小范围。工作目录是 D…"
[lack rpcId] "你只做 45_simple-download-monitor 的准备，不做漏洞审计。"
[rpcId]      {"kind":"user","rpcId":"ce5b0a7e-…","clientTimeZone":"Asia/Shanghai"}
```

### 反向验证：本会话（纯 GUI 驱动）

```
本会话 user/message 中 kind∈HUMAN_SOURCES 共 31 条
  带 rpcId : 31 (100%)
  缺 rpcId : 0
```

⇒ 在真实交互会话里，`rpcId` 是**稳定存在**的；在子代理会话里**一条都没有**。

## 三、复现命令

```bash
# ① kind 分布 + 有无 rpcId（400 会话）
node - <<'NODE'
import * as Z from "./src/rooms/zstd-log.mjs";
const logs = Z.listSessionLogs(process.env.DSH_HOME).slice(0, 400);
const kinds = new Map(); let human=0, rpc=0;
for (const f of logs) {
  let evs; try { evs = Z.readSessionEvents(f); } catch { continue; }
  for (const e of evs) {
    if (e?.type !== "user/message") continue;
    const s = e.data?.source ?? {};
    kinds.set(String(s.kind), (kinds.get(String(s.kind))||0)+1);
    if (["user","prompt","human"].includes(String(s.kind))) { human++; if (s.rpcId) rpc++; }
  }
}
console.log(Object.fromEntries([...kinds].sort((a,b)=>b[1]-a[1])));
console.log({ human, withRpcId: rpc });
NODE
```

## 四、这条判据带来的直接后果

1. **C667**：`keeper` 落账时把 `manual`（布尔）+ `srcKind` 写进 user 节点；**不记 `rpcId` 本身**（运行时标识不许落进用户可读文件）。
2. **C668**：归档时把 `manual === true` 的原话按 `order` 逐字投影成 `user-route.json`。
3. **历史数据不可回溯**：C667 之前的图没有 `manual` 字段 ⇒ 旧会话导不出棋路。这是事实限制，不是取舍；`scripts/user-route.mjs --session` 对此会显式报 0 条并说明原因。

## 五、未验证

- `rpcId` 在其他宿主版本 / 其他入口（API、脚本直发）上是否仍然只对「交互发送」成立 —— **未验证**。本文件只能证明：在本机当前宿主上，交互会话 100% 有、子代理会话 0%。
- 若某个历史会话的宿主版本不写 `rpcId`，它会被判成 `manual:false`（漏收）。这属于**已知的真阴性**，不能靠猜补。
