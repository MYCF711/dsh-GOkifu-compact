# 发布说明 · 1.17.2 / 1.17.3（2026-11-02）

> 1.17.2 与 1.17.3 **内容相同**（1.17.3 只是传播确认后补的版本号）。相对 **1.17.1** 只多两件事：一个真能力、一个口径修正。

## 一、新能力 · 归档收尾折叠（C210）

**场景**：你做完一件事，直接把会话**归档**了。

**以前**：归档发生在「上一次折叠之后」，那一段只进了图（节点/边），**没有任何压缩产物** ——
kifu 看起来完整，其实最后一段从没被压过。

**现在**：插件监听宿主的 `session/disposed`，做三件事（**全部 best-effort，绝不阻塞归档**）：

| 步骤 | 动作 | 失败时 |
|---|---|---|
| ① | 立刻 `full` 落盘（节点 / index / 标量） | 只记日志，归档继续 |
| ② | 图上记 `closeout: { at, eventsSinceLastFold, folds }` | 同上 |
| ③ | 尾巴 ≥ `closeoutMinEvents`（默认 **40**）⇒ 异步跑一次 `trigger: "archive"` 的折叠 | 硬超时 `closeoutTimeoutMs`（默认 **90s**） |

**三条新配置**（写进 preset 的引擎块即可）：

```yaml
closeoutFold: true        # 关掉就完全不补（仍会落盘 + 记 closeout）
closeoutMinEvents: 40     # 尾巴太短就不值得花一次模型调用
closeoutTimeoutMs: 90000  # 收尾折叠的硬超时
```

## 二、修正 · 计数口径（C211）

手工压缩写下的 `foldMark` **没有区间**。以前它被算进「折叠次数」，于是出现「证据 28 / 磁盘 29」这种
**假不一致**（`handoff-check` 的 ⑳ 会红）。现在两个工具都只数**有区间**的折叠，另出 `manual` 计数。

## 三、升级与回滚

- **升级**：`dsh plugin add dsh-gokifu-compact@1.17.2`（或按你惯用的安装方式），然后**重启 DSH** 生效；
- **回滚**：`dsh-gokifu-compact revert`（或装回 `@1.17.1`），重启；
- 归档收尾是**纯增量**：关掉 `closeoutFold` 即回到旧行为，数据层面只多一个 `closeout` 字段。
