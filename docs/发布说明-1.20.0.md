# dsh-GOkifu-compact 1.20.0 发布说明

> 发布日 2026-11-28。上一版 1.19.1。
> 本版**不改压缩算法、不改默认行为**；主题是「把看起来在生效、其实没生效的地方一次性清掉」。
> 配置面契约有一次**版本升级**（`CONFIG_SCHEMA_VERSION` 1 → 2），升级前请读第三节。

---

## 一、面板：四处不再骗人

### 1. 保存提示说了假话

面板一直显示「已写入 N 个 preset；**重启 DSH 后生效**」。实际上插件只写 `.pending` staging ——
这是刻意的（运行中改 `profiles/*/cordis.patch.yml` 会整树热重载，可能让宿主直接退出）。
**光重启不会应用**，还必须跑 `apply-pending-preset`。用户改完配置、重启、发现没变，再也找不到问题在哪。

现在按宿主返回的 `applied` 分流：暂存态明确写「**尚未生效**」并给出要跑的命令；只有真正写进实时
文件才说「已生效」。

### 2. 已停用的开关还在承诺功能

面板上的「自动补账」引擎**根本不读**（它不在 `resolveChess` 的白名单 `RESOLVE_ORDER` 里，
`this.chess.autoBackfill` 恒为 `undefined`）—— 拨到开、拨到关，两个方向都没有任何效果。
现在文案直说「已停用」，并点名真正的开关。

### 3. 真正该有的开关看不见（本版新增）

付费总闸 `autoArchiveBackfill` 此前只在引擎里手写声明：SCHEMA 没有、面板没有 ⇒ **功能可达性为零**。
本版把它接进面板：

| 项 | 值 |
|---|---|
| 默认 | **关闭**（不替用户预付模型费用） |
| 标签 | 「自动补账（付费，默认关）」 |
| 说明 | 写明会产生摘要模型费用，并带真实实测数据：历史花费 **$11.05**、真实使用 **0 次** |
| 取值语义 | **只认字面 `true`**；字符串 `"true"` 不生效；不写就是关 |
| 关闭时 | 仍可用面板的补账按钮手动补一次 |

### 4. 数值范围与宿主不一致

面板手写的 `min/max` 与 `SCHEMA` 有 5 处不同，其中 **3 处宿主更严** —— 面板放行、保存时被拒：

```text
压力余量（tokens）   面板上限 2000000 → 宿主只认 512000
归档收尾最小事件数   面板下限 0       → 宿主只认 ≥1
归档收尾超时(ms)     面板下限 0       → 宿主只认 ≥1000
```

现在**数值域一律以宿主为准**，面板只保留呈现决策（标签、控件种类、固定档位文案）。

## 二、数据安全（两条）

### 1. 坏图会被静默覆盖成空图

版本不符 / 半写 / 结构损坏的 `graph.json` 会让加载退化成空图，**下一次落盘就把原文件覆盖掉，且不留备份**。

现在**降级前先备份**到 `graph.json.bak-<ts>`，并把备份路径写进返回值（`repairedBackup`）。
备份失败也照实上报，不吞。

### 2. 一个坏 delta 帧会毁掉整份基线

`applyDelta` 与 `fromJSON` 曾在同一个 `try` 里：delta 里只要有一帧版本不符，异常就冒到外层，
**已经解析成功的基线被整份丢弃**（实测 2 节点 → 0 节点，落盘后 1042 字节变 442 字节）。

现在两者分开：delta 不可用就退到「只有基线」的图，原因经 `deltaDropped` 如实带出。
同时把「基线已重写」（`staleBase`，正常）与「文件坏了」（`badTail`，异常）分成两个标记 ——
此前两者混用，日志会把正常情况报成"坏帧"，还按半写处理。

## 三、升级注意：配置面契约 1 → 2

`CONFIG_SCHEMA_VERSION` **1 → 2**，键数 **33 → 34**（新增 `autoArchiveBackfill`）。

- 新增键在新建 preset 里会**显式写一行**（`autoArchiveBackfill: false`），值默认关；
- 旧 preset 里没有这一行也能正常工作（缺省即 false）；
- `autoBackfill` 这一行**保留但已停用**，新建 preset 会带注释说明「引擎不读这一行」，只为老文件兼容。

面板 API（`schemaVersion: 1`）与持久化格式（`version: 1`）**未变**。

---

## 四、降级路径不再更贵

模型不可用时的规则摘要，根目标"只取首行"但**首行本身没有上限**：一条 2,097,165 字符的单行消息
会让规则摘要产出 **2,097,473 字符**（同内容走热清单渲染只有 4,239，因为那边有 `ROOT_LIMIT=4000`）。
降级路径本该更省，结果反而把上下文撑大。

现在与热清单同口径截断（4000 字符 + 明确的 truncated 说明与 seq 出处）。

## 五、可维护性（零行为变化）

- `src/engine.mjs` **4689 → 4155 行**（−11.4%），命名导出 **29 → 11**，房间 **28 → 37**；
  **八次搬迁的全量用例数始终不变** —— 这是"只换位置不改行为"的机器证据；
- 房间边界判据：房间内禁止子进程 / 网络 / 动态执行，`node:fs` 与 `process.env` 走白名单（新增即须登记理由）；
- `scripts/` 140 个脚本全部登记在案；`gate.mjs` 收编数不退化；
- 反向 `evidence` 区间不再静默：`validate()` 报出并点名边，查询侧按 min/max 归一；
- 随包脚本需要源码树时给一句人话（"源码树专用，不是插件故障"）并 `exit 2`。
