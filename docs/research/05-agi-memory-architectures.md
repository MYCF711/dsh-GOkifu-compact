# AGI 长期记忆架构：对「会话内压缩」的启发（2026-11 调研）

> 读者：`dsh-gokifu-compact` 的维护者。本文只回答一个问题：
> **AGI / 记忆架构 / 世界模型这条线，能教我们怎么把这一个会话的历史压得更好。**
> 跨会话记忆、知识库、向量检索、工具改造、系统提示词 —— **一律不在本文**。凡结论指向那五样的，直接记为「不采纳（越界）」。

**一句话结论**：这条线真正有用的不是任何架构，是一个分类 —— **重要性由谁定义**：
> ① **学出来**（NTM / DNC / Compressive Transformer / 世界模型：需要梯度与「未来的损失」）；
> ② **算出来**（结构、因果、结算状态：压缩时就能算）；
> ③ **猜出来**（让模型说哪条重要：不可复现）。

我们没有梯度、不能训练、只能操纵文本 ⇒ **只能站 ②**。而站 ② 不是退而求其次，是这批架构的失败替我们选出来的唯一可行位置：它们证明了「学出来的重要性」在真实任务上没赢过「更长的窗口 + 对**原文**的检索」，而「原文还在」恰恰是 ② 的前提。

## 1 · 可微外部记忆（NTM / DNC / Relational Memory）—— 什么思想还活着

### 1.1 NTM：读写头分开，寻址有两种

【核实·摘要】NTM（Graves et al., 2014）：「coupling them to external memory resources, which they can interact with by **attentional processes**」「analogous to a Turing Machine or Von Neumann architecture but **differentiable end-to-end**」「**Preliminary** results demonstrate … simple algorithms such as copying, sorting, and associative recall」。

注意摘要里那个 "Preliminary" —— 它是本节最重要的一格证据，§1.5 会用。

三个可搬的思想：

1. **两种寻址并存**：content-based（按内容相似度取）与 location-based（按位置取）。
   今天两者都活着，但**分家了**：content → 向量检索 / RAG；location → `seq` / 文件路径 / 行号。
   ⇒ 对我们的意义：**热清单里的 `seq` 就是 location addressing**。它是唯一在"模型根本不知道有这段内容"时仍然有效的寻址方式 —— 内容寻址需要先知道要找什么，而模型不知道自己缺什么（03 §5.1）。
2. **读头与写头是两套判据**。NTM 用不同的头做读和写，因为「什么值得记」与「现在需要什么」是两个问题。
   GOkifu 结构上已经分开（keeper 写、ledger 读），但**判据没显式分开**：一条失败边的取舍同时服务两个目的。写进设计文档时该分开说，否则调参会互相打。
3. **擦除 ≠ 删除**：NTM 的写入是 `erase` + `add`（软擦除），不是覆盖。这与 GOkifu 的「遮蔽 + 保留原件」同构。
   **这不是巧合，是同一个约束下的同一个解**：当"写错"的代价高于"占空间"的代价时，软擦除永远是对的。

### 1.2 DNC：真正被继承的是「时序链接」

【模型知识】DNC（Graves et al., *Nature* 538:471–476, 2016）三项：content-based read、**动态内存分配**（usage / free-list：写空位而不是覆盖最旧）、**temporal link matrix**（记录写入顺序，读头可沿前驱/后继遍历）。

**temporal link matrix 是这一节最有价值的东西**：内容寻址回答不了「失败之前我做了什么」，只有顺序结构能。DNC 因此把**顺序**升成一等公民。

GOkifu 的边 = temporal link 的**符号版**，而且更强：DNC 只记"写的顺序"，我们的边带 `result`（fail / success / untested）与 `seq`。
> **⇒ 结论可以直接写进设计文档**：「图结构记忆」不是怪招，它是 DNC 里唯一真正承载信息的那一部分，被拿出来做成了显式的、可读的、可审计的结构。*可微*没赢，*链接*赢了。

另一条：动态分配 ⇒ **写新东西时优先找空位，而不是覆盖最旧**。对 fold 的启发在 §7 G-5（选区优先「已结算」而不是「最旧」）。

### 1.3 一次「内容寻址胜出」的实验：MANN

【核实·摘要】Santoro et al. 2016：「a new method for accessing an external memory that **focuses on memory content**, unlike previous methods that additionally use memory location-based focusing mechanisms」。

这是 RAG 的直接祖先：**砍掉位置寻址，只留内容寻址**。它赢了 —— 但赢的是"泛化到新样本"（one-shot），不是"管理一段长历史"。
⇒ 提醒：**检索与压缩解决的不是同一个问题**。检索让*新*信息进来，压缩让*旧*信息不消失。混用会把压缩写成半个检索器（§6-6）。

### 1.4 Relational Memory：槽位没用，槽位之间的作用才有用

【核实·摘要】RMC（Santoro et al., 2018）先确认「standard memory architectures **may struggle at tasks that heavily involve an understanding of the ways in which entities are connected**」，再用 multi-head dot-product attention「allow memories to **interact**」，在 WikiText-103 / Project Gutenberg / GigaWord 上 SOTA。

**这是本文对「热清单该怎么渲染」最直接的一条**：如果记忆条目之间不能互相作用，增加条目只是在增加噪声预算。
平铺的失败边列表，就是"不能互相作用的槽位"。

⇒ 关系必须**显式渲染**（哪条失败否证了哪个意图、哪条成功替代了哪条失败），因为读者不会自己去连边 —— 它没有 dot-product 去扫全表，只有一次顺序阅读。

### 1.5 为什么它们没有变成主流（四条，按重要性）

1. **它们要求模型与记忆一起训练**。读头是权重的一部分。冻结模型上没有读头，只有"往 prompt 里塞文本"。
2. **接口在权重里，不可审计**。没有文本契约 ⇒ 不能 diff、不能回放、不能换模型。
   而 GOkifu 的产物是 JSON + 文本，可读可 diff 可回放 —— **在我们这个环境里这是严格更强的性质**，也是 RecurrentGPT 那类「记忆即文本」能活下来的原因。
3. **证据只在玩具任务上**。NTM 摘要自己写的是 "Preliminary results … copying, sorting, and associative recall"。没有证据表明它撑得住"真实的多步工作"。
4. **真实任务上两个更便宜的东西赢了**：更长的窗口，与对**原文**的检索。
   【核实·摘要】Memorizing Transformers 用 **non-differentiable** 的 kNN 记忆，在 C4 / arXiv / PG-19 / GitHub / Isabelle 上一致提升，且「steadily improves … up to **262K tokens**」；
   【核实·摘要】RETRO 用 2T token 库 + 冻结 BERT 检索器，在 Pile 上以 **25× 更少参数** 达到 GPT-3 / Jurassic-1 级。
   > **⇒ 承重的不是可微性，是「原文还在 + 能寻址」。**

### 1.6 对「规则 / 图结构记忆」的启发（净结论）

- 它们的失败**是结构记忆的论据**，不是反论据：既然"学出来的重要性"没赢，"算出来的重要性"就是剩下唯一可站的位置。
- 但**只借结构，不借形态**：不要槽位、不要读写头、不要"记忆模块"这个词。借三条就够：**时序链接、地址（`seq`）、软擦除。**
- 最重要的一条：**别指望「记忆模块」自己学会重要。** 它只会优化你给它的损失；而我们的损失（下一步的验证结果）在压缩时还没发生。

## 2 · 压缩即理解（MDL / Hutter Prize / AIXI）—— 能用与不能用的界线

### 2.1 Hutter Prize 的三条工程读法（本轮抓到官网原文）

【核实·网页】事实：奖金 **50 万欧元**；把 1GB `enwik9` **无损**压到小于当前纪录 **100,424,672 B**（Vladimir Ivanov，2026-07-24，9.96×，奖金 37,300€）；**总分 `S = S1（压缩器 exe 体积）+ S2（归档体积）`**；奖金 = `500'000€ × (1 − S/L)`；限制 ≲50 小时、**单 CPU 核**、<10GB RAM、<100GB HDD。
官网原话：「Being able to compress well is closely related to intelligence」「The intention of this prize is to encourage development of intelligent compressors/programs as a path to AGI」。

三条读法，每条都能落成工程动作：

1. **`S = S1 + S2` 就是 MDL 的两段码 —— 模型（压缩器）的体积计入成本。**
   ⇒ 对压缩产物：**读者为了使用这份产物而必须被额外告知的东西，也是成本。** 一份需要 50 token 前言解释自己格式的热清单，比看起来大 50 token。GOkifu 的 `<chess-ledger>` 头部、动态图例行、`⚠ 上次摘要是规则生成` 都在这个账上 —— 它们值不值，要按"省下的误解"算，不能默认免费。
2. **「无损 + 解码器不得接收外部信息」** 定义了压缩的**合法知识边界**：能省掉的只有"解码器已经知道的"。
   放到会话压缩：模型的世界知识 + 系统提示词就是解码器的先验 ⇒ **可以删"模型本来就知道的"（工具手册、语言常识），绝不能删"只有这次会话知道的"（用户约束、这个仓库的报错、被否决的方案）。**
   这条与 `docs/压缩的职责边界.md` 的「只记这次做了什么」是同一件事，只是从信息论侧给了理由。
3. **它是比赛，不是方法。** enwik9 从 2019 年的 116,673,681 B 到 2026 年的 100,424,672 B：**七年、约 14%**；最后两年（110.8MB → 100.4MB）那 9% 值 37,300€，而每一档都是 PAQ 系手工特征工程。
   **它度量"压缩能力"，不生产"压缩方法"。** 当路线图用会得到"去优化压缩率"这种错误目标（§6-5）。

### 2.2 MDL：描述长度是相对于模型类定义的

【经典】两段码 `L(x) = L(M) + L(x|M)`；"最短描述"只有在**固定解码器类之后**才有定义；Kolmogorov 复杂度不可计算 ⇒ 一切实际压缩都是「限定模型类下的近似」。

三个工程后果：

- **"更短"不是绝对量。** 同一份摘要换个格式（表格 vs 散文）会让"最短"变。所以**压缩格式的可读性与约定是压缩率的一部分**，不能分开优化。
- **我们永远在比较候选编码，不在求最优编码。** ⇒ 可操作形态：A/B 两版渲染，用任务指标比，不追理论最优。
- **MDL 惩罚模型复杂度，不惩罚"读者要重建的假设"。** 把 5 条失败边压成"试了几种方案都失败"：字节更短，但读者必须重建"哪几种、为什么败"，且**不可恢复**。MDL 不建模这个，因为它不建模读者的动作。

### 2.3 AIXI：无偏正是它不可用的原因

【核实·摘要】AIXI（Hutter, 2000）：「We combine both ideas and get a **parameterless** theory of universal Artificial Intelligence」「the most intelligent **unbiased** agent possible」「The major drawback of the AIXI model is that it is **uncomputable**」；有界版 AIXI-tl 计算量 `O(t·2^l)`。

两条读法：

- **它压缩的是"生成未来的机制"，不是"过去的数据"。**
  ⇒ fold 时该问的不是"发生了什么"，而是"下一步要什么才不会被惊到"。这正是 §4 的判据。
- **无偏 ⇒ 不可计算 ⇒ 不可用。** 实用系统必须**有偏**；偏见就是任务。
  GOkifu 的偏见是「验证信号」（什么算成功 / 失败 / 未验证）—— 这既是它的正确性来源，也是它的边界：**对没被验证过的探索，它只能标 `untested`，不能判断价值**。这不是缺陷，是诚实。
- "最优"不可达 ⇒ 排除"找到最优压缩策略"的幻想；能做的只有**可测的增量**（`constraintRecall` / `failureRecall` 一类）。

### 2.4 「理解 = 压缩」能用到哪一步

【核实·摘要】Language Modeling Is Compression：Chinchilla 70B 把 ImageNet patches 压到原尺寸 **43.4%**、LibriSpeech **16.4%**，胜过 PNG **58.5%** / FLAC **30.3%**；「prediction-compression equivalence」可反向用 gzip 造生成模型。
【核实·摘要】Compression Represents Intelligence Linearly：31 个开源 LLM × 12 个 benchmark，「almost linearly correlates」。

**能用（三条，都能落成检查项）：**

1. **当筛选器**：一段历史若对"预测下一步的验证结果"没有贡献，它是可丢的**候选**（可测，不需要哲学）。
2. **当成本口径**：压缩收益要减去"读者为使用它付出的推理"（§2.1-1）。
3. **当评测方向**：用"能否从产物重建关键事实"测质量（01 的 commitments 探针就是实例）。

**会误导（三条，进 §6）：**

4. 把**模型**的压缩力当成**产物**的质量（线性相关测的是权重，我们改不了权重）。
5. 用 MDL 论证"删细节是理性"（MDL 不含读者动作）。
6. 把"压缩即智能"当路线图（**度量 ≠ 方法**）。

## 3 · 压缩式循环（Compressive Transformer）—— 最贴近我们的一个

### 3.1 它到底做了什么

【核实·摘要】CT（Rae et al., 2019）：「compresses past memories for long-range sequence learning」；WikiText-103 **17.1 ppl**、enwik8 **0.97 bpc**；提出 PG-19；也能当 RL 的记忆机制（object matching）。
【核实·摘要】它建在 Transformer-XL 上：segment-level recurrence + 新位置编码；依赖长度比 RNN **长 80%**、比 vanilla Transformer **长 450%**；评测快 **1,800+×**；enwiki8 **0.99 bpc**、WikiText-103 **18.3 ppl**。

【模型知识·未逐句核实】**两级记忆**：细层 cache 最近 n 段隐状态；细层溢出时最老的一段被**压缩**（压缩率 c）推进粗层 compressed memory，注意力同时读两层。压缩函数候选：max/mean pooling、1D 卷积、空洞卷积、**most-used**（保留被注意力读得最多的）、**learned**（用 LM 损失梯度训练，可选加自编码重建损失）。报道过：学出来的压缩有效；pooling 弱；most-used 是强而廉价的 baseline；重建辅助损失收益不大；压缩率越高越差。

### 3.2 压缩函数谱系 = 重要性代理谱系（本节的核心）

| 压缩函数 | 它假设「重要的」是什么 | 需要什么 | 在我们这里的可得性 |
|---|---|---|---|
| max / mean pooling | 局部统计显著 | 无 | 可用但**错**（会把 `EACCES` 平均掉） |
| 1D / 空洞卷积 | 局部模式 | 训练 | 不可得 |
| **most-used** | **过去被读得最多的** | 注意力记录 | **可得的符号版：被再到达 / 被重试的次数** |
| learned（LM loss） | **未来会用到什么** | 梯度 + 未来损失 | **不可得（我们没有未来损失）** |

**这张表的读法**：从 pooling 到 learned 是一条**代理精度递增**的轴，而它的终点是"直接用未来" —— 这在压缩时**在定义上不可得**。

⇒ 所以问题不是"怎么算出重要性"，而是"**选一个可核对、不可伪造的代理**"。三种候选：

- **结构位置**（是否在路径上、是否是根目标）—— 现在主要靠这个；
- **结算状态**（成功 / 失败 / 未验证）—— GOkifu 的立身之本；
- **被再到达 / 被重试的次数**（most-used 的符号版）—— 现在**没有**，这是本文能给的最具体的一条移植（§7 G-3）。

**绝不接受**第四种：模型说它重要（§6-8）。

### 3.3 三条可搬的结构结论

**(A) 分层 + 每层独立预算。** CT 的读者永远同时看到细层与粗层的**完整配额**；不会因为粗层满就把细层砍掉。
GOkifu 现在相反：`renderLedger` 在 L0–L5 里选**一个**能装下的档，**整份清单同档降级**（读码确认：`for (level = 0; level <= 5; level += 1)` 取第一个 `tokens <= maxTokens` 的候选）。于是"约束被截短"与"失败边少列 3 条"是同一个动作的两个后果。
⇒ 不同段落的**未来用法不同**（约束用于**判定**、失败边用于**排除**、路径用于**定位**），降级代价因此不同，预算应当分段给（§7 G-1）。

**(B) 压缩是分层降级，不是一次性决定。** CT 每次只把最老的一小段降一级。
⇒ 对 fold：**不要在一次 fold 里对整个区间同等对待**；靠近边界的、未结算的、被再到达过的，应当以更高保真进入粗层。

**(C) 它明确接受"粗层有损且不可逆"。** cache 可重算，compressed memory 不能。
⇒ GOkifu 比它强的地方在于**遮蔽保留原件**，所以我们的粗层其实可回溯。
⇒ 借的不是"压得更狠"，而是**把"哪层可以真丢"写进格式**：细层（verbatim tail）可丢、粗层（图）必须可回溯、指针必须无损。这一条已是 GOkifu 的架构主张，CT 只是给了它一个对照坐标。

### 3.4 为什么它不是主流

- 要训练整个模型（压缩函数是权重）；不能 retrofit 到冻结模型。
- 压的是**隐状态**，没有可读产物：不能 diff、不能审计、不能跨模型。
- 被"更长窗口 + 检索"取代（§1.5-4）。
- **但问题意识没被取代**：窗口再长也有尽头，且长窗口的中段会被忽略（01 已引 Lost in the Middle 的 56.1%）。**会话压缩不是过渡形态，是常规形态。**

## 4 · 世界模型 / 预测式压缩 —— 「未来无法推出」作为保留判据

### 4.1 Dreamer：表示被「价值」塑形

【核实·摘要】Dreamer：world model 总结经验；行为靠 **latent imagination** —— 把学到的状态价值的解析梯度**回传过想象出来的轨迹**，在**紧致状态空间**里做；20 个视觉控制任务上数据效率 / 计算 / 最终性能都更好。

关键结构（【模型知识】）：世界模型学习预测观测、奖励、折扣、继续标志；**表示不是被"重建保真"塑形的，是被"控制"塑形的** —— 凡是改变价值估计的量，才值得进隐状态。

⇒ **可搬的判据**：压缩该保留「**会改变下一步动作**」的东西。
操作化成一个评审问句（本文最该被抄走的一句）：

> **「删掉这一条，下一步可能做错什么？」** 答得出来 ⇒ 它值这些 token；答不出来 ⇒ 它不该占位置（预算富余时另说）。

按这个问句过一遍现有内容：

- **根目标 / 用户约束**：答"会做错判定"（算不算完成、允不允许）⇒ **必留**
- **带原因的失败边**：答"会重走死路"⇒ **必留**
- **某步的原始工具输出**：答"只有当下一步要引用它"才成立，否则由结果态可推 ⇒ **可降为指针**
- **时间戳、客套、重复解释**：答不出 ⇒ **可丢**

### 4.2 把「未来无法推出」严格化

信息论版本：`value(x) ≈ P(x 改变下一步动作) × (1 − P(x 可从别处推出))`。

**两个因子缺一不可**：`H(x|S)` 高不等于有用（随机噪声也高）。所以判据是「**决策相关且不可推导**」，不是一个熵值。

| | 未来推不出 | 未来推得出 |
|---|---|---|
| **改变动作** | **必留、逐字**：根目标、用户约束、失败原因、被否决的方案 | **降级为指针**：文件内容、git 状态、可再读的工具输出 |
| **不改变动作** | 预算富余时留（偏好、风格、背景） | **删** |

「推得出」的判据必须**机械**（能写成规则），否则就变成模型猜：

- 工具是 `read` / `grep` 且结果 = 文件内容 ⇒ 推得出（文件还在，可再读）
- 状态是 `git status` / `ls` ⇒ 推得出（可查）
- 工具手册 / 语法 ⇒ 推得出（系统提示或模型先验里）
- **用户口头约束、「这个报错在改 X 之后消失」、「先试了 A 才想到 B」这类因果配对、未结算的意图 ⇒ 推不出**

最后一行是重点：**因果配对是这类系统里唯一无法重建的东西**。文件可以再读，命令可以再跑，但"哪次修改让报错消失"只存在于历史里。

### 4.3 DreamerV3：一套超参跨域，胜过每域调优

【核实·摘要】DreamerV3：「a **single configuration**」「outperforms specialized methods across over **150** diverse tasks」；靠 normalization / balancing / transformations 获得跨域稳定；首次**无人类数据、无课程**在 Minecraft 从零采到钻石。

⇒ 对压缩：**别按会话类型 / 项目调参**。要"归一化"的量（占窗口比例、占总边数比例），不要绝对阈值。
GOkifu 的 `thresholdRatio` 0.45 / `firstFoldRatio` 0.30 / `retainRatio` 0.16 都是比例，方向正确；**若将来引入"按会话类型分支"的参数，就是 DreamerV3 之前的老路** —— 脆弱、不可验证。

### 4.4 JEPA：在表示空间预测，不在原文空间重建

【核实·摘要】I-JEPA 是「**non-generative** approach」：从一个 context block 预测同一图像中多个 target block 的**表示**；关键设计在 masking —— target 必须**尺度够大（语义）**、context 必须**信息足够（空间分散）**。ViT-H/14 在 16×A100 上 <72h。

两条可搬：

- **别重建原文，预测结构。** 重建会强迫把容量花在"不可预测的细节"上（像素噪声 ≈ 会话里的措辞噪声）。
  这从理论上解释了 01 的实测：机械抽取 79.1% vs LLM 摘要 16.0% —— **生成式重建把容量花在了"像对话"上**。
- **选区要语义完整。** 被遮的区域切碎了就学不到东西。
  ⇒ fold 区间必须落在**完整的尝试**上（意图 + 动作 + 结果）；切一半会留下不可解释的残片（"有个报错，但不知道是为了什么跑的"）。
  现状对照：`planFold` 已有工具对平衡（`balancedBefore / balancedAfter`），但那保证的是**消息层**的工具对；图层的「**尝试完整性**」（一条边的验证信号可能在 fold 之后才到）是另一根轴，现在靠 `classifyDangling` 的 `live-unsettled` / `candidate` 兜底。**兜底不是没有，但是没有度量**（§7 G-5）。

### 4.5 这条判据的边界（必须说清）

世界模型的判据需要**价值函数**。我们没有：只有三态验证信号（成功 / 失败 / 未验证）。
⇒ 「未来无法推出」只能当**排序启发式**，不能当"删 / 留"的判定器。任何把它当判定器的地方，都会退化成"模型猜重要性"。
⇒ 正确用法：**排序 + 显式标注**（"以下 N 条因预算未列出 + 去哪取"），而不是静默硬删。

## 5 · 长期记忆的工程架构（只取对压缩有用的）

### 5.1 分层：三层的形状，别加第四层

通用形状：工作层（每步可见） / 会话层（可寻址，按需取） / 归档层（跨会话）。压缩只管前两层的边界（第三层越界）。

GOkifu 的对应：热清单 = 工作层；`graph.json` + 原始日志 = 会话层；归档层不做。

两条工程性质：

- **每层必须有取回路径**，否则层间搬运等于删除（03 §3.5：取不到 = 真没了）。现在有 `seq` 与相对路径 `TRACE`，缺的是"这条被折叠的边去哪读"的**统一写法**（00 的 C3 已补一部分）。
- **层数越多，「这该在哪一层」越模糊**，读者开始猜。三层够；第四层是复杂度税。

### 5.2 巩固：抽象可以，重写不行

【核实·摘要】Generative Agents：完整记录经验（自然语言）→ **随时间综合成更高层的 reflection** → 动态检索以规划行为；ablation 表明 observation / planning / reflection 各自对"可信度"有贡献。
【模型知识】实现：memory stream 每条带时间戳、importance、last-access；检索分数 = recency（指数衰减）+ importance（LLM 打分）+ relevance（embedding），归一化加权；importance 累积超阈值触发 reflection。

**对压缩有用的部分**：巩固 = **提升抽象层级**，不是重写原文。一条抽象有价值，仅当它能**回指**到支撑它的原始条目。
**不能借的部分**：用模型写 reflection。它的成功标准是 **believability**，不是保真。把"住起来像人"的结论搬到"准确恢复工作状态"，是范畴错误（§6-9）。

### 5.3 遗忘：工程上只有三种，没有「打分」

真实存在的三种：(a) 容量驱逐（LRU / 最旧）；(b) 预算截断（渲染放不下）；(c) 显式归档（P6-C 的 sidecar）。
**没有一种是按"衰减分数"的** —— 因为分数需要被信任，而分数来自不可复现的估计。

值得借的是 LRU 的**读侧版本**：**「最近被再到达过的边优先保留」**。它可从图里机械算（后续边的 `from` / `to` 指回它），且恰好对齐 CT 里最强的廉价压缩函数 **most-used**。这是本文给出的最具体的一条移植（§7 G-3）。

**不借**：Ebbinghaus 曲线（03 §6-1 已否）、LLM importance 打分（§6-8）。

### 5.4 时间衰减：同一个公式，两个位置，错误代价不对称

在**检索**里，衰减只影响**排序**：错了顶多多取一条，代价有界。
在**压缩**里，衰减影响**存留**：错了是**永久看不见**，代价无界。

⇒ **同一个公式不能因为"在检索里好用"就搬到压缩里。** 这是判据层面的不对称，不是调参问题。
⇒ 时间在压缩里只有一个合法用途：**陈旧标注**（`[stale 42m]`），不是删除。GOkifu 现在正是这么用的 —— 这条做对了。

### 5.5 检索增强：在压缩里它叫「回填」，不叫「召回」

【核实·摘要】RETRO：2T token 库、冻结 BERT 检索器 + chunked cross-attention，在 Pile 上以 **25× 更少参数** 达到 GPT-3 级；「explicit memory at unprecedented scale」。
【核实·摘要】Memorizing Transformers：对**非可微**的 (key, value) 记忆做近似 kNN，在 C4 / arXiv / PG-19 / GitHub / Isabelle 上一致提升，**随记忆增大到 262K tokens 持续变好**，且能在测试时使用刚定义的函数 / 定理。

两条对压缩的启发（严格限定会话内）：

- **合法的检索形态是 page-in（按需回填原件）**，不是"召回知识"。不需要向量库，只需要 `seq` 寻址 + 一条取回路径。
- **它们的收益建立在"原始表示还在"**（kNN 取的是 past keys / values，不是摘要）。
  ⇒ 支持"保留原件、只遮蔽可见性"：**原件是可检索性的基础，摘要不是。** 原件丢了，任何检索都只能检索到摘要的错误。

### 5.6 一条反面证据：非参数记忆可以很便宜

【核实·摘要】Model-Free Episodic Control：一个简单的"海马式情景缓存"就「attains a highly rewarding strategy significantly faster than state-of-the-art deep RL」，且在更难的任务上最终回报更高。

⇒ 记忆的收益可以完全来自**存 + 取**，不需要"学"。这对"我们只做结构"是一个正面背书。

## 6 · ⛔ 站不住的说法（逐条给理由）

> 本节只针对**架构与理论侧的口号**。人类记忆类比的否证在 03 §6，提示压缩的否证在 01 §1.5，**不重复**。

**6-1 「记忆越像大脑越好」（生物保真当目标）**
错在：生物记忆的每个性质都是**约束下的妥协**（容量、代谢、发育），不是设计目标；NTM / DNC 正是"抄了形态（读写头、槽位）没继承收益"的样本。
害处：资源花在形态上（槽位、衰减、巩固周期），而这些在没有梯度的系统里不产生收益，只产生不可解释的行为。
做法：只借可验证的功能（可寻址、可回溯、擦除≠删除），每条都要能回答"去掉它会坏在哪"。

**6-2 「压缩就是丢掉不重要的」**
错在：**"不重要"在压缩时不可知**。重要性是"未来使用"的函数 —— CT 必须用未来损失学它，Dreamer 必须用价值函数定它；压缩时未来还没发生。
且：丢"不重要"的**没有收益**（它本来就不占决策带宽）；真正省 token 的是丢"**重要但可再取**"（文件内容、可查状态）。两个动作混为一谈会两头落空。
做法：分成两类 —— **降级可见性（可回溯）** 用于"可能重要"，**丢弃内容（不可回溯）** 只用于"可再推导"。

**6-3 「用时间衰减 / 遗忘曲线决定保留」**
错在：衰减是**排序函数**，不是**存留函数**（§5.4 的不对称）。且它假设"越新越相关"，而会话里最相关的往往是**最早的约束**（根目标），必须永久最高权重 —— 直接与衰减冲突。
做法：用**引用 / 结算状态**替代时间；时间只用于陈旧标注。

**6-4 「窗口够大就不需要压缩了」**
错在：窗口是**容量**，不是**可用注意力**；位置效应让中段被忽略（01 已引 56.1%）；成本随长度上升而收益递减。
更硬的一条：即使窗口无限，**"哪条是失败的"仍是结构判断**。读 100 万 token 去找失败原因，比读一张图慢得多。
做法：把目标从"省 token"改成"**给出结构**"；token 是副产品。

**6-5 「压缩率越高越智能 / 摘要越短越好」**
错在：Hutter Prize 的压缩率定义在「固定语料 + 无损 + 无外部信息 + **计入解码器体积**」四个条件下，会话压缩四个都不满足；Compression-Intelligence 的线性相关测的是**权重**的压缩力，不是**产物**的质量。
且：短摘要把重建成本转嫁给读者，而两段码的 S1 没被计入。
做法：用**任务指标**（交接测试、`constraintRecall`）验收，不用长度验收。

**6-6 「记忆即检索，有 RAG 就不用压缩」**
错在：检索解决"取得到"，不解决"知道该取"。模型不知道有一段被折叠过时，它不会去检索（03 §5.1：模型没有"取不到"的信号）。
且：RETRO / Memorizing Transformers 的收益建立在**原始表示仍在**；检索不能替代"决定留下什么"，它只是把成本推给存储。
做法：压缩产物必须**自证不完整**（"未列出 ≠ 未发生" + 取回路径）—— 这是检索能起作用的前提。

**6-7 「可微记忆解决了长上下文，只是算力不够」**
错在：可微记忆的核心假设是**读头能被训练成"读对"**。冻结模型上没有读头，只有"往 prompt 里塞文本"，而塞进去被读成什么由注意力决定，不由我们的寻址决定。
且：NTM 的原始证据只有 copy / sort / associative recall（摘要原文），DNC 也没有真实长任务的规模证据。
做法：把"寻址"从模型内部搬到**文本契约**（`seq` / `id`），让寻址可审计；不追求"模型自己会读对"。

**6-8 「让模型判断哪条重要」（LLM-as-importance）**
错在：不可复现、不可审计（理由也是生成的），且压缩点正是重构失真最活跃的时刻（03 §4.1）。Generative Agents 的 importance 打分服务的是 believable，不是保真。
且：它会系统性高估"叙事上重要"的（戏剧性失败），低估"判别上重要"的（一条排除了 3 个候选的枯燥失败）。
做法：重要性只能来自可核对的结构量 —— 是否被再到达、是否结算、是否排除动作、是否被用户复述。

**6-9 「反思 / 巩固 / 摘要链能提升记忆质量」**
错在：每层生成都是一次**重写**，误差累积（ρ^k，01 §2.5 已定量）。Generative Agents 的 reflection 有 ablation 支持 believability，**没有保真度量**。
做法：抽象层只允许**机械聚合**（同工具同参数合并、同义置换合并），每条带 evidence 指针。

**6-10 「MDL 说最短的描述最好，所以删细节是理性」**
错在：MDL 的最优性是**给定模型类下、对整份数据**的；它不建模"读者后续的动作"，所以"删掉未来要用的一条"在 MDL 意义下可能更短。两段码的第二项是"给定模型后的残差"，"读者会不会用"不在模型里。
做法：把"未来可用性"显式写进编码代价（预算按不可推导性分配），而不是交给 MDL 直觉。

**6-11 「更强的模型会让压缩问题消失」**
错在：更强的模型压缩力更强，但**它读不到的仍然读不到**；能力提升的是"给定 token 的利用率"，不是"被遮蔽 token 的可达性"。
且：能力越强越会**流畅地填补**缺失（confident blunders，01 §2.4），使缺失更难被发现。
做法：把"标注不完整"当作与模型能力无关的必需品，不做成"模型够聪明就不需要"的可选项。

### 7.2 明确不做（越界或已被否证）

| 不做 | 理由 |
|---|---|
| **向量检索 / 语义召回做回填** | 越界（知识库）。合法形态只有 `seq` 寻址 + 相对路径（§5.5、§6-6） |
| **按会话类型 / 项目分支调参** | DreamerV3 的反面：单配置跨域才是稳的（§4.3） |
| **时间衰减 / TTL / 衰减权重** | 排序函数误用为存留函数，错误代价无界（§5.4、§6-3） |
| **LLM 重要性打分 / 让模型排序** | 不可复现、不可审计，且在压缩点上失真最活跃（§6-8） |
| **追"像大脑"的分层数 / 巩固周期** | 形态不产生收益（§6-1） |
| **用压缩率当验收指标** | 四个前提都不满足，且长度 ≠ 质量（§6-5） |
| **递归摘要 / 反思链 / 摘要的摘要** | ρ^k 衰减；抽象层只许机械聚合（§6-9、01 §2.5） |
| **逐字重建"完整对话"** | JEPA：别在原文空间重建，要在结构空间预测（§4.4） |

### 7.3 如果只能改一件事

**G-3（most-used 的符号版）。** 三个理由：

1. 它是本文唯一**新增信号**的建议；其余六条都是"已有信号的重新分配"。
2. 它精确打在 01 定位的失效模式上 —— **失效不是损坏，是"不在热清单里"**。而"下一步会不会再需要它"最好的机械代理，就是"过去几步里它被再到达过几次"。
3. 零模型调用、纯结构、可单测（给一张图，断言排序）。风险上限是"排序没变好"，不是"丢数据"。

**但 G-1 的收益更大。** 它是当前 `renderLedger` 的一个真实缺陷（整份清单同档降级 ⇒ 预算紧时先牺牲的恰好是约束与出处）。只是它动的是渲染主干，必须单独一刀、全量 bench 前后对照、goldens 逐字比对 —— **不要和 G-3 放进同一个 commit**。
