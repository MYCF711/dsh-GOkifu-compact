# 2026-11 上下文压缩前沿：对本插件的可执行结论

> 调研日 2026-11-16。只读外部一手资料 + 本机 DSH `0.2.2-rc.2` asar；**0 模型调用**。
> 本文不改生产默认值，不启动真实 reader 实验。外部数字只代表原论文设置，**不得直接外推到本插件**。

## 0. 一句话决策

**能更进一步，但方向不是「再换一个摘要模型」，而是「按当前问题，从已有棋谱里确定性找回相关证据」。**

建议下一条实验线：**Q1 · 代码锚点驱动的按需召回（code-anchored query recall）**，默认 `NOT_ADOPTED`；
配套一个**离线证据遮蔽重建审计**，先证明选得对，再花真实 reader 调用。

---

## 1. 上游 DSH 有没有「免费用」的新能力

本机宿主为 **`@deepseek-ai/dsh-desktop-runtime 0.2.2-rc.2`**。直接读 rc.1 / rc.2 两份 asar：

| 模块 | 结果 |
|---|---|
| `@deepseek-ai/dsh-compaction/lib/index.js` | 两版逐字节相同（sha256 前缀均为 `9db5200bd40b7d04`） |
| `dsh-compaction-tool-result-pruner` | 两版逐字节相同 |
| `dsh-compaction-basic` | 只有 1 行行为差异：rc.2 把 `aborted` 的构造改为 `LlmError.fromFailure(finish.failure)` |

⇒ **rc.2 没有提供新的压缩/召回接口，不能把升级当成质量收益。**
当前 magpie 文本 API 也不暴露注意力行、logits、KV cache 或模型嵌入；下文凡依赖这些能力的方案都只能借鉴思想，不能复现。

## 2. 最新研究与「能不能用」

### 2.1 QRAE：保留原文证据 + 未决候选缓存（2026-11-05）

[QRAE: Query-Relevant Attention Entropy for Context Compression in DeepSearch Agents](https://arxiv.org/abs/2611.07976)
报告：任务成功率平均 **+2.35pp**、端到端延迟 **−30%**、报告 token **−45%**。

它的关键不是又一个摘要器，而是：

1. 由当前 query 给**完整原文 chunk**打分；
2. 高分 chunk 进持久白名单；
3. **不确定的 chunk 不删除**，留在候选缓存，后续可重新评估。

但打分需要读取模型指定 attention heads，并做 paired prefills。**当前 API 没有这个入口，不能照搬。**

可借鉴的是产品形状：**可见白名单 + 盘上有据可查的候选集**。这与本插件「热清单 + 原始棋谱」天然同构；
下一步应复用现有图，而不是再建一个常驻向量库。

### 2.2 ReConMem：对话记忆必须和仓库实体对齐（2026-11-05）

[ReConMem: A Graph-Based Dual Memory System for Repository-Oriented Conversations](https://arxiv.org/abs/2611.07759)
报告：LoCoEval 单跳/多跳 Pass@1 分别比最强基线高 **7.917 / 7.292pp**；
CodeAssistBench 比 Full History 高 **4.10pp Correct / 7.09pp Partially Correct**。

对本插件最相关的是三件事：

- 对话事实挂到**文件 / 类型 / 函数 / 变量**等代码实体；
- 检索时沿「对话 ↔ 代码」关系做**有界扩展**；
- 代码按结构粒度压缩，而不是把相关文件全文塞回去。

本插件已有 `touched-files.mjs`：能从图边机械解析 read/edit/write 的路径和 seq。
所以可以先做**确定性的文件/符号锚点子集**，不必先实现完整的双图、embedding 和仓库索引。

### 2.3 SumOne：摘要质量可用「遮蔽重建」训练/评测（2026-11-04）

[SumOne: A Simple and Efficient Summarizer for Plug-and-Play Agent Memory](https://arxiv.org/abs/2611.06445)
用 2B summarizer + 冻结 reconstructor，按约 512-token 块随机遮蔽 50% 原文，重建质量加长度惩罚作为奖励。

结果不能只看摘要里的「成本降 75%」：

| 设置 | Full History | Self-Summary | SumOne |
|---|---:|---:|---:|
| SWE-bench Verified（OpenCode） | 0.63 | 0.56 | 0.59 |
| **DS Harness（论文表 3）** | **0.50** | **0.41** | **0.42** |

也就是说，**在 DSH 这组跨 harness 结果里，SumOne 只比 self-summary 高 0.01，仍比全文低 0.08。**
再考虑它要 5K 轨迹、GRPO 训练和独立 2B 模型，**现在不值得替换本插件摘要路径。**

真正值得拿的是它的**评测思想**：不要只数 `constraintRecall` / `failureRecall` 和 id，
还要看「原文被拿走以后，读者能否从压缩产物恢复关键证据」。

### 2.4 CoMem / Coca-Cola / ASTC：结果好看，但当前不可部署

| 论文 | 报告结果 | 本插件判定 |
|---|---|---|
| [CoMem](https://arxiv.org/abs/2611.16384)（2026-11-12） | query-guided soft memory，多基准优于既有压缩 | 需要训练 compressor 与 soft memory slots；不能经文本 API 接入 |
| [Coca-Cola](https://arxiv.org/abs/2611.06500)（2026-11-04） | token −70.01%～89.24%，运行时间 −24.45%～55.97% | 需要把工具结果编码进模型 embedding，并做 action-preserving training；不可直接部署 |
| [ASTC](https://arxiv.org/abs/2610.41291)（2026-10-30） | Attention Pairs 最多 −50.68% | 依赖 GDN/attention 的模型内部 recurrent state；不可用 |

### 2.5 一个额外警告：语义保真 ≠ 行为保真

[Does Context Compression Preserve Refusal Alignment?](https://arxiv.org/abs/2611.06380)（2026-11-04）
发现 encoder 压缩即使重建保真高，也会削弱拒答行为。

本插件不是 encoder 压缩，不能直接套用数值；但它支持本仓已有原则：
**验收必须是真实 reader 的配对任务结果，不能拿摘要相似度、重建率或覆盖率代替。**

## 3. 推荐实验：Q1 · 代码锚点驱动的按需召回

### 3.1 做什么

当前用户消息若明确提到文件路径或代码符号：

1. 从现有图边中找出与这些锚点**机械可证**相关的事实 / 失败边 / 成功路径；
2. 在固定 token 预算内优先注入这些**原文证据指针与必要短值**；
3. 根目标、用户约束、必须保留的失败记忆**不进入竞争**，照旧保留；
4. 未选中的内容仍在棋谱里，下一步 query 变化时可重新召回 —— 不是删除。

第一版只做**精确路径 / 规范化相对路径 / 明确符号**；不做模糊猜测、不读 bash 命令猜路径、
不调用 embedding、不新增常驻缓存、不新建仓库索引。

### 3.2 为什么是它

- **贴合真实瓶颈**：当前不是「图里没有」，而是「当前问题需要的那条没在热清单里」。
- **符合两条公理**：只重排已有证据，不生成新事实；原文和 seq 指针仍在。
- **成本形状正确**：零额外模型调用；可做到有界扫描、有界输出，不增加常驻内存。
- **比通用摘要更值得试**：SumOne 的 DSH 结果并不支持换模型；ReConMem 则直接命中 coding agent 的仓库对齐问题。

### 3.3 不做什么

- 不把 QRAE 的 attention 分数换名为「QRAE」；本方案是**确定性锚点召回**，不是复现 QRAE。
- 不把 ReConMem 的 +7.917pp 当作本插件预期收益。
- 不在每步注入相关文件全文；只带能回证的必要事实与指针。
- 不默认开启，不改现有渲染字节。

## 4. 先做的离线评测：证据遮蔽重建审计

现有机械指标只证明「约束文字 / 失败边 id 还在」，不能证明「读者拿得回关键证据」。
建议新增一个**离线**审计，不进入生产每步路径，并分清两层：

1. **Stage A（0 模型调用）**：从冻结题集选取关键证据 span（主体、时点、值、失败原因、文件/符号关联），遮蔽后机械检查压缩产物是否仍含**该证据或其可回证指针**；比较 `current` vs `code-anchored recall` 的命中率、token 与 p95 渲染延迟。
2. **Stage B（计入调用预算）**：需要测真实读者时，再给 reader「压缩产物 + 未遮蔽上下文」，判定它能否恢复该证据，同时记录编造与 UNKNOWN。

**不要只随机遮 50% 文本**：随机块会把预算花在可再读、可重算的措辞噪声上。
本项目最该测的是「哪次修改消除了哪个报错」「这个值属于哪个主体/哪个时点」这类不可重建的因果与锚点。

若使用模型做 reconstructor/judge，必须与 summarizer 分开，并保留原始证据作最终裁决；
模型评审不能覆盖机械金标准。该审计只用于**筛选候选**，最终仍以 paired real-reader 任务验收。

## 5. 建议冻结的实验闸门

### Stage A · 零模型调用

- 冻结合成题集：至少覆盖文件锚点、符号锚点、无锚点、同义多文件、无证据五类；
- 对照：现行渲染 vs Q1；
- 必过：mandatory 内容逐字不丢、无锚点时输出逐字不变、预算不突破、无伪造路径；
- 性能：在最大真实图上跑渲染基准，记录 p50/p95 与 RSS；不引入新的常驻结构。

### Stage B · 遮蔽重建 + 小配对 pilot（未达 Stage A 不运行）

- 遮蔽重建与任务 reader 共用预算：20 个非饱和任务 × 2 臂 × 3 样本 = **最多 120 次调用**，0 重试；
- reader、温度、题面、答案、 grader、token 预算全部预注册并冻结；
- 公开面只放聚合与合成夹具，不放私有正文 / 会话 id / 本机路径。

### 采纳门槛

默认 **`NOT_ADOPTED`**。只有同时满足才允许进入默认路径：

1. paired compact 不差于现行臂，且至少一类锚点任务有真实收益；
2. full/compact 配对退化不超过冻结阈值，UNKNOWN 不增加；
3. token 与 p95 延迟收益为正，无新的常驻内存增长；
4. 20 题若两臂都饱和 ⇒ 只能判 `POSITIVE_SIGNAL`，**不得写 PASS**，须扩到 formal 50/50。

## 6. 最终排序

| 优先级 | 项 | 判定 |
|---|---|---|
| 1 | **代码锚点按需召回**（确定性、零模型调用、默认关） | **建议做 Stage A** |
| 2 | **证据遮蔽重建审计**（离线评测，不是生产压缩器） | 与 Stage A 同步做 |
| 3 | 完整 ReConMem 双图 / embedding 检索 | 暂缓；先证明轻量锚点版本有收益 |
| 4 | SumOne / CoMem 等专用摘要模型 | 不采纳；DSH 数据与训练成本都不支持 |
| 5 | QRAE / Coca-Cola / ASTC 原实现 | 不可部署；只保留「白名单 + 可恢复候选」的设计思想 |

**底线不变：保留原始证据；让关键证据持续可见；让所有派生事实可回证。**

## 7 · 实施结局（2026-11-16）：Q1 已完成实验，但未采纳

Q1 已按本文建议完成团队实现、独立复核与真实配对实验：

- 默认关闭的 `queryRecall` 开关、确定性文件/符号召回、UI/preset/Engine 全链接线；
- Stage A **15/15**；最大真实图派生命中 p95 **9.996ms**；
- 初审 2 BLOCKER / 5 MAJOR / 7 MINOR 全部闭环，全量 **2541/0**；
- Stage B **120/120、0 重试**：A0 8/20 → A1 15/20，但 B-06 退化、wall p95 变差；
- 最终 **`NEGATIVE_SIGNAL / NOT_ADOPTED`**，默认关闭，不用性能或合成覆盖率冒充真实收益。

完整证据：`evidence/query-recall-review-final.md`、`evidence/query-recall-pilot-public.json`。
下一次若要重新提议采纳，必须使用新的 held-out 任务并重新预注册。
