## 1. 三份调研的共同结论（只摘与压缩有关的）

### 1.1 学术给出的最重要一句

> **2026 年的实测证据已经把「压多少」这个问题降级了 —— 真正的分水岭是「压缩器有没有重写事实」。**
> （`01` 的原话；下一条是它在本仓的具体形态。）

> **GOkifu 的 ρ^k 衰减消失了，但风险没消失，只是换了名字**：从「**被改写**」变成「**不在热清单里**」。
> 一个节点在 k 次 fold 后仍完好存在于 `graph.json`，但如果它没进那 351 tokens，模型就看不见它。
> **⇒ 真正的失效模式是「检索」，不是「损坏」。**

这条改变优先级排序：**热清单选哪几条边**，比"摘要写得好不好"更能决定压缩质量。

其余可直接用的：`(warn 70%, flush 100%, evict 50%)` 三元阈值、逐字不改写散文 + 显式标注剥离、
`superseded_by` 标注（不删边）、page out / fault in、commitments 探针当回归测试。
**明确不借**：递归摘要（ρ^k）、新事实覆盖旧事实（对失败边）、重写旧节点表示、soft prompt。

### 1.2 产品实践给出的三条

1. **「可回溯」与「压缩」不冲突，且已是行业默认**：Claude Code / Codex / Devin / LangGraph / OpenHands
   全部可回溯；**不可回溯是 `dsh-compaction-basic` 的设计债，不是常态**。
2. **没人靠「把摘要写好」解决约束丢失** —— 所有解都在「重发 / 重灌」这一侧（CLAUDE.md、rules、AGENTS.md、
   canonical context）。Claude Code 有一张「What survives compaction」的**逐机制确定表**。
3. **只有 Codex 把压缩抽象成「生命周期」而非「动作」**，因此它可以有「不摘要、直接开新窗口」这种实现。

横向对比里 GOkifu 的位置：触发=DSH 生命周期、粒度=**增量 fold**（唯一）、保留=根目标/约束/成功路径/失败边/
OPTIONS/悬空边分类（每步重灌）、可回溯=**是**、工具记录=**是（分类为验证信号）**。

**另外两条我认为最值钱的（来自 `02` 的总结，之前没进主表）**：

4. **主流产品已收敛出「三层通道」**：**常驻重发层**（rules / CLAUDE.md / AGENTS.md）、
   **可丢弃层**（工具输出、助手闲聊）、**压缩后重灌层**（文件、plan、todo、memory）。
   三层里**只有中间那层该被压** —— 这正是 `docs/压缩的职责边界.md` 判据的「产品版表述」：
   常驻层归 AGENTS、重灌层归宿主/工具、能压的只有会话里那些"用过就不再需要逐字保留"的过程性内容。
5. **所有压缩故障都能归成一句话**：**压缩把「已经付过代价拿到的信息」降级成了「下一个模型的推测」**。
   ⇒ 失败边之所以必须逐字保留，就是因为它是"付过代价"的那部分里**最贵、最不可重建**的一种
   （文件可以再读、命令可以再跑，**"这个做法失败了以及为什么"只存在于历史里**）。

### 1.3 认知科学给出的三条

> **能动的是「形状」，不能动的是「动力学」。**（`03` 的原话）
> 形状 = 工作记忆怎么分块、情景/语义怎么分工、线索该怎么给；动力学 = 遗忘曲线、巩固周期、情绪加权。
> 前者能照搬（而且已经照搬了几条），后者照搬就出事 —— 因为 agent 的存储免费、读取精确，代价结构与人不一致。

1. **来源监控**：知道"这条信息哪来的"是独立能力 ⇒ 出处（seq）比内容更不该被砍（已落地，见 §2）。
2. **遗忘多数是「取不到」而非「没存」**，而模型没有 TOT 感 ⇒ 省略行必须给线索，否则等于真没了。
3. **提取诱发遗忘（RIF）**：只呈现一部分会压制未呈现的部分 ⇒ 沉默本身就是断言（已落地，见 §2）。

**明确不借**：遗忘曲线设 TTL/衰减权重、模型自评重要性、"人会自动重构所以摘要糙点没关系"、
"工作记忆 = 上下文窗口"、跨会话巩固。

## 8. 第 3 轮调研：记忆系统（04）与 AGI 架构（05）

### 8.1 记忆系统（`04-memory-systems.md`）的净结论

> **九套系统里能进本插件的只有四样东西 —— 闭包指针（D1）、失效标注（D2）、分档预算（D3）、版本戳（D4）。
> 它们全都不是"记忆"，而是"让一个降维产物不失真、可退回"的记账方式。**
> 共同点：不需要跨会话、不需要检索、不改变模型该做什么。

| 可采纳 | 落地形态 | 对应本表候选 |
|---|---|---|
| D1 闭包指针（合并时闭包取**并集**） | `foldMarks.push({closure:{nodeIds,seqFrom,seqTo}})`；tier-2 合并 union | #12 |
| D2 失效**只标注不删** | `old.supersededBy = new.id`，仍渲染 `[superseded by e12]` | #11 |
| D3 分档预算**显式化** | `ledgerBudgetTiers()` 把 L0–L5 预算从散落的数组里提出来 | #8 相关 |
| D4 版本戳防旧写回覆盖新写回 | `g.lastFoldVersion` + `#flush()` 前比对（现有 `_tier2InFlight` 只防重入） | 新 |

**不采纳**：时间衰减/heat、LLM 语义裁判、写时合成/记忆演化、模型自编辑+分页换入、多臂检索/图/向量、参数层记忆。
**一处边界张力**：Hindsight 的 `proof_count` 是**可机械统计的事实计数**（借），不是**模型评分**（不借）。

### 8.2 AGI 长期记忆架构（`05-agi-memory-architectures.md`）的净结论

> **重要性有三种来源**：学出来（需梯度 + 未来损失：NTM/DNC/Compressive Transformer/世界模型）、
> **算出来**（结构/因果/结算状态）、猜出来（模型打分，不可复现）。
> **我们没有梯度 ⇒ 只能站"算出来"。** 而这一支的失败恰好替我们选定了它：
> Memorizing Transformers 用**非可微** kNN 到 262K 持续变好、RETRO 用 2T 库以 25× 更少参数追平 GPT-3
> ⇒ 承重的不是可微性，是「**原文还在 + 能寻址**」。

| 可采纳 | 说明 | 对应候选 |
|---|---|---|
| **G-3 most-used 的符号版** | `reentryCount`（该状态被后续路径再到达的次数）+ `retryCount`，用于渲染排序。**唯一新增信号**、零模型调用、可单测 | 新 #15 |
| **G-1 分项预算** | `renderLedger` 的「整份清单同档降级」是**真实缺陷**：预算紧时先牺牲的恰好是约束与出处。收益最大但动渲染主干 | 新 #16 |
| **G-2 不可推导性标记** | keeper 建节点时机械判定 `derivable`（read/grep/ls/git 的文件内容）；渲染时先降级；**意图/结论/验证信号永不标 derivable** | 新 #17 |
| G-5 边界完整性 | ✅ 已落地（`9690e1e`）：`foldMarks[i].dangling` 四分类快照 | — |

**明确否定两条**：
1. **「压缩就是丢掉不重要的」** —— 重要性是"未来使用"的函数，压缩时未来还没发生；
   且丢"不重要"的没有收益（它本来就不占决策带宽），真正省 token 的是丢「**重要但可再取**」，这是两个动作。
2. **「用时间衰减决定保留」** —— 衰减在**检索**里只影响排序（错了多取一条，代价有界），
   在**压缩**里影响**存留**（错了永久看不见，代价无界）。同一个公式、两个位置、错误代价不对称。

**两条附带洞见**：
- **MDL 两段码** ⇒ 压缩产物的"使用说明"也算成本：一份需要 50 token 前言解释自己格式的热清单，比看起来大 50 token。

### 11.2 审计规则演进：哪些越权句式是靠外部审计才发现的

这条线值得单独记：`boundary-audit` **基线 2 条**（`behavior-guidance` / `tool-governance`），C15–C64 之间新增 **4 条句式规则**，现在一共 **6 条**；每一次扩规则都是因为漏掉了真实文本。

| 轮次 | 新规则 | 漏掉的形态 | 谁发现的 |
|---|---|---|---|
| （基线） | `tool-governance` | 工具 schema / 权限治理被压缩产物改写 | 设计期 |
| C15 | `behavior-guidance`（中文 + `you should/must`） | `(continue or abandon)` 这类**许可式**行动指导 | 自审 |
| C45 | `retry-advice` | `retry when it changes` / `take it` / `or create it` —— 英文**何时再试**建议 | 自审（C45 前夜） |
| C46 | `epistemic-advice` | `treat as unproven` —— **认知指令**（教模型怎么看待事实） | 自审 |
| C64 | `directive-short` | `…，别重复。` —— **祈使短句**（中文，无「不要重试」字样） | **外部专员审计** |
| C64 | `memory-restore-advice` | `需要时按 seq 回读` —— **恢复时机**指令，且会随摘要长期留在上下文 | **外部专员审计** |

教训（写进流程）：

1. **规则是枚举，语言是开放集** —— 只靠「加正则」永远补不完；所以每条规则都要配「纯事实写法不假红」的反向用例，
   并且属性测试直接复用同一份 `RULES`（C64），避免测试与审计各写一套判据；
2. **摘要模板也是模型可见文本** —— 它产出的内容会长期留在上下文里，越权代价比热清单更高；
3. **最大的漏网概率来自「看起来像事实的指令」**（`retry-if edge exists`、`treat as unproven`、`需要时…回读`），
   而不是明显的「你应该」——这类只能靠**独立视角的审计**发现，自审存在系统性盲区（已实证）。
