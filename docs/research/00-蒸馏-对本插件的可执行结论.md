## 1. 三个来源各自说了什么（只摘与压缩有关的）

### 1.1 学术（见 `01-academic-compression.md`）

| 结论 | 对我们的意义 |
|---|---|
| **提示压缩（LLMLingua 类）不改变历史**，每次推理重算 | ⚠️ **不是我们的问题域**：它优化的是"这一次请求的输入"，我们优化的是"历史怎么降维"。两者生命周期不同，**不要混用** |
| **增量折叠**（只压上次 checkpoint 之后）是长会话保留率的关键 | ✅ 已实现（`fold-planner.mjs` 的 `selectIncrementalRange`）——市场对标 §6.4 与本仓库独立得出同一结论 |
| **每轮重摘要全历史 ⇒ 保留率 ρ^k 衰减** | ✅ 已规避：这正是我们相对官方 `compaction-basic` 的核心修正 |
| **多级摘要 = 系列复述**，会累积失真（Bartlett） | ✅ 我们的对策：机械抽取 + 模型只润色表达 + 失败边逐字；**不要去训练模型"更会摘要"** |
| 图/树结构（RAPTOR / GraphRAG）适合**跨文档检索** | ⚠️ 那是知识库，越界。我们的棋谱图是**会话内因果**，不是文档索引 |

### 1.2 产品实践（见 `02-product-practice.md`）

| 结论 | 对我们的意义 |
|---|---|
| **Anthropic 的定义**：compaction = 接近窗口上限时把对话摘要、再开新窗口；与 **structured note-taking**（跨会话记忆）、**multi-agent**（并行）并列**三种不同手段** | ✅ 直接支持我们的边界划分：我们只做第一种 |
| Claude Code 的 compaction：**保留架构决策、未解决的 bug、实现细节**，丢弃冗余工具输出；压缩后**附上最近访问的 5 个文件** | ✅ 与我们的「失败边 + 约束 + 根目标」同构；「最近访问的文件」是可考虑的补充（属于"压什么"） |
| **"compaction 的艺术在于选择保留什么"**；过激压缩会丢掉"后来才显得关键"的细节 | ✅ 我们的立场：**只遮蔽、不删除**，原件永远可回溯 |
| 官方建议：**先在真实 agent trace 上调 prompt，先最大化 recall，再迭代 precision** | ✅ 我们的规则摘要（零模型）先保 recall（失败边一条不许少），模型只做表达压缩 |
| **tool result clearing 是最安全的轻量压缩** | ✅ 已借宿主 `toolResultPruner`（压缩前先剪一次） |

### 1.3 人类记忆（见 `03-human-memory.md`）

| 结论 | 对我们的意义 |
|---|---|
| **来源监控**（Johnson 1993）：知道"这条信息哪来的"是独立能力 | ✅ 本轮已落地：失败边的 seq 在任何降级档位都不砍（建议 A） |
| **遗忘多数是"取不到"而非"没存"**；但模型没有 TOT 感 | ✅ 支持"只遮蔽保留原件"；同时意味着**省略行必须给线索**（数量 + 区间 + 去哪查），否则等于真没了 |
| **提取诱发遗忘**（RIF）：只呈现一部分会压制未呈现的部分 | ✅ 本轮已落地：OPTIONS 在 L2+ 也保留一行计数（建议 D）——沉默即断言"没有别的路" |
| **工作记忆容量是"可操作的块数"（3–5），不是字符数** | ✅ 热清单按**因果关系**组织，不按条目配额；预算按 token 而非"最多几条" |
| **⛔ 不能用遗忘曲线设 TTL / 衰减权重** | ✅ 明确不做：agent 存储免费、读取精确；本仓已有 27.8% 悬空残留，再加"自动过期"是灾难 |
| **⛔ "人会自动重构，所以摘要糙点没关系"** | ✅ 明确不做：LLM 的错是**流畅且局部合理**的，更难发现 ⇒ 机械抽取优先、结论带回指 |

## 3. 候选改进（只列压缩本职，按「收益/风险」排序）

| # | 改进 | 依据 | 现状 | 风险 |
|---|---|---|---|---|
| 1 | **折叠边界无条件重发约束与根目标**（不依赖 40 事件节流） | 约束丢失比失败边丢失更致命；间隔应匹配"要撑多久" | 部分（靠摘要里的 CONSTRAINTS_VERBATIM 兜底） | 无新增 token（摘要本来就有），风险在"忘了测" |
| 2 | **`provenanceCoverage` 观测指标**（带 id/seq 的行数 / 总行数，按档位记录） | 来源监控可量化 | 未做 | 纯观测，零 token |
| 3 | **省略行带"去哪查"**（现在一处有路径、一处只有泛称 `graph.json`） | "取不到 = 真没了" | 部分 | +40~80 字符 |
| 4 | **最近访问的文件路径**进摘要（Claude Code 的做法） | 产品实践 | 未做 | 属于"压什么"，需确认不越界（文件路径是会话事实 ✔） |

## 4. 明确不采纳（越界或有害）

| 方向 | 为什么 |
|---|---|
| 跨会话记忆 / 知识库 / 向量检索 / GraphRAG | 越界（属于 Hindsight、知识库） |
| 教模型"何时该 restore"的 nudge | 行为指导，属于 AGENTS/persona |
| 用遗忘曲线做 TTL / 衰减权重 | 认知类比误用；会变成"自动丢边"的借口 |
| 让模型自评"重要性"来排序 | 不可复现；正是重构失真最活跃的时候 |
| 训练专门的摘要模型 | 与"机械抽取 + 表达润色"的架构冲突，且不可复现 |
| 把热清单写得更"通顺" | 流畅性可能是风险；保留原始报错串是防伪手段 |
