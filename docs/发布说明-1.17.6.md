# 发布说明 · 1.17.6（2026-11-02）

> 相对 **1.17.5**。这版没有改压缩算法本身，改的是**「该发生的事有没有真的发生」**——
> 一条真机证伪推翻了一个设计假设，顺手补上补账通道、把面板做成能自己办事、并给好几处「仪器静默降级」加了护栏。
> **所有效果都要重启 DSH 后才生效**（插件在启动时加载）。

## 一、真机证伪：GUI 归档不发 `session/disposed`（C216）

**场景**：你以为归档时会自动做一次收尾折叠（1.17.2 的 C210 是这么设计的）。

**真机实测**：GUI 归档只往 `workspace.json` 的 `archivedSessionIds` 里追加 id ——
**不发 `session/disposed`**（那个事件只有 `dsh-session` 的 `detachEntered` 才发）。所以 1.17.5 上
**12 个已归档会话一条 `closeout` 都没有**，尾巴合计 24,189 个事件从没被压过。

**现在**：改挂宿主的 `domain/changed`（只认 `domain=workspace`、`table=""`、`operation=put`），
用 `change.value.archivedSessionIds` 做差分（`registry` 落后一拍，不能读它）。

## 二、新能力 · 补账（`backfill`）+ 面板按钮（C216 / C234）

归档会话**没有 agent**，宿主的压缩只对 idle agent 有效 ⇒ 欠的账只能「重新变成 live」才能补。
所以补账的动作是：**取消归档 → resume → 收尾折叠 → 原样归档回去**（resume 失败也会把归档状态还原）。

面板「上下文压缩」右栏新增 **「补账」卡**：

| 按钮 | 做什么 |
|---|---|
| **检查欠账（不调模型）** | 只报清单：哪个会话、尾巴还有多少事件 |
| **开始补账** | 真补（每个会话一次模型调用），结果：`补完 X / Y（真折叠 Z；失败 W）` |

也可以直接打接口（等价）：

```bash
curl -s -X POST http://127.0.0.1:64349/gokifu/api -H "content-type: application/json" -d '{"action":"backfill","dryRun":true}'
curl -s -X POST http://127.0.0.1:64349/gokifu/api -H "content-type: application/json" -d '{"action":"backfill"}'
```

## 三、面板 · 检查更新（U5）

右栏新增「检查更新」卡：当前版本 / 最新版本 / 上次检查 / 状态；有新版本时顶部出横幅 + 可复制的升级命令。
**只拼命令，绝不执行安装**；registry 不可达时是「检查失败：原因」，不会把整页打坏。
**已知不新时不给命令**（本地比 registry 新时给 `@latest` 等于教人降级）。

## 四、压缩产物（清单）的三处修正

| 编号 | 修正 |
|---|---|
| C226 | **只有 1 个节点的路径，任何档位都不渲染**（门槛 `path.length > 1`）—— 契约 ⑥ 的真根因，live 上 2 个会话稳定触发 |
| C223/C224 | 零失败会话（约 **26%**）走的最小清单**没有当前位置**，还缺 `ROOT USER` / `OPTIONS` / `UNVERIFIED` 计数 —— 全部补齐，并让 `handoff-check` 走生产同一条分支 |
| C227 | 被过滤掉的「无终点残留失败」**算了却从没输出** ⇒ 补一行 `# 另有 N 条无终点残留（…全文 graph.json）` |
| C231 | **已修正的失败沉底**：同一条命令后来自己跑通的失败边，一条不删，但排到 LEARNED 段末（低判别价值的别占最前） |

## 五、诊断（doctor）变可信

- **C218**：不再只看「最新 6 份会话日志」——改按**时间窗**选（窗口内写入过的都看，上限 24 份）；
- **C221**：修掉一个巨型 `else`，`ledger-budget.json` 不存在时不再让一族检查**静默消失**（空 home 33 → 37 项）；
- **C220**：「上下文缓存命中」首次可见（实测 **97%** 的输入走缓存）；
- **C219**：「热清单注入动作」append vs replace（replace = 改写 surface 中间那条 ⇒ 前缀缓存作废）；
- **C230**：「热清单抗干扰」—— 已修正的失败占比（实测 **43/306 = 14%**）。

## 三、补账：从「能补」到「补得明白、补得完」

| 变化 | 你会看到什么 |
|---|---|
| **干跑先给钱**（C286） | 「检查欠账」不只报条数，还给**预计 token 与花费**（实测 35 个欠账 / 可估 11 个 / ≈ **5.51 M tok ≈ $0.83**，按冷缓存全额价算） |
| **冷缓存要预告**（C285） | 归档会话的缓存早清空了，提示"这钱省不掉" |
| **大尾巴自动分段折**（C288/C289/C291） | 原来对 11 个超大尾巴（11/11 都 >150k tok，最大 **1.24 M**）一折必超窗口。现在自动切段（每段 ≤150k、最多 6 段、受 90s 预算约束），部分成功也算成果 |
| **单段上限可调**（C316） | 新配置 `closeoutMaxFoldTokens`（默认 150k）。宿主窗口 1M 时可调到 400k，1.24M 的尾巴从「两轮」变「一轮」 |
| **分段折完要记账**（C298/C299） | `closeout.chunkedFolded` 会写回；doctor 与补账房间的「折过了没有」统一口径——**不再把已折完的会话误报成未补**（误报会让你重复点补账 = 重复付费） |

## 四、面板：从「展示」到「会算账」

- 「检查更新」动作（`update`）：面板能自己查有没有新版本，不必离开界面（U5）；
- 折叠成本卡显示**上次摘要用了哪个 provider/模型**与真实 usage（C286 起带单价口径）；
- 欠账卡显示**剩余/分批**与预计轮次（C258）。

## 五、仪器静默降级：多处「不报错但一直撒谎」被修掉

这一族是本版最密集的修复，共同特征是**代码不崩、指标永远正常、结论永远错**：

| 现象 | 修法 |
|---|---|
| doctor 读 `quality.outOfRangeLater`，而**该字段从来没人写** ⇒ 永远报"正常"（C280/C281） | 分方向统计 + `audit-field-reads` 扫「读了但没人写」 |
| 「摘要被 `max_tokens` 截断」完全不可观测（C317–C321） | 记 `foldMark.finishReason`；doctor 报截断次数；老数据明说「未采集」 |
| 终止原因的**字段名/载体/拼法**连错四轮（C317→C320） | 从宿主 asar 里挖出 `assembler.finish.reason.kind`，并**归一化** `max-tokens`/`max_tokens`/`length` 三种拼法 |
| 字段写进了 `ledger-budget` 而 doctor 读 `foldMarks`（C321） | 写进 foldMark；新增守卫查「读的字段必须在构造里写过」（C323） |
| 热清单渲染 95% 时间在**拼字符串**（C313 实测 21.95ms，其中查图仅 5%） | doctor 报「最大会话渲染耗时」，>100ms 变警告（C314）——**不值得优化的东西装报警器** |

## 六、维护面：把「该人做的事」准备到复制就能跑

- **重启验收清单**加了「现状快照」（C295）：重启前后逐条对照，不用凭记忆；
- **能力探针**（C294）：直接问面板「你认识 `update`/`backfill` 吗」——比时间戳可靠（启动戳可能来自**已退出**的进程，C293）；
- **待补 tag 命令**（C324）：`npm run gate` 末尾直接给 `git tag -a v1.17.x <sha> -m … && git push origin …`，当前三个版本（1.17.4/5/6）都还没 tag；
- **用例数守卫**（C325）：测试文件被覆盖/删减会红（本版真的踩过一次）；
- **文档守卫**（C310/C326）：文档里的脚本路径与**参数**必须真实存在。

## 七、已知限制 / 还没做的

1. **本版未发布**：`1.17.6` 只打了 commit，**没有 tag、没有 npm publish**（`npm run gate` 末尾会提醒，并给好命令）；
2. **所有效果要重启验证**：面板能力探针现在是 ✗（进程里那份模块比磁盘旧）；
3. 大图渲染优化（K-16）**刻意没做**：C313 证明 95% 在拼字符串、收益 20ms 级，已改成 >100ms 报警；
4. 补账的真实花费与成功率**没有真机样本**（要重启后第一次跑才有）。
