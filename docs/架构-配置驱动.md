# 架构 · 配置驱动（配置 → 功能 → UI）

> **本文档说明「一个配置键从声明到生效」的完整链路。**
> 它回答的问题是：**我加一个开关，怎么保证它真的生效、真的能关、真的有人读？**
>
> 权威实现：`src/rooms/config-schema.mjs`（R15）· `src/rooms/feature-registry.mjs`（R17）
> 门禁：`test/config-schema.test.mjs` · `test/feature-registry.test.mjs` · `test/ui-config.test.mjs`

---

## 0 · 为什么需要这一层

在 C688 之前，同一个配置键在**五个地方**各写一遍：

| 位置 | 写的是什么 |
|---|---|
| `engine.mjs` 的 `Config` | zod 类型 + 默认值 |
| `engine.mjs` 的 `resolveChess()` | 键序白名单 + 净化语义 |
| `ui.mjs` 的 `DEFAULTS` / `FIELD_LABELS` | 默认值 + 中文名 |
| `lib/client.js` 的 `FIELDS` | 标签 / 类型 / step / min / max / 枚举 |
| `install.mjs` 的 `engineBlock()` | preset 模板行序 |

它们**已经漂移过**：

- `maxTokens` 曾同时是 4096 / 2048 / 8192；
- `retainRatio >= thresholdRatio` 的修正只在两处里的一处生效；
- 手写 `FIELDS` 与 `SCHEMA` 有 **5 处范围不一致**，其中 3 处 host 更严 ⇒ **面板放行、保存即 400**；
- `autoArchiveBackfill` 是唯一一个**不在 SCHEMA 里**的键，默认值散在 5 处。

C688 把这条链路收敛成**一条单向数据流**。

## 1 · 三层结构

```
┌─────────────────────────────────────────────────────────────┐
│  ① 配置层  src/rooms/config-schema.mjs（R15）                │
│     SCHEMA：34 行 —— key / type / default / where / range /  │
│              values / label / desc                          │
│     「有哪些键、默认多少、范围多少」= 唯一真值               │
└──────────────────────────┬──────────────────────────────────┘
                           │ 只读
┌──────────────────────────▼──────────────────────────────────┐
│  ② 功能层  src/rooms/feature-registry.mjs（R17，C688 新增）  │
│     FEATURES：11 个功能 —— 每个声明它消费的键 / 默认是否开 / │
│               是否花钱 / 实现在哪                            │
│     HOST_CONSUMED：4 个宿主消费、插件只透传的键（显式豁免）  │
│     「这个键归谁管」= 唯一真值                               │
└──────────────────────────┬──────────────────────────────────┘
                           │ 派生
┌──────────────────────────▼──────────────────────────────────┐
│  ③ UI 层  lib/client.js 的 deriveFields()                    │
│     从 host 下发的 describeFields()（SCHEMA 派生）翻译成     │
│     面板 Field 组件吃的形状                                  │
│     「面板怎么画」= 派生，不手写                             │
└─────────────────────────────────────────────────────────────┘
```

**方向是单向的**：配置层不知道功能层，功能层不知道 UI 层。任何一层都不许反向写回。

## 2 · 加一个配置键，要动哪里

按顺序做，**每一步都有门禁**：

| 步 | 动作 | 门禁 |
|---|---|---|
| 1 | 在 `SCHEMA` 追加一行（**追加到末尾**，不许插入） | `config-schema` C675 键序快照 |
| 2 | 若键序变了，`CONFIG_SCHEMA_VERSION` **+1** | `config-schema` C675 |
| 3 | 在 `FEATURES` 里找到管它的功能，把键加进 `keys` | `feature-registry` C688① 孤儿键 |
| 4 | 若它是**宿主消费**的（插件只透传），加进 `HOST_CONSUMED` 而不是 FEATURES | `feature-registry` C688⑥ |
| 5 | 若是 preset 域且要上面板，加进 `PANEL_FIELD_ORDER` | `ui-config` 覆盖 DEFAULTS 全部键 |
| 6 | 跑 `node scripts/config-table.mjs --write` | `config-table` C249 |
| 7 | 跑 `node test/run.mjs` | 全量 |

**漏掉第 3 步** ⇒ `orphanKeys()` 非空 ⇒ 门禁红，提示「这些键能改但没有任何功能读它（假配置）」。

## 3 · 四个纯查询（功能层）

| 函数 | 回答的问题 | 非空意味着 |
|---|---|---|
| `featureOf(key)` | 这个键归哪个功能管 | — |
| `orphanKeys()` | 哪些键**谁都不管** | 假配置：用户改了没有效果 |
| `undeclaredKeys()` | 哪些键**功能声明了但 SCHEMA 没有** | 表里拼错，或 SCHEMA 删了没跟着删 |
| `duplicateKeys()` | 哪些键被**两个以上功能**声明 | 表写错（一个键只能归一个功能） |

`costlyDefaults()` 额外回答：「哪些功能**花钱且默认开**」—— AGENTS §2.0 要求这类必须写清打开会多花多少钱。

## 4 · UI 层的两条硬约束

### 4.1 只渲染 `where: "preset"` 的键

`where: "engine"` 的键（`retainTokens` / `graphDir` / `factGuard` / `hotLedgerMinEvents` …）是**引擎作用域**：
面板写进 preset 的 `config:` 块**不会生效**（`engineBlock()` 不渲染它们）。画出来就是**假 UI**。

这条约束原来隐含在「手写 23 项」里，C688 显式写进 `deriveFields()` 的 filter。

### 4.2 展示顺序 ≠ SCHEMA 顺序

- **SCHEMA 键序** = preset 块里 `engine` 段的行序 = **对外契约**（C675 钉着，记忆侧与手写 preset 依赖它）；
- **`PANEL_FIELD_ORDER`** = 面板阅读顺序 = **产品契约**（常用 4 项在前、归档收尾在后）。

两者是不同契约。混用会让面板一开就变样。表里没有的新 preset 键会**追加到末尾**（不会消失）。

---

## 5 · 已知边界（别越界）

- **本层不读配置、不产生事实** —— 它只是一张表 + 四个纯查询。零 fs、零宿主、零 engine。
- **`HOST_CONSUMED` 不是缺陷清单** —— 那 4 个键由 `dsh-compaction` 消费，插件只经 `pickBase()` 透传。
  把它们"修"成插件自己读，会与宿主抢同一个开关。
- **`FEATURES` 的 `where` 字段是文档，不是判据** —— 它写"改这个功能要动哪个文件"，
  不参与任何运行时判断（防止有人拿它当 import 表）。
- **注册表冲突不抛错** —— 它是只读表，抛错会让整个插件加载失败。冲突由测试点名。

## 6 · 验证命令

```bash
node test/run.mjs feature-registry   # 7 条：孤儿/未声明/重复/声明完整/墓碑/豁免表/只读
node test/run.mjs config-schema      # 22 条：SCHEMA golden + 版本号 + 键序快照
node test/run.mjs ui-config          # 14 条：面板字段覆盖 DEFAULTS 全部键 + label 一致
node test/run.mjs rooms              # 20 条：架构方向门禁（feature-registry 已登记）
node test/run.mjs                    # 全量
```

**墓碑口径**：删掉 `closeout` 功能的声明 ⇒ `closeoutFold` / `closeoutMinEvents` 立刻变成孤儿 ⇒ C688⑤ 红。
