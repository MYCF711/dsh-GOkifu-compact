# 归档压缩：怎么验证它真的发生了

> 一句话：**归档后看两样东西 —— `closeout.folded` 是不是真的，`foldMarks` 里有没有新增。**
> 只要有 `folded: true` 而 `foldMarks` 没变，就是「假成功」（C531/C557 修的就是这个）。

---

## 一、正常流程长什么样

```
会话被归档 / 被销毁
      ↓
#closeout（写 closeout 记录）
      ↓
#closeoutFold
   ├─ 尾巴太大 → 分段折叠（compactRegion × N）
   ├─ 单段折叠（compactIfNeeded）
   └─ 上面两条都失败/空转 ⇒ 离线补折（读磁盘日志 + 默认模型）
      ↓
foldMark 落账（trigger = archive / archive-offline）
```

**关键判据：`foldMark` 是唯一的"真的折了"的证据。**
`closeout.folded` 只是结论字段；它必须能对上图里新增的 mark（C557 起强制如此）。

---

## 二、三条命令（按顺序看）

### ① 现在是什么状态

```bash
node scripts/status.mjs --fast
```

关心两行：

```
· 补账：52 个欠账 · $1.03 …              ← 还有多少没压
· 自动补账：开 · 近 24h 折了 N 段 …      ← 后台到底在不在动
```

**出现「⚠ 新字段一个都没写 ⇒ 跑的还是旧代码」** = 引擎跑的是旧构建，新逻辑没生效。

### ② 压出来的东西能读吗

```bash
node scripts/last-summary.mjs --session <会话 id 前缀>
```

输出正文 + 质量指标（约束召回 / 未知 id / 缺段 / 结尾干净）。
**指标好看不够，正文要能读** —— C528 之前就吃过"召回率全 1、正文却截断"的亏。

### ③ 整体健康

```bash
node scripts/doctor.mjs
```

看 `归档收尾（closeout）` 与 `归档后剩余的未折尾巴` 两条。

## 三、两种故障形状（都在真机出现过）

| 形状 | 现象 | 根因 | 现在由谁兜底 |
|---|---|---|---|
| **假成功** | `closeout.folded: 1`，但 `foldMarks: 0` | `compactRegion` 调用成功被当成"折了"（归档后没有 surface，它安静地什么都不做） | C531（分段）/ C557（单段）：folded 改为看证据 |
| **空转不转离线** | 分段 `stopped: "no-op"`，但没走离线补折 | 新停止原因没进 `shouldTryOfflineFold` 白名单 | C555 |

两种都会让「尾巴纹丝不动，账上却说折了」。

## 四、真机样本（2026-11-04，归档后）

```json
closeout: {"source":"disposed","eventsSinceLastFold":757,"folds":0,
           "foldAttempted":true,"folded":1}
foldMarks: 0        ← 假成功
```

用磁盘代码补跑一次后：

```json
foldMarks: 1
  → archive-offline · seq 9-63 · 3,959 字符
closeout: {"source":"archive-offline","foldOffline":true,
           "offlineCovered":{"start":9,"end":63},
           "offlineUncoveredHead":{"from":1,"events":8}}
```

## 五、这些数字在哪看

| 指标 | 位置 |
|---|---|
