# 工程教训集：GOkifu 压缩工作里「踩过才知道」的坑

> 2026-11-01 · 从本轮 20+ 轮实际工作里提炼。
> 收录标准（同 `$DSH_HOME/AGENTS.md` 的规矩）：**查不出来、且失败代价高**的规则才配写进来。
> `grep` 得到的不写；单测已钉死的不写（那些跑测试就会红）。

---

## 1. 指标本身也要被验证，不能因为有测试就假定它测得对

**踩过的三次**：

| 现象 | 根因 | 代价 |
|---|---|---|
| 「失败边占 238%」 | `sections` 是**字符数**，拿 `renderLedger().tokens` 当分母 | 差点按错误数据去改预算分配 |
| 降级档位出处覆盖率掉成 0 | `provenanceCoverageOf` 只认 `(seq `，短格式 `(sa-b)` 不认 | 把"省字符"误判成"丢出处" |
| `quality` 在规则/降级路径缺失 | 只有模型路径设置 `_lastSummaryText` | doctor 显示「未采集」，看起来像"没丢"，实际"没测" |

**判据**：新指标落地时，必须用一个**已知答案的输入**跑一遍对照（空摘要 ⇒ recall 0；全文摘要 ⇒ recall 1）。
只跑「有值」不算验证。

---

## 2. 没有消费者的指标不许进代码

`sections` 第一版只算不用，`fold-quality` 第一版只有单测调用 —— 都是"算着，但没人知道它算得对不对"。

**判据**：提 PR 前问一句「**谁读它**」。答案必须是 `doctor` / `ledger-budget.json` / `graph.json` / 某个断言，
不能是"以后可能用"。

---

## 3. 诊断结论要停在诊断本身，别顺手滑到「所以做不到」

**踩过**：看到 `real-fold-trigger` 落盘的图 `user 节点数 = 0`，判断"keeper 没跑"，然后直接结论
"这条路走不通、不能验证保真度"，还写进了文档。

**实际**：桩是自己写的，缺什么补什么就行 —— 加一个 `session._emit(event)` → `ctx.emit("session/event")`
就通了（并行会话两小时后就修好了）。

**判据**：写"做不到"之前，先分类：
- **架构限制**（改不了，例如"进程不可重启"）→ 才可以写"不能"；
- **实现没写完**（桩缺事件派发、工具缺参数）→ 只能说"当前没做"，不能说"不能做"。

---

## 4. 看不见的字符只能靠行为测试抓

第一次写幻觉探针的正则，python 把 `\b` 写成**退格字符 U+0008**。编辑器里看和 `\b` 一样，
`node --check` 不报错，正则就是匹配不上 —— `checked` 恒为 0。

**判据**：任何正则/转义字符串，写完立刻用一个**预期有匹配**的输入跑一次；只看代码会漏。

**同类**：bash 里 `git commit -m "多行消息"` 遇到中文引号会把后面拆成 pathspec；改用 `git commit -F <文件>`。

---

## 5. 两个会话同时跑 `node test/run.mjs` 会假红

共用 `test/.harness/graphs`，典型症状是 `T2-5 ... 应产生 1 条 tier2 记录，实际 2`。

**判据**：看到 T2-5 / tier2 之类**偶发**红，先做两步验证再审代码：
1. 单独跑那个文件（`node test/run.mjs tier2`）；
2. `tasklist | grep -c node.exe` 看有没有别的会话在跑。

---

## 6. 数据会推翻推测，而且比推测便宜

| 推测 | 数据 | 结论 |
|---|---|---|
| 「给根目标/约束抬下限」（#16 分项预算） | 失败边占 41–67%，约束只占 0–26%，根目标 2–89% | 主要矛盾是失败边，不是约束 |
| 「提高失败边表示效率」 | 94 字符/行，其中 reason 占 66% | reason 是核心价值，砍它就是砍质量 |
| 「`evidence` 缺失是问题」（候选 #14） | live 33 条失败边缺 evidence **0 条** | 问题不存在 |

**判据**：动手之前先花 5 分钟量一下。**测量比论证便宜得多**。

---

## 7. 分清「链路真」与「数字真」

`real-fold-trigger` 修好后，`constraintRecall = 1`，但那是**引擎机械追加**保证的（有效证据）；
`failureRecall = 0` 受桩自拼 prompt 影响（**不代表生产**）。

**判据**：任何"验证通过"的结论，都要写清**它证明了什么、没证明什么**。否则下一个人会把它当作生产指标引用。

---

## 8. 边界争议写进文档，不要用代码「顺手实现」

用户明确要求「不要把 AGENTS / tools / 系统提示词等其他机制的功能越权覆盖」。
本轮清掉了 4 处行为指导（摘要骨架的「下一步」、`ruleSummary` 的行进指令、
`foldFailureWarning` 的「告诉用户」、`OPTIONS` 的「you may continue or abandon」）。

**判据**：新增任何注入到模型上下文的内容前，过 `docs/压缩的职责边界.md` 的五问自检；
答不上就写进该文档的「边界争议」小节，**不写代码**。

## 9. 验证 patch 时，要验「最后生效的那一层」

2026-11-02 实机事故：重启后插件 UI 正常、版本显示 1.17.0、`verify-install` 18/18 全绿，
但 `chess-context/` 不再落盘 —— 因为 `profiles/<p>/cordis.patch.yml`（**用户层 patch，最后应用**）
里有一份 `preset-standard` 快照，写着 `@deepseek-ai/dsh-compaction-basic`，
把插件 bundle 层「换成 engine」的覆盖又盖回去了。

**判据**：任何「已接管 / 已生效」的结论，都必须同时看**用户层 patch**（最后应用的那层），
不能只看包内 patch。现在 `findShadowedUserPresets()` + `doctor` / `verify-install` 各一条检查会直接报错；
一键修复包在 `home/.gokifu-fix-2026-11-02/`（DSH 完全退出后运行，带备份 / 原子替换 / 自动回滚 / 幂等）。

**推论**：GUI 编辑「模式 / preset」会重写用户层 patch —— 每次编辑后重跑体检，不要假设上次修好就一直好。
