## 0. 目标不是"文件变小"

三条判据，缺一条都不算成功：

1. **改一个用户可见行为，只需碰一个地方**（改动半径）；
2. **"全绿"只需一条命令**（`node scripts/gate.mjs`）；
3. **加一个新能力不需要理解 4600 行**（新房间 + 登记 + 一条边界用例）。

参考方案里"减少行数"不是目标，只是副产品。

## 3. 用户点名的那条：**UI 声明下沉到模块**

> 原话：「dsh 的插件的 ui 都是在插件本身就注册好的，而我们的 ui 是否也可以这样？这样的好处就是 ui 不会乱，不会对不上，而且不会出现假 ui，文本填进去是真生效的」「把 ui 声明在每个需要有 ui 的模块部分」

**现状问题**（可在代码里指认）：

- `src/ui.mjs` **2133 行**同时干四件事：HTTP 路由、配置文件读写、面板字段定义、会话态聚合；
- `lib/client.js` 是浏览器半，字段名在 `FIELDS`（15 键）里**又抄了一遍** `config-schema.mjs`（23 键）——
  AGENTS §2.6 已记「A2-4 收敛只到 4/5」；这就是「UI 对不上」的机器成因；
- 面板文案与阈值档位（`THRESHOLD_TIERS`）在 `client.js` 里手写，与 host 侧 schema 无校验 ⇒
  改一处不改另一处，**界面上不会报错，只会显示错的东西**（"假 UI"）。

**动作（P2 的一条独立切片）**：

1. 每个需要 UI 的房间**导出一份 `ui` 声明**（纯数据，零 React、零 HTTP）：
   ```js
   export const ui = {
     fields: [{ key: "thresholdRatio", label: "触发阈值", kind: "select", options: [...] }],
     panels: [{ id: "folds", title: "折痕", columns: [...] }],
   };
   ```
2. `src/ui.mjs` 只做**汇总 + 挂载**：`import * as room of rooms`，`Object.values(room).flatMap(r => r.ui?.fields ?? [])`；
3. `lib/client.js` **不再手写字段表**，渲染 `ui.fields` 的 JSON；
4. 门禁加一条：**任何 `ui` 声明里的 `key` 必须存在于 `config-schema.SCHEMA`**（否则红）——
   这一条就是"文本填进去是真生效"的机器判据；
5. 删除 `lib/client.js` 里的 `FIELDS` 硬编码（AGENTS §2.6 记的那笔欠账）。

   新增房间必须同时更新 `ROOMS` 表 + 附录 A 的过滤器对照（PR #28 就是漏了后者，盲审判出来的）。
