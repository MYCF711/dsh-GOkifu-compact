# 上下文压缩：两条公理

> v2 · 2026-11-07
>
> 这不是规则清单。只有两条不能靠换模型、换提示词、换框架推翻的公理；其余都是推论、路线或猜想。

## 公理一 · 可见性公理

> **模型对本次会话历史的使用，只能来自当前实际可见的上下文。**

不在当前上下文里的历史，不会自动参与当前决策。

所以：

- `graph.json` 里有，不等于模型知道；
- 日志能回读，不等于模型已经读到；
- 上一次摘要写过，不等于这一次还看得见；
- 工具存在，不等于模型会主动调用。

**对当前决策而言，不可见的信息等于不存在。**

## 公理二 · 证据不增公理

> **派生压缩不能创造新的原始证据；有损压缩丢失的信息，也不能从摘要自身恢复。**

摘要、棋谱、索引、热清单、旧 checkpoint，都只是原始历史的派生物。它们可以变换表达、组织关系、提供指针，但不能让一条原本没有证据的话变成事实。

所以：

- 旧摘要不能证明新摘要；
- 模型写得确定，不等于事实成立；
- 规则抽到字符串，不等于抽对了主体与时点；
- 原文若被毁且派生物没保留，任何模型都不能保证找回。

**生成只是候选，证据才使事实成立。**

---

## 两条推论

### 推论一 · 压缩的对象是可见性，不只是文本长度

压缩真正决定的是：**哪些证据还能继续影响未来的行为。**

因此“更短”可能更差，“原文还在”也可能已经失效。必须同时回答：原文在哪里、当前模型看见什么、reader 是否真的会使用。

### 推论二 · 可证明的归冷代码，不可证明的不得升格

配置、边界、seq、quote、时点、工具对、回放、事务、计数、回滚，能机械判定就由冷代码裁决。

LLM 只负责语义归纳与表达候选。无法证明的内容只能标 `UNVERIFIED / PENDING / UNKNOWN`，不能靠再生成一次或换个评委变成事实。

**真正不能错的部分，不能只靠 LLM。**

---

## 本项目唯一铁律

> **保留原始证据；让关键证据持续可见；让所有派生事实可回证。**

落到当前路线，就是：

```text
原始会话
→ 结构化棋谱与证据指针
→ 增量 fold（一段历史只折一次）
→ 用户选择的默认模型压缩叙事
→ 冷代码校验、补回与标记降级
→ 热清单重注入关键事实
→ 原文按需回读
→ 真实 reader 验收
```

这不是因为 DAG、热清单或某个模型天然先进，而是因为它们分别服务两条公理：

- 原文与指针解决**证据不增**；
- 热清单与回读解决**可见性**；
- 冷代码与真实 reader 解决**不得把生成当事实**。

路线可以优化，但这句铁律不能漂移。

---

## 市场上的方向都只是猜想

| 方向 | 只有在什么条件下才值得采用 |
|---|---|
| 截断 / 滑动窗口 | 被丢弃的历史不再影响后续任务 |
| 规则抽取 / 状态机 | 主体、时点与语义抽取经过真实样本验证 |
| LLM 摘要 | 派生事实可回证，且 reader 任务不明显退化 |
| 递归摘要 | 不重复折同一证据，不把旧摘要当根证据 |
| token 级压缩 | 不改变约束、否定词、标识符与关键事实 |
| RAG / 图检索 / 文件外部化 | reader 真能找到、取回并使用所需证据 |
| agent 自主整理 | 没有不受约束的删除权，且可回滚、可验收 |
| 缓存 / 快照 | 只降低成本，不冒充事实保留 |
| **DAG + 增量 fold + 热清单（我们）** | 也只在真实 reader 证据范围内成立，不是天然最优 |

**我们的路线同样是待持续验证的工程选择，不是第三条公理。**

当前 K-27 只证明一个 reader 与后处理在冻结 50 题上的局部结果；K-26 已证明摘要仍会写错主体与时点；K-2 已证明直接每步清理成功工具结果会退化。这些结果都不能被“路线先进”覆盖。

---

## 以后只问四个问题

任何新方向进入默认路径前，只问：

1. **原始证据还在吗？**
2. **关键证据会持续可见吗？**
3. **每条派生事实能回到原始证据吗？**
4. **真实 reader 在 full/compact 配对下还能完成任务吗？**

答不出来，就是猜想；实验不通过，就不采用。

> **压缩不是把历史写短，而是让未来仍然知道：发生了什么、证据在哪里、现在该相信什么。**
