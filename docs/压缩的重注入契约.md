# 压缩的重注入契约：哪些东西永远不靠摘要活

> 2026-11-01 · 依据 `docs/research/02-product-practice.md` §8.1-⑤
> （Claude Code 有一张「What survives compaction」的逐机制确定表；我们没有，补上。）
>
> **判据**：这些东西之所以"不靠摘要"，是因为摘要可能丢、可能被模型改写、可能在降级时被裁掉。
> 凡是有"丢了就不可恢复"性质的，必须在每一步**重新灌进**上下文（而不是指望它活在上一次的摘要里）。

---

## 1. 契约表

| # | 项目 | 来源 | 谁负责重灌 | 机器判据 |
|---|---|---|---|---|
| ① | **根目标**（用户最初要什么） | 首条 user 消息 | `ledger.mjs` 的 `ROOT USER (verbatim)` | `test/ledger-boundary.test.mjs` #4 |
| ② | **约束**（不能做/必须做，逐字） | 所有 user 消息里抽取的约束 | `CONSTRAINTS (verbatim)` | 同上 |
| ③ | **失败边**（试过且失败 + 原因原文 + 证据 seq） | keeper 从工具结果分类 | `LEARNED (N failed attempts)` 段，**任何降级档位都不砍 seq** | 同上 + A |
| ④ | **未落地的选项**（candidate / live-unsettled） | 悬空边分类 | `OPTIONS (not yet landed)`，L2+ 至少留计数行 | 同上 + D |
| ⑤ | **未验证声明**（跑了但没外部信号） | verifier 的 `unverified` | `UNVERIFIED (ran, but no external signal)` | 同上 |
| ⑥ | **当前路径 / 工作位置** | 棋谱的 agent 节点链 | `# WORKING:` / `# path:` 行 | 同上 |
| ⑦ | **出处**（seq / edge id） | 每条边自带 | 行内 `(seq a-b)`，**全档保留** | 同上 + A + I |

## 2. 为什么这七项、而不是别的

- **① ②**：丢了会**改变任务本身**（"必须" 和 "最好" 是两个任务）。摘要可以概括叙事，但不能改写这两类。
- **③ ⑤**：丢了会**重复踩坑 / 把猜测当事实**。失败原因是唯一的判别依据；`unverified` 是防止把猜测升格成结论的闸门。
- **④**：丢了会让模型以为"只有当前这一条路"（提取诱发遗忘）——沉默本身就是断言。
- **⑥**：丢了会**不知道自己在哪**，从而重复已完成的工作。
- **⑦**：丢了就**无法回查**——一段没有出处的历史，等于不可验证的传闻。

## 3. 什么**不**在这张表里（以及为什么）

| 不进契约的东西 | 理由 |
|---|---|
| 工具定义 / 工具用法 | 属于工具层与系统提示词（越界，见 `docs/压缩的职责边界.md`） |
| AGENTS 规则本身 | 属于 agent-instructions；压缩只在它**作为会话事实出现**时把它当作约束记下来，不负责重述 |
| persona / 语气 | 系统提示词职责 |
| 跨会话记忆 / 知识库条目 | 记忆系统职责 |
| "下一步该做什么" | 模型/AGENTS 的判断；压缩只给事实（本轮已清理 4 处越权） |

## 4. 墓碑测试（缺少任何一项必须变红）

`test/ledger-boundary.test.mjs` 的 **#4 重注入契约**：构造一张同时含根目标、约束、失败边、OPTIONS、UNVERIFIED、seq 的图，
逐项断言它们在 `renderLedger().text` 里出现。断言用**内容**而不是标题措辞 —— 改标题不会误红，删信息一定红。

> 建议后续把这张表也接进 `doctor`：对 live 的每张图渲染一次，检查七项是否齐全，
> 缺项时给 `warn`（而不是 error）—— 因为某些图天然没有 OPTIONS 或 UNVERIFIED。

## 5. 机器判据（2026-11-01 补齐：`scripts/handoff-check.mjs`）

> 墓碑测试只证明**夹具**里七项齐全；生产的图形态差得远。所以补一个**只读**的可执行检查：
> 对 `DSH_HOME/chess-context/sessions/*/graph.json` 每张图渲染一次，逐项判定：
> ①根目标 ②约束 ③失败边 ④未落地选项 ⑤未验证 ⑥当前位置 ⑦出处覆盖率 ⑧省略行可解析 ⑨预算。
> 用法：`node scripts/handoff-check.mjs`（人读）/ `--json`（机读）/ `DSH_HOME=…`（换 home）。退出码：有 FAIL ⇒ 1。

**它第一次跑 live 就抓到三个真缺口（均已修，2026-11-01）**：

1. **⑤ 在 L2+ 静默消失** —— 与当年 OPTIONS 同一类错误（沉默 = 断言「没有未验证的东西」）。
   修法：L2+ 至少留一行 `UNVERIFIED: N unproven (latest eN) — detail in graph.json`。
   代价：有未验证声明的紧档会话可能 over-budget（实测 500→513，+13 tokens）；**有意为之**，doctor 的
   `over-budget` 指标会把这个代价显性化，而不是让模型以为「没有未验证的东西」。
2. **失败边不是物理上一行** —— 多行 errorSnippet 会把 `(seq …)` 挤到第二行，模型读到「一条边拆成两行」，
   出处覆盖率也被误判成「渲染器在砍 seq」。修法：intent/reason 统一单行化（换行→空格，字符数不变）。
3. **出处覆盖率口径把 OPTIONS/UNVERIFIED 算进分母** —— 它们本来就不带 seq ⇒ live 覆盖率恒 <1（0.22/0.43/0.80），
   指标变噪音。修法：只统计失败边行；并区分「渲染器砍 seq」（fail）与「源边本来没有 evidence」（warn，数据缺口）。

## 6. 压缩质量验收清单（2026-11-01）

> 前面五节讲「必须保住什么」，这一节讲**怎么用机器证明它保住了**。
> 全部是零模型调用的指标；每一项都已有 live 消费者（doctor / ledger-budget.json / graph.json），
> 不存在「算着但没人看」的指标（第 2 轮踩过的坑）。

| # | 指标 | 判据 | 在哪看 | 现在（live，2026-11-01） |
|---|---|---|---|---|
| 1 | `provenanceCoverage` | **必须 = 1**（边行里带 `(seq …)` 或 `(sa-b)` 的比例） | `ledger-budget.json` 的 `provenanceMin` / doctor | 未采集（新代码未在 live 跑过） |

| 4 | `foldMarks.dangling.liveUnsettled` | 记录趋势；**升高说明 fold 边界切在动作中间** | `graph.json` 的 `foldMarks[i].dangling` | 新字段，尚无样本 |

| 6b | **保真度 L1**（`fold-quality.mjs`）：`constraintRecall` / `failureRecall` / `compressionRatio` | 前两个**必须 = 1**（丢一条约束=任务变了；丢一条失败边=必然重踩）；`compressionRatio` 只记趋势不设阈值 | engine 每次 fold 写 `foldMarks[i].quality`；doctor「压缩保真度（最近 fold）」显示召回下限/压缩比，并**点名**丢失的约束与失败边 | ✅ 模块+测试（`c406163`）→ engine 接线（`622db95`）→ doctor 显示 + 回归（本轮） |

**验收流程（发版前跑一遍）**：

```bash
node test/run.mjs 2>&1 | tail -3        # 全量必须 0 failed
node scripts/bench-repro.mjs            # 热清单 token 不许出现意外 DRIFT
node scripts/handoff-check.mjs          # 压缩产物交接检查
node scripts/doctor.mjs                 # live 状态：错误 0，警告需逐条解释
```

**一条纪律**：任何新增指标，必须同时回答「谁消费它」。没有消费者的指标一律不许进代码 ——
否则它会一直算着，而没人知道它算得对不对。

### 6b 的行为验证（2026-11-01，用 live 图跑的纯函数对照）

拿会话 `9d5551ed`（9 条失败边 / 2 条约束）做两次输入对照：

| 输入 | constraintRecall | failureRecall | compressionRatio | missing |
|---|---|---|---|---|
| **空摘要** | 0 | 0 | null | 9 条失败边 + 2 条约束逐条列出 |
| **提到全部失败边 id 与约束原文的摘要** | 1 | 1 | 313.73 | 空 |

**结论**：这个指标不只是「算得出来」，而是真的能区分「留住」与「丢了」；而且丢的时候会**逐条点名**
（`missingFailures: ["e3","e4","e6",...]`、`missingConstraints: [...]`），可以直接拿来排查是模型没按模板写、
还是渲染层根本没把它放进清单。

**这一条验证为什么必要**：前面几轮已经踩过一次——`sections` 第一版把字符当 token 算，得出「失败边占 238%」。
**指标本身也要被验证**，不能因为它有测试就假定它测得对。

### 6b 的生产链路验证（2026-11-01，`real-fold-trigger.mjs` 跑出的真实 fold）

`node test/real-fold-trigger.mjs`（真实模型 magpie，自动 fold 全链路）通过 **5/5** 后，检查它落盘的图：

```
foldCount: 1 | foldMarks: 1
  #1 | 遮蔽 120,000 tok | summaryChars 335
    cRecall=1 fRecall=1 ratio=714.29 | expected c=0 f=0 | missing c=[] f=[]
```

**确认了两件事**：

1. **`foldMarks[i].quality` 在真实 fold 上确实被写入** —— 从 `summarize()` 记账 → `measureFoldQuality()` →
   `foldMarks.push()` → `doctor` 读取，整条链路是通的，不是只有单测能跑。
2. **但这次是「真空通过」**：夹具（`fold-trigger`）里没有约束也没有失败边（`expectedConstraints=0 / expectedFailures=0`），
   所以 `recall=1` 只证明"没有东西可丢"，**不证明"有东西时不会丢"**。

**因此下一步要做的是**：给 `real-fold-trigger.mjs` 的夹具补上约束与失败边（至少各 2 条），
让真实 fold 的 `constraintRecall` / `failureRecall` 变成**有内容的检验**。
在那之前，真实语料上的保真度只有"链路通"这一级证据，**不能宣称"真实会话里也恒为 1"**。
