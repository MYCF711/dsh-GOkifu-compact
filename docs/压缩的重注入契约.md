## 先读这一段：清单是「常驻」的，别用「写入率」判断可见性（C195）

热清单写进 surface 后**一直存在**，直到被折叠压掉（压掉后有 `lostToFold` 自动补写）。
限流规则（≥40 个事件 / 失败边多 5 条才重写）是为了**不每步重复注入**。

所以 doctor 报的「清单写入 7/291（2%）」是**正常**的：

| 指标 | 含义 | 健康区间 |
|---|---|---|
| 清单写入率 | 每次渲染尝试里**真正写进 surface** 的比例 | 低（1%–20%）说明限流在起作用 |
| `skipReasons` | 被跳过的原因分布（throttled-* / identical / same-digest） | `throttled-*` 占多数 = 设计如此 |
| 清单可见性 | 模型看到的最新清单 = surface 上那一条 | 由 `lostToFold` 保证「被压掉会补写」 |

**真正异常**：写入率 0% 且 `lostToFold` 从不触发（清单被压掉也不补）—— 那时 doctor 的
「热清单预算」会同时缺 `skipReasons`（旧版本）或 `none` 计数异常，两者一起看。

# 压缩的重注入契约：哪些东西永远不靠摘要活

> 2026-11-01 · 依据 `docs/research/02-product-practice.md` §8.1-⑤
> （Claude Code 有一张「What survives compaction」的逐机制确定表；我们没有，补上。）
>
> **判据**：这些东西之所以"不靠摘要"，是因为摘要可能丢、可能被模型改写、可能在降级时被裁掉。
> 凡是有"丢了就不可恢复"性质的，必须在每一步**重新灌进**上下文（而不是指望它活在上一次的摘要里）。

---

## 1. 契约表

| # | 项目 | 来源 | 谁负责重灌 | 机器判据 |
|---|---|---|---|---|
| ① | **根目标**（用户最初要什么） | 首条 user 消息 | `ledger.mjs` 的 `ROOT USER (verbatim)` | `test/ledger-boundary.test.mjs` #4 |
| ② | **约束**（不能做/必须做，逐字） | 所有 user 消息里抽取的约束 | `CONSTRAINTS (verbatim)` | 同上 |
| ③ | **失败边**（试过且失败 + 原因原文 + 证据 seq） | keeper 从工具结果分类 | `LEARNED (N failed attempts)` 段，**任何降级档位都不砍 seq** | 同上 + A |
| ④ | **未落地的选项**（candidate / live-unsettled） | 悬空边分类 | `OPTIONS (not yet landed)`，L2+ 至少留计数行 | 同上 + D |
| ⑤ | **未验证声明**（跑了但没外部信号） | verifier 的 `unverified` | `UNVERIFIED (ran, but no external signal)` | 同上 |
| ⑥ | **当前路径 / 工作位置** | 棋谱的 agent 节点链 | `# WORKING:` / `# path:` 行 | 同上 |
| ⑦ | **出处**（seq / edge id） | 每条边自带 | 行内 `(seq a-b)`，**全档保留** | 同上 + A + I |

## 2. 为什么这七项、而不是别的

- **① ②**：丢了会**改变任务本身**（"必须" 和 "最好" 是两个任务）。摘要可以概括叙事，但不能改写这两类。
- **③ ⑤**：丢了会**重复踩坑 / 把猜测当事实**。失败原因是唯一的判别依据；`unverified` 是防止把猜测升格成结论的闸门。
- **④**：丢了会让模型以为"只有当前这一条路"（提取诱发遗忘）——沉默本身就是断言。
- **⑥**：丢了会**不知道自己在哪**，从而重复已完成的工作。
- **⑦**：丢了就**无法回查**——一段没有出处的历史，等于不可验证的传闻。

## 3. 什么**不**在这张表里（以及为什么）

| 不进契约的东西 | 理由 |
|---|---|
| 工具定义 / 工具用法 | 属于工具层与系统提示词（越界，见 `docs/压缩的职责边界.md`） |
| AGENTS 规则本身 | 属于 agent-instructions；压缩只在它**作为会话事实出现**时把它当作约束记下来，不负责重述 |
| persona / 语气 | 系统提示词职责 |
| 跨会话记忆 / 知识库条目 | 记忆系统职责 |
| "下一步该做什么" | 模型/AGENTS 的判断；压缩只给事实（本轮已清理 4 处越权） |

## 5. 机器判据（2026-11-01 补齐：`scripts/handoff-check.mjs`）

> 墓碑测试只证明**夹具**里七项齐全；生产的图形态差得远。所以补一个**只读**的可执行检查：
> 对 `DSH_HOME/chess-context/sessions/*/graph.json` 每张图渲染一次，逐项判定：
> ①根目标 ②约束 ③失败边 ④未落地选项 ⑤未验证 ⑥当前位置 ⑦出处覆盖率 ⑧省略行可解析 ⑨预算。
> 用法：`node scripts/handoff-check.mjs`（人读）/ `--json`（机读）/ `DSH_HOME=…`（换 home）。退出码：有 FAIL ⇒ 1。

**它第一次跑 live 就抓到三个真缺口（均已修，2026-11-01）**：

1. **⑤ 在 L2+ 静默消失** —— 与当年 OPTIONS 同一类错误（沉默 = 断言「没有未验证的东西」）。
   修法：L2+ 至少留一行 `UNVERIFIED: N unproven (latest eN)`（C56 起去掉冗余的「— detail in graph.json」：位置已由 graph.json / nodes/<id>.md 承载）。
   代价：有未验证声明的紧档会话可能 over-budget（实测 500→513，+13 tokens）；**有意为之**，doctor 的
   `over-budget` 指标会把这个代价显性化，而不是让模型以为「没有未验证的东西」。
2. **失败边不是物理上一行** —— 多行 errorSnippet 会把 `(seq …)` 挤到第二行，模型读到「一条边拆成两行」，
   出处覆盖率也被误判成「渲染器在砍 seq」。修法：intent/reason 统一单行化（换行→空格，字符数不变）。
3. **出处覆盖率口径把 OPTIONS/UNVERIFIED 算进分母** —— 它们本来就不带 seq ⇒ live 覆盖率恒 <1（0.22/0.43/0.80），
   指标变噪音。修法：只统计失败边行；并区分「渲染器砍 seq」（fail）与「源边本来没有 evidence」（warn，数据缺口）。

### 6b 的生产链路验证（2026-11-01，`real-fold-trigger.mjs` 跑出的真实 fold）

`node test/real-fold-trigger.mjs`（真实模型 magpie，自动 fold 全链路）通过 **5/5** 后，检查它落盘的图：

```
foldCount: 1 | foldMarks: 1
  #1 | 遮蔽 120,000 tok | summaryChars 335
    cRecall=1 fRecall=1 ratio=714.29 | expected c=0 f=0 | missing c=[] f=[]
```

**确认了两件事**：

1. **`foldMarks[i].quality` 在真实 fold 上确实被写入** —— 从 `summarize()` 记账 → `measureFoldQuality()` →
   `foldMarks.push()` → `doctor` 读取，整条链路是通的，不是只有单测能跑。
2. **但这次是「真空通过」**：夹具（`fold-trigger`）里没有约束也没有失败边（`expectedConstraints=0 / expectedFailures=0`），

**因此下一步要做的是**：给 `real-fold-trigger.mjs` 的夹具补上约束与失败边（至少各 2 条），

在那之前，真实语料上的保真度只有"链路通"这一级证据，**不能宣称"真实会话里也恒为 1"**。

### ⚠ 6b 的更正（2026-11-01，同日晚）：`real-fold-trigger` **不能**验证保真度

上一版这里写过「下一步给 `real-fold-trigger.mjs` 的夹具补约束与失败边」。**这个判断是错的**，实测后更正：

- 该脚本的 session 是**手写桩**，没有触发 `ctx.on("session/event", …)`（engine 就是在那里调 `observeEvent` 的）；
- 所以 **keeper 根本没跑**，落盘的图里 `user 节点数 = 0`、`expectedConstraints = 0`、`expectedFailures = 0`；
- 给它加约束 / 失败边的 seed **不会改变任何结果**——`recall = 1` 永远是真空通过。

**当时写的「正确的验证路径只有两条」已被下面的更正之二推翻**（第三条路是可行的）：

1. `test/fold-quality.test.mjs` —— 合成图（直接构造 `nodes` / `edges`），能精确控制期望值；
2. **真实 DSH 会话**的 fold —— 等 `foldMarks[i].quality` 在 live 上出现，再看 `constraintRecall` / `failureRecall`；
3. ~~不存在~~ ⇒ **见更正之二：`real-fold-trigger.mjs` 现在可以**。

**教训**：验证一个指标时，先确认"产生数据的链路真的跑起来了"，再谈"指标算得对不对"。
这次就是先看到 `quality` 字段存在（链路看起来通），再看 expected 全是 0，才反推出 keeper 根本没跑。

### ⚠ 6b 的更正之二（2026-11-01，同日更晚）：`real-fold-trigger` **已能**验证保真度链路

上面那条更正把原因诊断对了（keeper 没跑），但结论下早了：**问题不是"没法验证"，而是"桩没把事件派发出去"**。

修法（`test/real-fold-trigger.mjs`）：
- `session.append()` 里加 `session._emit(event)` → `buildCtx()` 里接成 `ctx.emit("session/event", session, event)`
  —— engine 的 keeper 正是注册在 `ctx.on("session/event", …)`；
- 补一条**失败的**工具调用 + 紧随其后一个 `step/end`（keeper 在这一步建 agent 节点并把边指向它，
  否则边一直 `to=null`，10 分钟后会被判成 rewash 残留、保真度统计不到）；
- 校验改成看**所有** foldMark（增量 fold 的早期 range 才包含那条失败边）+ 落盘/内存双读。

实测（真实模型 `group/deepseek-v4.1-flash1017`，3 次 fold）：

```
fold#1 seq 2-25  quality: c=2/1  f=1/0     ← 期望约束 2 / 期望失败边 1，链路不再是真空
fold#2 seq 26-28 quality: c=2/1  f=0/1
fold#3 seq 29-42 quality: c=2/1  f=0/1
保真度：ok（约束 2 / 失败边 1 · cRecall=1 fRecall=0 ratio=351）
```

**这条证据的边界（必须一起读）**：本文件的 `ctx.llm` 是**桩**，它不使用引擎给的棋谱指令 + 机械事实块，
而是自己拼一段 prompt ⇒ `constraintRecall=1` 是引擎机械追加保证的（这条有效），
`failureRecall=0` 反映的是**桩 prompt 没把失败边喂给模型**，**不代表生产路径**。
它证明的是：**engine → keeper → fold-quality → foldMarks 这一段是真的在跑、且期望值不再是 0**。
生产口径的 `failureRecall` 仍需等 live 真实 fold 的 `foldMarks[i].quality`。

### 6c 哪些字段**有意**只做全局口径（不需要单会话门禁）

C79 之后，合同 §6 的 16 行全部有「单会话 handoff-check + 全局 doctor + 证据页」三层覆盖。
剩下的 `foldMark` 字段不再加门禁，理由写在这里，避免下次再问「为什么它没有检查项」：

| 字段 | 为什么不做单会话门禁 | 现在谁在用 |
|---|---|---|
| `route.provider` / `route.model` | **纯诊断**：记录这次摘要走了哪条路由，没有「好坏阈值」可判（换了模型不是错误） | doctor「最近 5 次 fold」逐条显示 |
| `ms`（摘要耗时） | 纯诊断：耗时受模型/网络影响，单次慢不构成缺陷（趋势看 `live-folds`） | doctor 最近 5 次 / `live-folds` 逐次表 |
| `summaryChars` | 与 `quality.summaryTokens` 重复度量同一件事（长度），后者已进 ⑩ 保真度与成本口径 | doctor / `live-folds` |
| `totalAfter` / `foldCount` | 会话级计数，语义是「fold 之后总量 / 第几次」，没有可判错的边界 | doctor / `live-folds` |
| `fallback`（摘要降级） | **有阈值**（rules 降级应告警）但判据属于**全局质量趋势**：单会话偶发一次规则降级不是交接阻塞项 | doctor 成本/保真度；`live-folds` 逐次表 |
| `at` / `seqStart` / `seqEnd` | 定位信息；其中区间**已间接校验**（⑯ 闭包自洽检查 `seqStart <= seqEnd`） | ⑯ / 证据页排序 |

**判据**：只有当字段存在「**可判错的边界**」时才加门禁（如 `openAtEnd > 0`、`nodes > graphNodes`、`share < 30%`）；
纯粹描述「发生了什么」的诊断字段，只要有**可读的消费者**即可，不必变成红绿灯。
