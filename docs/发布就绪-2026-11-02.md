## 4. 「已无优化方向」的依据（逐项）

1. **热清单成本**：从全量 28,800 → **415 tokens**（−98.6%），且失败边保留 8/8、约束与根目标逐字不丢。
   再压只能靠**删内容**（失败记忆/约束），已实测否决（`evidence/热清单超预算归因-2026-11-02.md` §4 的 L6 实验：
   能压到 238，但破坏 M2/L5 契约）。
2. **超预算**：现存超限全部是 `floor`（约束+根目标下限即超）或 `irreducible`（已是最省仍超），
   `bug = 0` —— 没有「还能更省却没省」的渲染缺陷可选。
3. **保真度**：真机 c=1 / f=1 / unknownIds 0 已连续多轮；降级路径（规则摘要）也记 quality（C7）。
4. **边界**：三轮清扫（C45/C46/C47）+ 专员审计（C64）后，模型可见文本已无行动/认知指导；
   审计规则从 2 条扩到 5 条，且每条都有「纯事实不假红」的反向用例。
5. **可观测**：所有写入字段都有消费者（C65/C67 收掉最后两个死字段），且消费者本身有测试（C66）。
6. **诊断安全**：诊断不再可能把成功的 fold 变成失败（C64），也不会默认写仓库（C65）。

## 5. 已知缺口与「为什么不修」

| 缺口 | 判断 | 理由 |
|---|---|---|
| `superseded_by` 的**渲染层**标记 | 暂缓 | live 24 会话 **0 次置换合并** ⇒ 每行加标记只会增 token；等真实样本出现再单独一刀（带 bench） |
| 「块 → 原始 seq」完整闭包 | 暂缓 | 需要动 graph schema（契约先行）；当前 `closure` 计数+首尾 id 已满足可寻址性 |
| `derivable` 标记 | 不适用 | 热清单/摘要都不注入「工具输出体」，没有可再取的降级落点（`evidence/热清单内容普查-2026-11-02.md`） |
| `lastFoldVersion` 版本戳 | 暂缓 | 单进程写回，无跨进程一致性需求 |
| doctor 的 3 条警告 | 设计内/待重启 | ① `buildId` 落后 = 等重启；② home 层 drift = 退出自愈；③ over-budget = 已归因的设计内超限 |
| 历史摘要里的旧文案（`需要时按 seq 回读`） | 不重写 | 已落盘摘要不追溯改写（改写历史 = 破坏「摘要就是当时产物」的性质）；新摘要已修 |
| **第三方 preset 的压缩后端** | 不覆盖（只登记） | 例如 `dsh-design-studio:preset-design`（设计模式）自带 `compaction-basic` ⇒ 该模式不走棋谱压缩。强行覆盖属越权且会被对方升级冲掉；doctor 新增检查会点名（C94） |
