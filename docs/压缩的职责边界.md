# 压缩的职责边界：GOkifu 只做 compact，不越权

> 2026-11-01 · 主人在调研任务里明确定调：
> **「分清楚哪些是压缩 compact 的任务，哪些不是，不要把 AGENTS、tools、系统提示词等其他地方涵盖的功能越权覆盖。只做好本职工作，把本职工作做到最好。」**
>
> 这份文档就是那条边界线的成文法：判据、清单、以及当前代码的审计结果。**改代码前先读它；新增任何注入内容前先过第 2 节的判据。**

---

## 1. 一句话判据

> **一段内容属于「压缩」，当且仅当它同时满足两条：**
> **① 它产自本次会话的历史**（不是产品自带的知识、不是通用规则、不是工具契约）；
> **② 它只在压缩生命周期里出现**（决策压什么 / 执行压缩 / 呈现压缩产物），不常驻、不解释世界。

两条都满足才算本职；缺一条就等于替别的机制干活。

## 2. 职责清单（按机制分，越权 = 红线）

### ✅ 属于压缩（GOkifu 的本职）

| 职责 | 具体内容 | 落到代码 |
|---|---|---|
| **决定压什么** | 阈值/增长闸、候选区间、保护区（最近 N 条、首条 user、工具对边界） | `fold-planner.mjs`、`engine.mjs` 的 `compactIfNeeded()` |
| **决定不压什么** | 根目标（pinned）、约束、失败边、未验证声明、被保护工具的最近快照 | `kifu-model.mjs` 节点类型、`facts-prompt.mjs` 的抽取 |
| **执行压缩** | 把旧历史降维成棋谱摘要；机械抽取事实 + 一次模型润色；超长整条拒绝而不是截断 | `engine.mjs` 的 `summarize()`、`ledger.mjs` 的 `renderFacts` |
| **保真校验** | 摘要丢没丢约束/失败边、有没有把 UNVERIFIED 升格成事实、有没有编造节点 | `verify.mjs`、`facts-prompt.mjs` 的规则 |
| **压缩产物的可见性** | 把「压缩掉了什么、还剩哪些失败边/约束」以最小体积呈现给模型（热清单） | `hot-inject.mjs`、`ledger.mjs` 的 `renderLedger` |
| **可回溯** | 被遮蔽的消息仍在 append-only 日志里，压缩块能指回原始 seq 区间 | `foldMarks`、`sessionPaths` |
| **去重/降维的确定性策略** | 同工具同参数只留最新、同义重复（置换）合并、重复报错合并 | `kifu-model.mjs` 的 `mergeNodeInto`、`transposition` |
| **成本与延迟** | 压缩调用本身的 token 预算、失败重试、fallback | `engine.mjs` 的 fallback 仪表盘 |
| **可观测** | 折了几次、遮蔽多少 token、失败边几条、缓存命中 | `doctor.mjs`、`/gokifu/api` 的 `today/latest` |

### ❌ 不属于压缩（碰了就是越权）

| 机制 | 它负责什么 | 压缩绝不能做的事（反例） |
|---|---|---|
| **AGENTS.md / 硬规则** | 用户与项目的**恒定行为规则**（"禁关 magpie"、"不要手改 profile patch"） | 不许把"你应当先备份再改"这类通用规则写进热清单或摘要模板；不许因为"压缩后模型可能忘记规则"就自己再复述一遍规则 |
| **persona / 系统提示词** | 模型的身份、语气、能力边界 | 不许改 persona 的措辞、不许在 system 段落里追加"压缩提示"、不许教模型"何时该 restore"（那是行为指导） |
| **tools 定义与治理** | 工具 schema、权限、approval、sandbox | 不许改工具描述/参数、不许自建"decompress 工具"去接管工具层、不许做 `permission: allow\|ask\|deny` 这类治理开关（那是宿主/工具层的事） |
| **跨会话记忆 / 知识库** | 跨会话的事实沉淀、检索、知识图谱 | 不许把本次棋谱写进跨会话库、不许做"从历史会话检索"、不许把 Hindsight/向量库接进来当压缩 |
| **上下文工程（context engineering）** | 如何挑选、组织**本次请求**的上下文（哪些文件、哪些工具结果进窗口） | 不许决定"该读哪个文件"、不许预先裁剪工具结果（那是 `tool-result-pruner` 的事）、不许改请求的消息组织 |
| **提示压缩（prompt compression）** | 推理前压缩**输入文本**（LLMLingua 类），每次推理都要重算 | 不许把它混进会话历史压缩（两者生命周期完全不同：一个不改变历史，一个是持久化改写） |
| **UI / 展示** | 设置页、图表、配置表单 | 不许在压缩路径里做展示逻辑；页面只读压缩产物 |

### ⚠️ 灰色地带与裁决

| 场景 | 裁决 | 理由 |
|---|---|---|
| **每步注入热清单**（不只在压缩后） | ✅ 属于压缩 | 它是**压缩产物的可见性保障**：被遮蔽的内容模型看不到，热清单是唯一窗口。前提是内容**全部来自棋谱**（根目标/约束/失败边/当前路径），一旦掺入通用建议就越界 |
| **摘要指令里的 "You are the fold engine…"** | ✅ 属于压缩 | 它只喂给**摘要模型**，不注入主 agent，是压缩执行的一部分 |
| **摘要里的 "Never promote UNVERIFIED to fact"** | ✅ 属于压缩 | 这是压缩产物的**保真规则**，不是 agent 行为指导 |
| **教模型"何时该 restore"** | ❌ 越界 | 这是行为指导 → 应放在 AGENTS 或宿主提示里。压缩只能**提供事实**（"seq 10-643 已折叠，可用 X 还原"），不能教"你应该还原" |
| **压缩后自动重放规则** | ❌ 越界 | 规则的持久化是 AGENTS 的职责；压缩只管"历史里出现过什么" |
| **受保护工具（todo/skill）最近快照不压** | ✅ 属于压缩 | 这是**压什么/不压什么**的决策，属于压缩策略 |
| **`protectedTools` 的配置项** | ✅ 属于压缩 | 它配置的是"压缩时避开哪些工具的历史"，不是工具本身的权限 |

## 3. 当前代码的边界审计（2026-11-01）

| 位置 | 行为 | 判定 |
|---|---|---|
| `src/rooms/facts-prompt.mjs` `buildChessInstruction()` | 生成摘要指令（含"You are the fold engine"、禁编造、禁升格） | ✅ 只喂摘要模型，不外泄给主 agent |
| `src/rooms/ledger.mjs` `renderLedger()` | 渲染热清单（ROOT GOAL / CONSTRAINTS / FAILED ATTEMPTS / CURRENT PATH） | ✅ 全部来自棋谱事实，未见通用建议 |
| `src/rooms/hot-inject.mjs` `decideInjection()` | 每步 replace 一条 ledger；空图 skip | ✅ 只负责"压缩产物的可见性" |
| `src/engine.mjs` `summarize()` / `compactIfNeeded()` | 覆盖官方策略，保留 surface 事务 | ✅ 压缩核心行为 |
| `src/engine.mjs` 继承 `BasicCompactionEngine` | 事务/锁/`<compacted-summary>` 框定/工具对边界全交给官方 | ✅ 不重写宿主不变量 |
| `src/ui.mjs` `/gokifu/api` | 配置读写 + 健康自检 + 图表数据 | ✅ 展示层，不参与压缩决策 |
| `cordis.patch.yml`（1.16） | 只插 `gokifu-ui` + 覆盖四个官方 preset 的 compaction 行 | ✅ 不改工具/规则/提示词 |

**结论（2026-11-02 修订）：历史上发现并已修掉的越权项**（每一条都写了测试，见 CHANGELOG C15/C45/C46/C47/C64）：

| 位置 | 越权形态 | 状态 |
|---|---|---|
| `renderFacts`/`ruleSummary` 的「下一步：…」 | 行动指导 | ✅ C15 删除 |
| 标记图例 `retry when it changes` / `take it` / `or create it` | 行动建议 | ✅ C45 改为事实口径 |
| 标记图例 `dead = … (retry-if edge exists)` | 「何时可再试」的暗示 | ✅ C64 改为 `the tag names that edge` |
| 热清单置换告警 `…，别重复。` | 祈使短句（行动指导） | ✅ C64 删除末句 |
| 摘要模板 `需要时按 seq 回读` | 教模型何时恢复记忆 | ✅ C64 改为 `（seq 可定位）` |
| 摘要标题 `## 已探明死路（逐条保留，一条不许少）` | 指令随摘要长期留在上下文 | ✅ C47 改为章节名 |

**当前仍然没有「已知未修」的越权项**，但审计规则覆盖是渐进补齐的（C45 补英文 retry、C46 补认知指令、
C64 补祈使短句与「何时回读」）—— 新规则都带有「纯事实写法不假红」的反向用例。需要长期盯住的三个风险点：

1. **热清单膨胀**：如果以后往里加"建议做什么"，就越界。约束：热清单只放**已发生的事实**与**用户/系统已声明的约束**，不放"下一步应该"。
2. **摘要指令膨胀**：给摘要模型的规则越多，越容易滑向"用摘要模型替 agent 做决策"。约束：摘要模型只做**降维与保真**，不做规划。
3. **"还原"能力**：如果实现 restore，只能提供**寻址事实**（哪个 seq 区间、怎么取），不能教模型何时用。

## 4. 与「其它机制」的接口（只读，不改写）

压缩必须**读懂**兄弟机制产出的东西，但**只读不改**：

| 来源 | 压缩怎么用它 | 绝不能做 |
|---|---|---|
| 系统提示词 / persona | 识别哪条 user 消息是真正的任务（首条 user 钉住） | 改写它 |
| AGENTS 规则 | 会话里出现的规则片段可作为约束计入棋谱 | 主动复述或解释规则 |
| 工具调用记录 | 作为节点/边进入棋谱；工具对边界由官方保证 | 改工具 schema、裁剪工具输出（那是 pruner 的活） |
| 用户消息 | 根目标 + 约束逐字保留 | 改写用户原话 |
| 宿主 compaction 事务 | 继承 `compactRegion`/`compactNow`/`surfaceOp: replace` | 绕过事务直接删消息 |

## 5.1 机器审计（2026-11-01 起，可执行）

人工自检之外，跑一条命令把最容易越界的两类东西变成检查（只扫**字符串字面量**、先剥注释）：

```bash
node scripts/boundary-audit.mjs        # 0 条才算过；--json 机读
```

- **行为指导**：`下一步：` / `不要重试` / `you should` / `continue or abandon` 等出现在模型可见字面量里 ⇒ error；
- **工具治理**：`permission: allow|ask|deny` / `approval:` / `sandbox_permissions` ⇒ error；
- 唯一豁免：`src/rooms/facts-prompt.mjs` 的 `behavior-guidance`（那是**只喂摘要模型**的指令模板，
  约束压缩行为、不注入主 agent），豁免必须写在脚本 `ALLOW` 里并注明理由。

它的第一次运行就抓到一条真实残留：`renderFacts` 的 `STALE_UNSETTLED … (continue or abandon)`
—— 上一轮清理 OPTIONS 时漏在了事实块里。**这就是人工审计会漏的证据。**

## 5. 边界自检（提交前跑）

新增任何压缩行为前，问五个问题，有一条答不上就不要写：

1. **它产自本次会话历史吗？**（否 ⇒ 不是压缩）
2. **它只在压缩生命周期里出现吗？**（常驻提示词 ⇒ 越界）
3. **它改变了模型"该做什么"吗？**（是 ⇒ 属于 AGENTS/persona）
4. **它改了工具契约或权限吗？**（是 ⇒ 越权）
5. **它跨会话了吗？**（是 ⇒ 属于记忆/知识库）

## 6. 与调研的关系

`docs/research/` 下的调研（学术 / 产品实践 / 人类记忆）只用来回答一个问题：
> **同样的历史，怎样降维才丢得最少、还原得最准、代价最低。**

凡是调研结论指向"记住更多/跨会话/教模型怎么做"，一律不采纳（越界）；凡是指向"压缩得更准/更省/更可回溯"，才进入候选。第 7 节的候选清单按这条筛过。

## 8. 边界复审记录（2026-11-01，第一轮）

> 背景：前面几轮只用五问自检审**新写的代码**，从没回头审**已落地的**。本轮补上。

**方法**：不用 grep 猜，而是**渲染一份真实热清单逐行读**（会话 `3a50f4d2`，L1 / 460 tokens），
外加扫 `renderFacts`（喂摘要模型的那份）。

**结果**：

| 位置 | 内容性质 | 判定 |
|---|---|---|
| `renderLedger` 热清单（给主 agent） | `ROOT USER (verbatim)` / `CONSTRAINTS (verbatim)` / `LEARNED (N failed attempts)` / `OPTIONS (not yet landed)` / `UNVERIFIED (ran, but no external signal — unproven)` / `# WORKING` / `TRACE` | ✅ 全是会话事实（C45/C46/C64 三次清扫后仍成立；`boundary-audit` 的 5 条规则 + 属性测试共同看守） |
| `renderFacts`（给摘要模型） | `[HARD FACTS — …; must survive compression unchanged]` / `keep every line, never merge, never drop` / `do not invent or merge them` | ✅ 属于**压缩执行指令**，不是给主 agent 的行为指导 |
| 约束里出现的「不要依赖它」「不要营销腔」 | **用户原话** | ✅ 属于事实保留（正是该逐字留的东西） |

**发现一个显示 bug（已修）**：约束原文自带 markdown 列表符号时，渲染又补一个 `- ` ⇒ 输出成
`- - **约束清单**（用户说的不能做/必须做）`。修法：渲染前只剥掉**前缀符号**（`^\s*[-*]\s+`），
正文一个字不改 —— 逐字保留的口径不受影响。

**下一轮复审的触发条件**（不是定期，是有事才审）：

- 任何新增注入到模型上下文的文本；
- 任何"为了让模型更好理解"而改写的措辞；
- 任何来自 doctor / 验收清单的提示语被搬进热清单的时候。

## 2026-11-02（C45）新增案例：标记图例里的英文行动建议

热清单的标记图例长期写着 `retry when it changes` / `retry only if retry-if breaks` /
`take it` / `retry when it appears, or create it` —— 这是**行动指导**（什么时候该再试、该走哪条路），
属于 AGENTS/persona 的职责，不属于压缩。

- 图例已改为**只陈述事实**（`the environment lacks a required permission` /
  `a working edge <edge> reaches the SAME position` …）；
- `boundary-audit` 新增 `retry-advice` 规则（error），把英文行动建议与中文「下一步 / 不要重试」同口径检查；
- 判据示例：`retry when …` ❌（指导） / `connection refused` ✅（事实）。

## 2026-11-02（C46）新增案例：UNVERIFIED 段里的 `treat as unproven`

「跑了但没有外部信号」是**状态**；`treat as unproven` 是**认知指令**（教模型怎么看待这批边），
属于 AGENTS/persona。现在标题只写 `UNVERIFIED (ran, but no external signal — unproven)`。

- `boundary-audit` 新增 `epistemic-advice` 规则（error）：`treat as` / `you can` / `you may` /
  `make sure to` / `be sure to` / `feel free`；
- 判据示例：`treat as unproven` ❌（认知指令） / `unproven` ✅（状态）；
- 与 C45 的 `retry-advice` 同源：压缩陈述事实，不教模型「怎么想」「怎么做」。

## 2026-11-02（C47）新增案例：摘要标题里的指令

旧摘要模板的章节标题是 `## 已探明死路（逐条保留，一条不许少）`。摘要产物会**长期留在上下文里**，
这条括号等于对后来每一轮模型持续下命令（属于 AGENTS/persona 的职责）。现在标题只写章节名，
「每条都要出现」作为**给摘要模型的规则**留在规则段（facts-prompt 内部，ALLOW 例外）。
判据：标题=结构与事实；规则=教摘要模型怎么写。两者不能混。
