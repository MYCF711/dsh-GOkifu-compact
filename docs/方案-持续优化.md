## 一 · 目标与非目标

**目标**：把「棋谱」这一层做到模型真的能用 —— 压缩之后，模型每步都能看到「目标 / 约束 / 哪些路走过 / 结果如何 / 为什么」。
**非目标**：不做 2.x 版本号冲刺、不做可视化编辑器、不做跨会话全局失败库（先把单会话做强）。

**硬约束（每条都来自现状审计）**：
1. 每步固定开销不得突破 **1 ms**（当前热清单 0.463 ms / 323 tokens，见审计 §7.2）。
2. 热清单预算 `hotLedgerMaxTokens: 500` 不许上调（上调即破坏「一屏内」的可用性）。
3. 不改 DSH 安装目录、不改 `compactRegion` 事务（继承官方 `BasicCompactionEngine`）。
4. 每个切片必须能**单独回退到旧行为**（一个配置开关或删一个文件），不允许「整层一起改」。

## 四 · 每个切片的验收判据（可复跑，不靠感觉）

### S1 · 图不变量守卫

- **实现**：`test/verify-graphs.mjs` 末尾增加不变量段：`selfLoops === 0`、`edgeNodeRatio <= 1.5`、`collapsedGraphs === 0`；违反 ⇒ `process.exitCode = 1`。
- **新增测试** `test/graph-invariants.test.mjs`：构造 3 个坏图（1 条自环 / 边节点比 2.0 / 全自环），必须全部判红；1 个健康图判绿。
- **数据清理**：`node test/rewash-selfloop.mjs --apply`（dry-run 先看），只改 `to` 字段，保留边与结果；备份在 `.bak`。
- **验收**：`node test/verify-graphs.mjs` 退出码 **0** 且输出「自环 0 = 0.0% / 坍缩图 0」；`node test/doctor.mjs` 的「图结构（自环）」从 warn → ok。

### S2 · `weak-success`

- **实现**：`verifier.classify()` 对只读工具（`read` / `glob` / `grep` / `ls`）成功返回且无错误行 ⇒ 返回 `{ result: "unverified", weak: true, verify: { kind: "read-ok" } }`；`graph.mjs` 的 WORKING 路径选取接受 `edge.weak === true` 作为「弱锚点」；`ledger.renderLedger()` 的「已验证事实」段**不列** weak 边。
- **测试**：`node test/run.mjs verifier` + `node test/run.mjs ledger` 新增 6 项：read 成功→weak；read 报错→failure；glob 空→weak；`--json` 失败→failure；WORKING 行能选 weak；已验证事实段不含 weak。
- **验收**：`test/ab-render.mjs` 夹具里，只读场景的 WORKING 行命中率 **0/5 → ≥3/5**；`node test/run.mjs` 全绿。

### S3 · 降级可见

- **实现**：`engine.summarize()` 在规则摘要路径下把 `mode: "rules"` 写进 graph 的 `lastFoldMode`；`ledger.renderLedger()` 在 `lastFoldMode === "rules"` 时输出一行 `⚠ 上次摘要是规则生成（无模型润色）`。
- **测试**：`test/engine-harness.test.mjs` 新增「LLM 抛错 → 规则摘要 → 热清单出现提示」用例。
- **验收**：规则摘要后热清单出现该行；正常 hybrid 摘要不出现；预算仍 ≤ 500 tokens。

### S4 · `minFoldTokens` 缩放

- **实现**：`resolveConfig` 里 `effectiveMinFold = Math.max(8000, Math.floor(contextWindow * 0.08))`；`range.selectIncrementalRange()` 用有效值。
- **测试**：`test/range.test.mjs` 新增 4 组（窗口 50K / 100K / 200K / 1M）。
- **验收**：200K 窗口下，原「1.2 步一 fold」的夹具不再触发；`bench.mjs` 的 `selectRange` 仍 ≤ 0.05 ms。

### S5 · `TRACE` 具体化

- **实现**：`renderLedger()` 的 TRACE 行改为 `TRACE: <index.md 路径> · recent n12 改缓存 / n15 跑测试 / n18 定位`；节点数最多 3 个、每个标签 ≤ 12 字；预算不足时退回只写路径。
- **测试**：`test/ledger.test.mjs` 新增 2 项（有最近节点 / 无最近节点）。
- **验收**：500 token 预算下仍不超；渲染耗时 ≤ 0.6 ms（bench 2000）。

### S6 · 真实链路门禁

- **实现**：`package.json` 增 `"test:real": "node test/realm.mjs"`；`test/realm.mjs` 串行跑 `real-modules → real-fold → replay-verify`，缺前置（asar / modules 闭包 / 会话日志）时打印「跳过原因」并退出 0，不允许假绿。
- **验收**：`npm run test:real` 三条全过；删除 `tmp/dsh-gokifu-compact/modules` 后报「跳过：modules 未提取」而不是通过。

### S7 · 落盘增量

- **实现**：`src/store.mjs`：`append(change)` 写 `<session>/journal.jsonl`；每 20 次或 fold 后写 `graph.json` snapshot；启动时 `journal` 重放 + snapshot 校验。`engine` 通过 `storage: "auto"` 选择，默认仍 `json`（先观察）。
- **测试**：`test/store.test.mjs`：崩溃恢复（journal 半条）、幂等重放、snapshot 与 journal 版本不一致。
- **验收**：2000 边下写放大 ≤ 旧版 1/5；恢复后 `graph` 与全量写完全等价（深比较）。

### S8 · 首折削峰

- **实现**：`firstFoldRatio`（默认 0.30）只作用于「本会话第一次 fold」；之后回到 `thresholdRatio`。
- **测试**：`test/engine-harness.test.mjs` 新增首折场景。
- **验收**：首折遮蔽量下降 ≥30%，fold 次数不增加。

### S9 · 发布链

- **实现**：补 10 个版本 tag（1.3.5 / 1.4.0 / 1.5.0 / 1.5.1 / 1.6.0–1.6.3 / 1.9.0 / 1.9.1）；npm 只发稳定版（AGENTS.md 硬规则）；README 顶部版本与 npm 一致。

- **前置**：主人明确授权（本阶段禁止提交/推送/发版）。

### S10 · 安装器 `link:` 修复

## 八 · P0 诊断：「上下文压缩」长页面无法滚动

> 结论先说：**不是滚动条被藏了，是整棵子树里没有任何滚动容器**。容器 `overflow:hidden`，页面根 `overflow:visible` + `min-height:auto`，多出来的内容被裁掉。
> 本节所有数字为本机实测（等价复现环境），命令见 §八.8。

### 8.1 复现步骤

1. 打开 DSH GUI → 左侧「插件」列 → 点「上下文压缩」。
2. 页面显示到「参数」卡片中段即被裁断，继续向下滚纹丝不动。
3. 窗口越矮，被裁掉越多（`centerCol` 压到 400px 时，15 行参数只剩前 6 行可见）。

### 8.2 根因链（四段，每段有出处）

| # | 事实 | 出处 |
|---|---|---|
| 1 | 文档根定高、滚动交给宿主：`html,body,#root{height:100%;margin:0}` | `dsh-web-frontend/dist/assets/index-BPHePDI_.css` @75028 |
| 2 | 外壳定高 grid + `overflow:hidden`：`.BynINW_frame{grid-template-rows:100%;height:100%;display:grid;position:relative;overflow:hidden}` | `@deepseek-ai/dsh-client-ui-layout/lib/client.js` @3288 |
| 3 | 中央列是 **定高 flex 列 + `overflow:hidden`**：`.BynINW_centerCol{flex-direction:column;min-width:0;display:flex;overflow:hidden}` | 同文件 @4543 |
| 4 | slot outlet 的 wrapper 是 `display:contents`（**不生成盒子**）：`const ANCHOR_STYLE = { display: "contents" }` | `@deepseek-ai/dsh-client-ui-renderer/lib/client.js` @45200 |
| 5 | ⇒ 页面根 `div` 是 `centerCol` 的**直接 flex 子项**；而它没有 `height` / `min-height:0` / `overflow` | `lib/client.js:53`（`styles.page`）、`:193`（页面根渲染）、`:264`（`main` 槽注册） |

### 8.3 实测数值（1256×774 视口）

| 元素 | clientHeight | scrollHeight | overflow-y | min-height | 其它 |
|---|---:|---:|---|---|---|
| `centerCol` | **774** | **1447** | **hidden** | auto | flex / column / 宽 996 |
| 页面根 `div` | **1447** | 1447 | **visible** | **auto** | height 1399.36px · padding 24px 28px · max-width 980px |
| `document.scrollingElement` | 774 | 774 | — | — | 文档本身也不滚 |
| 可滚动祖先链 | — | — | — | — | **`[]`（一个都没有）** |

**内容高度构成（逐项可对账）**：`h1 32` + `p 19.19` + 卡① `143.56` + 卡② `103.97` + **「参数」卡 `940.05`（15×51.39）** + 按钮行 `35` + 配置来源行 `17.59` + 6×`gap 18` + `padding 48` = **1447.36** ✓

### 8.4 单一假设的最小验证（同页面 / 同视口 / 同手势）

| 变体 | 结构 | 结果 |
|---|---|---|
| **A 现状** | 页面根直接是 `centerCol` 子项 | 滚轮 900px → `scrollTop **0**` ❌；**脚本** `scrollTop=99999` 可达 **673** ⇒ 「程序可滚、用户不可滚」 |
| **B 单行修** | 页面根加 `height:100%;min-height:0;overflow-y:auto` | 滚轮 → `scrollTop **673**` ✅ |
| **C 官方双层** | 外层 `height:100%;min-height:0;overflow:hidden` + 内层 `flex:1;min-height:0;overflow:auto` | 滚轮 → `**673**` ✅；滚到底后最后一个控件可见 ✅ |
| **D 短视口** | 现状结构 + `centerCol=400px` | `scrollHeight 1447 / clientHeight 400`，滚轮 → `0` ❌（结论不依赖 774） |

**仪器校准**（先证明不是测试脚本不会滚）：120×120、`overflow:auto`、内容 1500px 的校准盒，同一 CDP 滚轮手势 → `scrollTop 400` ✅。
**已排除的弯路**：本运行时的 `page.mouse.wheel` 不产生滚动（校准盒也不动）；只有 CDP `Input.dispatchMouseEvent{type:"mouseWheel"}` 有效。

### 8.5 同类路径检查

- 全工作区搜 `name: "main"` 的槽位注册：**只有这一处**（`lib/client.js:264`）⇒ 不存在「同类页面批量中招」。
- 官方同槽页面（`@deepseek-ai/dsh-client-ui-schedule` 的 `TaskManagerPage`，同样注册进 `main`）写法是三层：
  `page{width:100%;height:100%;min-height:0;display:flex;overflow:hidden}` → `pageScroll{flex:1;min-height:0;overflow:auto;scrollbar-gutter:stable}` → `pageContent{max-width:960px;margin:0 auto;padding:0 clamp(24px,4vw,48px) 48px}`。
  本插件缺的正是前两层，且把 `maxWidth/padding` 放在了最外层（应放在内层内容容器上）。
- 项目内其余 `overflow` 只有装饰性进度条（`lib/client.js:62`，`height:6px;overflow:hidden`），无同类风险。

### 8.6 修复建议（M1，未实施）

> ⚠ **2026-10-29 22:1x 复验后修正**：M1 的首选形态是**页面根四属性**（`boxSizing:'border-box'` + `height:'100%'` + `minHeight:0` + `overflowY:'auto'`），见 **§14.2**；下面这套「三层拆分」保留为**对照形态**，不再作为首选（理由见 §14.2）。

`lib/client.js` 的 `styles.page` 拆三层，DOM 包两层：

```
page        { height:100%; min-height:0; display:flex; flex-direction:column; overflow:hidden; color:inherit }
pageScroll  { flex:1; min-height:0; overflow:auto; scrollbar-gutter:stable }
pageContent { max-width:980px; margin:0 auto; padding:24px 28px 48px; display:flex; flex-direction:column; gap:18px; min-width:0 }
```

禁止任何一处再自己写 `Boolean(deps[pkg])` 或 `existsSync(node_modules/pkg)` 这类字符串/存在性判定。

理由（可复跑）：同一缺陷在三个位置各有一份弱判定，实测三条都假绿 ——
`verify-install` 13/13 `[exit 0]`、`install` 连跑两次 `[exit 0]`、`doctor` `[exit 0]`，
而 `link:` 目标根本不存在。修一处不修另两处 = 缺陷仍然可达。

### 13.2 定稿：判据的四个层次（缺一不可）

| 层 | 判定 | 为什么必须有 |
|---|---|---|
| 1 | 依赖声明存在（`dependencies[pkg]`） | 原来只有这一层 |
| 2 | 规格是本地路径形态（`link:` / `file:`），否则按 registry 安装判 | 版本号 + 实装在 profile 内是**合法**的 npm 安装，不能一律判红 |
| 3 | 解析后的真实目录**存在**，且其 `package.json.name === pkg` | 目录在 ≠ 是对的那个包（实测用「冒牌包」夹具证明只看目录会放行） |
| 4 | `profile/node_modules/<pkg>` 的 **realpath 等于** 规格解析出的 realpath（registry 模式则要求实装在 profile 内） | 声明与实物必须一致；junction 指向别处时声明再对也没用 |

Windows 注意：第 3/4 层用 `realpath` 比较。**大小写差异不算错**（本机实测 `…/PKG-Src` 与 `…/pkg-src` 是同一目录，pnpm 也能链上）——
用字符串比较会造出**假 RED**，这跟假绿一样是缺陷。

### 13.4 定稿：安装器的语义（幂等 = 判真实身份，不是判存在）

| 状态 | 安装器行为 |
|---|---|
| `node_modules/<pkg>` 不存在 | 建 junction → 真实项目目录 |
| 是链接但**断链 / 指向别处** | **重建**（旧行为是「已存在，跳过」然后 ✓ 完成 —— 安装器自己的假绿） |
| 是链接且指向本目录 | 跳过链接 |

| 依赖声明存在但**解析不到本包**（不存在 / 包名不符 / 指向别处） | **改写**为正确值（先备份 `package.json.bak-before-gokifu-<ts>`） |
| 依赖声明已正确 | 不动（不产生新备份） |

这是 S10a 的硬约束：本次缺陷的源头就是「按包名猜目录」。
