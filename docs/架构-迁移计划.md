## 2. 为什么先门面、后搬文件

三条证据（都在代码里）：

1. **测试对源码文本有依赖**：`test/engine-harness.test.mjs:96-102` 读 `src/engine.mjs` 全文，把 4 个 `@deepseek-ai/*` 包名 `.replace()` 成 stub 再写 `src/.engine-under-test.mjs`；`test/persist-incremental.test.mjs:174-183` 同样手法生成 `-p3` 副本并**断言 patch 必须命中**（`:180`）。先搬文件 ⇒ 这两条先红，且报错指向 stub 路径，**无法区分是重构坏了还是夹具坏了**。
2. **测试按模块路径 import**：28 处 `import … from "../src/<mod>.mjs"`（本轮 grep）。先搬文件 = 同时改「实现位置」+「28 条 import」+「门面建立/删除」，三个变量一起动。
3. **本仓已有一条被验证的做法**：`test/graph-fixtures.mjs`（task-59）就是「生产 API 不动、测试层加门面」（其头注释 `:1-15` 自述：生产调用点 98 处不变）。房间化沿用同一套路：**先加门面/先抽函数，后改调用点，最后删旧路径**。

**推论（写进每一刀）**：A2 只允许「新增房间文件 + 在 engine/ui 内部换成调用」，A3 只允许「移动文件 + 留一行 re-export」。**具体动到落盘字节或 prompt 文本的代码，本计划一行都不搬**。
