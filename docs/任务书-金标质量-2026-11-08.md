## 2. K-26 金标规范补充（本轮执行口径）

以下条款是对 `docs/knowledge/K-26原子事实标注协议.md` 的执行补充；与协议冲突时以协议为准，协议未写清的以本节为准。

1. **样本坐标**：一律用 `manifest.samples` 的 **0-based index**；本轮只标 index 1–11，index 0 不重做。禁止用 1-based 口语编号写产物。
2. **事实来源**：一条原子事实 = 只传达一个可判真假短句；沿用 dossier 已冻结的候选事实，不重新抽取、不增删条数（见 §1.3）。
3. **状态映射**：`GOLD → supported`、`REJECTED → not-supported`、`PENDING → pending`；`supported` 必须给出逐字 `quote` 与同会话 `evidenceSeq`；`not-supported` 必须写清反证或缺口；`pending` 必须写清「缺哪条一手证据」。
4. **quote 规则**：`quote` 必须是**同一会话、同一声明 `evidenceSeq` 事件文本**里的连续子串（允许截断到 120 字符，不允许拼接、转述、改标点）；命中不了就不得标 `supported`。
5. **范围规则**：`supported` 的 `evidenceSeq` 必须落在该样本 `lastOfflineSummary.range = [start, end]` 内；超出范围的证据不得支持该摘要事实（只能 `not-supported` 或 `pending` 并说明）。
6. **时点规则（不可妥协）**：事实按**节点当时**状态判定；后续修改才成立 ⇒ 原节点 claim 判 `not-supported`；后续验证只有在「中间没有修正性修改」时才可作为同一事实的证据。多数票不能推翻硬失败或时点否决。
7. **主体规则**：只认 `user/message` / `assistant/message` / `tool/result` 的原始事件；`agent/inbox/spliced`、`session/title-llm-request`、`chess-ledger` 等 harness 复制品不得当作「用户原话」；harness 注入不得写成用户说的。
8. **不伪称人工标注**：`annotator` 必须写 `rule-gold:<member name>`；不得写 `human` / `人工`。人工抽查只作旁证，不阻塞本轮。
9. **三审结构**：标注员负责①规则引擎（机械校验）与②压缩模型（看原始片段复判）；T6 独立终审子代理负责③独立审 + 最终裁决。三审全过且时点规则通过才可 `RULE_GOLD`。
10. **must-keep**：37 条 must-keep 清单从 `labels.jsonl` 原样复制，禁止从摘要反推；`anchorCoverage` 只测锚点下界，同义覆盖另报，不混入主数。
