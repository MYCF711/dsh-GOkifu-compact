# 任务书：两条公理纠偏（事实可回证 + 关键证据可见）

> 版本：2026-11-07 · 执行方式：**Lead 照表派单，不再现场拆任务**
>
> 目标：修复 K-26「派生事实不可回证」与 K-2「成功工具结果不可见」两类已证实问题；不改变两条公理，不顺带做 UI、性能、发布链或大重构。

## 1. 最终交付与采纳条件

交付一条可评审的 `factGuard` 实验线：

```text
模型产出“事实候选 + 叙事及事实引用”
→ 冷代码校验 subject / quote / evidenceSeq / validAtSeq
→ 不合格事实拒绝，引用它的叙事一并拒绝或降级 UNVERIFIED
→ 成功工具结果提取短小、可回证的 valueFacts
→ online / offline / ledger 三条路径共用
→ K-26 / K-2 / K-27 分别验收
→ 达标才默认开启，未达标输出 NOT_ADOPTED
```

**默认状态**：开发期间 `factGuard:false`。不得在实验未通过时默认开启。

### 总采纳门槛（全部满足才允许 AX-15 开启）

1. K-26 冻结 12 份：已裁决 precision **≥95%**；must-keep **37/37 不下降**；主体混同、无源负向断言、过期“当前”、实参当返回值四类均有反例测试。
2. K-2：原有 4 题与新增成功结果题均无 baseline→candidate 退化；候选不得靠 UNKNOWN 增多换取“少错”。
3. K-27：正式 50/50 达到 compact Acc **≥90%**、Δtask **≥−5%**、perType 与 abstention 全绿。
4. 全量测试 0 failed、boundary 0、privacy changed confirmed=0/review=0。
5. 独立审核没有未解决的 P0/P1。

任何一项不满足：AX-15 以 `DONE / NOT_ADOPTED` 收尾，保留实验代码与证据，**不默认开启、不删失败样本、不回调阈值**。

## 2. 模型选择（Lead 不需要再选）

### 2.1 所有实现与审核子代理

```json

  "model": "group/deepseek-v4.1-flash-1017"
```

## 3. Lead 的固定工作流

### 3.1 工作树与集成

- Lead 在主仓库根目录先机械解析：`REPO="$(git rev-parse --show-toplevel)"`、`REPO_PARENT="$(dirname "$REPO")"`。
- 主仓库：变量 `<REPO>`（不写死个人绝对路径）。
- 集成分支：`task/axiom-integration`。
- 集成工作树：`<REPO_PARENT>/gokifu-axiom-integration`。
- 每个子代理独立 worktree：`<REPO_PARENT>/gokifu-axiom-<id小写>`。
- 每个任务分支：`task/axiom-<id小写>`。
- 第一波从 `HEAD` 创建；后续波次从**上一波已验收的 `task/axiom-integration` HEAD** 创建。
- 任务书本体可能尚未提交；子代理直接读 `<REPO>/docs/任务书-两条公理纠偏-2026-11-07.md`。

创建集成工作树（只执行一次）：

```bash
git worktree add ../gokifu-axiom-integration -b task/axiom-integration HEAD
```

创建子任务工作树的统一形状（替换 `<id>` 为如 `ax01`）：

```bash
git worktree add ../gokifu-axiom-<id> -b task/axiom-<id> task/axiom-integration
```

### 3.2 派单调用模板

```text
subagent({
  description: "<AX-ID 短标题>",
  provider: "magpie",
  model: "group/deepseek-v4.1-flash-1017",
  cwd: "<REPO_PARENT>/gokifu-axiom-<id小写>",
  prompt: "阅读 <REPO>/docs/任务书-两条公理纠偏-2026-11-07.md，只执行 <AX-ID>。严格遵守该任务的可写路径、验收、产出和禁止项；不要合并、不要推远端、不要改其它任务文件。完成后用 send_message 向 lead 报告 rev、测试命令/退出码、产出路径、未验项。"
})
```

### 3.3 每一波的固定验收与合并

1. 子代理返回后，Lead 打开产出文件，**亲自重跑该任务测试**，不转述汇报。
2. 只合指定分支：`git merge --no-ff task/axiom-<id>`；禁止 `git add -A`、禁止强推。
3. 每波全部合入后，在集成工作树串行执行：
   `node test/run.mjs`、`node scripts/boundary-audit.mjs`、`node scripts/privacy-audit.mjs --changed`。
4. 全绿才创建下一波 worktree；红则留在对应任务分支修，不进入下一波。
5. 子代理测试可在各自 worktree 并行；全量测试只能在集成工作树串行跑。
6. 运行中不重启 DSH、不写 `profiles/*/cordis.patch.yml`、不碰 live home；真实数据只读复制到 `tmp/`。
7. 每波结束更新 `docs/派单表.md` 状态与证据；外部 push/PR/npm/Release 均不在本任务书授权范围内。

## 4. 精确 DAG：完成谁，立即启动谁

### 4.1 依赖总表

| 波次 | 可并行任务 | 前置必须完成 | 这波完成后立即解锁 |
|---|---|---|---|
| W0 | **AX-00（Lead）** | 路由检查通过 | AX-01、AX-02、AX-03 |
| W1 | **AX-01 + AX-02 + AX-03** | AX-00 | AX-04←AX-02；AX-05←AX-01 |
| W2 | **AX-04 + AX-05** | 各自前置完成并合入 | AX-06、AX-07、AX-08（需 W2 全绿） |

| W4 | **AX-09 + AX-10** | W3 全绿 | AX-11←AX-10 |
| W5 | **AX-11（单独）** | AX-10 | AX-12 |
| W6 | **AX-12（真实 reader，单独）** | AX-03、AX-09、AX-10、AX-11 | AX-13 |
| W7 | **AX-13（真实 reader，单独）** | AX-09、AX-10、AX-12 | AX-14 |

### 4.2 同波启动规则

- 同一行的任务必须在**同一 assistant 消息里**发出多个 `subagent` 调用。
- 不串行等待一个返回后再派同波下一个。
- 派完继续审核上一波证据、准备集成，不 `wait/poll`；运行时会通知完成。
- 任何任务失败只阻塞它的直接下游；无依赖任务照常推进。
- AX-11/12/13 是有真实模型费用的验收，必须按表串行，不为了“多并行”同时打网关。
