## 1. OWASP：日志和错误信息怎样脱敏

### 1.1 核心事实（已核实）

1. **不要直接记录 session 与凭据。** OWASP Logging Cheat Sheet 的「Data to exclude」列出 `Session identification values`、`Access tokens`、敏感个人数据/部分 PII、认证口令、数据库连接串、加密密钥等；通常应删除、遮蔽、清理、哈希或加密，而不是原样写入日志。对 session id，原文特别给出「如确需按会话关联，可考虑哈希值」。
2. **路径和内部网络信息不是无条件公开。** 同一节把 `File paths`、内部网络名称/地址、非敏感个人数据（姓名、电话、邮箱）列为记录前可能需要特殊处理的数据。
3. **关联标识不都等于 session 凭据。** 「Event attributes」建议记录 `Interaction identifier` 来关联同一次用户交互。故不能把一切 `requestId`/`runId`/UUID 都机械等同于 session id；但真正的 session identification value 又不能因为它出现在事件属性示例里就原样放行。
4. **错误详情与对外错误响应分层。** OWASP Error Handling Cheat Sheet 的 Objective 是：意外错误向用户返回通用响应，详细错误留在服务端供调查；其示例说明错误消息可暴露技术栈、SQL 信息和安装路径。
5. **清理还包括日志注入面。** Logging Cheat Sheet 的 Event collection 要求对所有事件数据处理 CR、LF、分隔符，并按输出格式编码。这与隐私脱敏是两个不同目标，不能拿「已转义换行」证明「已去隐私」。
6. **日志功能本身要进入测试与代码审查。** Verification 明确要求把日志机制纳入 code review、application testing 和 security verification。

### 1.2 对永久隐私门的最小规则（规则建议，待实现）

| id | 扫描对象 | 应判 `confirmed` 的命中 | 不能直接判 `confirmed` 的命中 |
|---|---|---|---|
| **P1-SECRET** | 发布文本中的键值、HTTP 头、PEM、连接串 | 非空 access token/API key/Bearer 凭据、私钥、认证口令；明确 `sessionId`/`session_id`/cookie session 的真实值；来自真实会话材料且未登记的 session 标识 | 单独的单词 `token`、`session`；`<redacted>` 等无值占位；普通 correlation/request/run id |
| **P2-PERSONAL** | 日志、错误摘录、docs/evidence 中的个人数据 | 真实敏感个人数据；与真实运行记录绑定的直接标识 | 邮箱/姓名正则本身；`example.com` 地址；明确登记的公开项目联系方式 |
| **P3-PATH** | 文件路径、stack trace、错误响应 | 真实用户 home、带用户名的 profile 路径、私有工作区/checkout 绝对路径；包含这些内容的错误堆栈 | 相对 import、URL 路由、Unix 系统默认工具路径、仅有代码行号而没有私有路径的文本 |
| **P4-RUNTIME-ID** | session/run/request/interaction id 及其上下文 | 能访问非公开会话、或能把发布材料联接到真实用户/真实会话内容的标识；语义不明时在发布门按未豁免命中阻断 | 仅用于关联日志且不授予访问权、不联接非公开数据的 interaction/correlation id |
| **P5-ERROR** | 公开文档中的错误响应与堆栈 | 含 P1–P4 内容的错误详情 | 通用错误码、通用重试提示、不含敏感值的公开官方错误形状 |

实现时必须遵守三条：

- **匹配词不等于事实。** P2/P4 很多命中只能先叫 `review`；发布时 `review` 仍未豁免则失败，但报告不得把「疑似」伪写成「确认泄露」。
- **报告不二次泄密。** 输出 `ruleId + path + line + classification` 即可，不打印完整 token、cookie、session id、个人数据或私有路径；不要用整条原文做错误消息。
- **默认不改写。** 隐私门只检测并给退出码，不在扫描过程中自动替换发布文件。确需清理时另开一刀、单独复验。

## 2. npm `files` / `pack`：白名单之后仍要复核真实发布物

### 2.1 核心事实（已核实）

1. `files` 是可选的**反向 gitignore 风格**数组：列出的文件、目录、glob 会进入 tarball；省略时默认 `["*"]`。
2. 根目录 `.npmignore` **不能覆盖** `files` 字段；子目录中的 `.npmignore` 可以。没有 `.npmignore` 而有 `.gitignore` 时，后者会被采用。因此「git 已忽略」不是 npm 发布隐私门。
3. 无论 `files` 如何配置，`package.json`、`README`、`LICENSE`/`LICENCE`、`main` 指向文件、`bin` 指向文件都会包含；README/LICENSE 可为任意大小写和扩展名。
4. npm 有默认忽略清单，但原文同时说明其中多数仍可通过 `files` 显式纳入；`.git`、`.npmrc`、`node_modules` 和若干 lockfile 等例外不能纳入。默认忽略清单不是内容脱敏器。
5. 无参数 `npm pack` 处理当前 package folder；正常模式会写 `<name>-<version>.tgz`。本轮用本机 npm **11.19.0** 实际执行 `npm pack --dry-run --json`，确认当前仓库可以用 JSON 取得发布文件清单，且 dry-run 没有生成该 tarball。

### 2.2 本工作树实测（已核实，2026-11-06，写本文前基线）

当前 `package.json` 的 `files` 包含 `src`、`lib`、`docs`、`evidence`、`scripts` 等，并含 `main: src/ui.mjs` 与 `bin: scripts/cli.mjs`。所以：

- **不能只扫 `src`。** README、`docs/**`、`evidence/**`、`scripts/**`、强制包含的 main/bin 都在发布面。
- **本文也会进包。** 写完后的最终 pack 验证必须看到 `docs/knowledge/发布脱敏与日志清理-外部资料.md`，而不是把它当作仓外研究笔记。
- `test/`、`tmp/` 当前不在 `files` 白名单中，但仍需每次以 packlist 实测，不能凭这一句话永久假设为零。

### 2.3 对永久隐私门的最小规则（规则建议，待实现）

1. **packlist 是唯一发布面来源。** 在仓库根执行 `npm pack --dry-run --json`，检查子进程退出码并解析 JSON；失败、空清单、JSON 不可解析都直接门红。不要以 `git ls-files`、手抄目录或 `.gitignore` 代替。
2. **逐文件扫描。** 对 packlist 的每个条目扫路径名与文本内容，至少覆盖 P1–P5；必须包含 README、package metadata、main/bin。不可读文件、未知二进制、解码失败不得静默跳过。
3. **结构断言。** 每次断言 `test/`、`tmp/`、`.harness-stubs`、`.engine-under-test*` 为 0，并断言强制包含文件确实在清单中；另将实际清单与既有 pack 基线/出处检查并列运行。
4. **发布前判分。** `confirmed` 或未处置 `review` 必须退出非零；只有精确、带理由的公开合成豁免可通过。把脚本接入既有 `gate.mjs` 的 judged gates 与发布预演，而不是只放一条人手可忘的 advisory。
5. **当前仓可先用 dry-run 清单 + 工作树字节。** 当前 `package.json` 没有 `prepack`/`prepare` 脚本。若以后增加会生成发布内容的生命周期脚本，需升级为「在受控临时目录实际 pack 并扫 tarball 内字节」，不能继续假定工作树字节等于最终包字节。

## 3. 运行标识何时敏感，何时只是公开合成示例

### 3.1 已核实的外部边界

- `localhost` 及其子域具有回环语义；RFC 6761 也把 `127.0.0.1` 作为 IPv4 local host 示例。这个语义是公开、固定的，不包含某个用户的身份。
- RFC 2606/6761 保留 `.test`、`.example`、`.invalid`、`.localhost` 以及 `example.com`、`example.net`、`example.org` 等名称；example domains 的用途是文档示例。
- RFC 5737 保留 `192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24` 供文档使用，并明确写出 **These blocks are not for local use**。
- 上述 RFC 只为名称/地址提供保留语义，**没有**给任意 session/run UUID 发「合成且安全」证书。合成运行标识必须由本仓 fixture/allowlist 证明来源。

### 3.2 本仓分类表（规则建议；仓内样本覆盖待核实）

| 命中形状 | 分类与门禁动作 | 边界 |
|---|---|---|
| 真实会话材料中的 session id、指向真实 `sessions/<id>` 材料的标识 | `confirmed`，阻断 | 即使它「只是 UUID」也不能因形状放行 |
| 明确 fixture 中的合成 session id | 仅在 `(path, ruleId, literal)` 精确登记且有理由时按 `public-synthetic` 放行 | 不用整文件/整目录豁免；同一值出现在别处重新判 |
| request/run/interaction id | 默认 `review`；证明只用于关联且不联接非公开数据后可登记放行 | 若实际等价 session/access id，则升级为 P1/P4 `confirmed` |
| `localhost`、`127.0.0.1` 作为 URL host 或监听/连接默认值 | host 本身不是隐私命中；继续扫同一字符串的 userinfo、query、path 与其他字段 | 不得把带 token 的完整 URL 因 host 是回环而整体豁免 |
| `example.com/net/org`、`.example`、`.test` 中的示例 | 在文档/fixture 的精确上下文中可判 `public-synthetic` | example 名下的 userinfo/query 仍需扫；不是任意相似域名都保留 |
| 三段 RFC 5737 TEST-NET 地址 | 文档示例可判 `public-synthetic` | 不用来替换可执行回环默认值；RFC 明确不是 local use |
| 公开声明的项目联系方式 | 仅精确登记后按 `public-declared` 放行 | 不把所有邮箱、GitHub noreply 或作者字段自动视为非个人数据 |

**关键区别：**「公开保留值」由 RFC/官方默认值证明；「合成测试值」由本仓可审计 fixture 证明；「看起来像假的」不是证明。

## 4. 不能机械替换可执行默认值的边界（已核实事实 + 规则建议）

1. **不能把 `127.0.0.1`/`localhost` 换成 TEST-NET 或 `example.com`。** 前者是回环，后者分别是文档地址与可正常解析的 example 名；替换会改变连接目标或使服务失效。
2. **不能把 URL 路径当成本机文件路径清理。** 例如 API route、exports 子路径、相对 import 是程序契约；只有真实文件系统路径命中 P3 才处理。
3. **不能清理 shebang/系统默认工具路径。** 例如 npm bin 文件的 Unix shebang 是可执行语义，不是用户 home 泄露。
4. **不能把 OWASP「日志中不要记录源代码」理解成「npm 包不能含源代码」。** 本任务扫描的是发布物中的敏感内容和日志/错误摘录；有意发布的源码仍是正常产品内容。
5. **不能只做全局字符串替换。** 同一标识在密钥字段、URL host、文档保留名、fixture、真实会话路径中的语义不同；必须按字段和上下文分类，并对可执行文件跑原有测试。
6. **不能用哈希当作万能公开化。** OWASP 对 session id 是「确需关联时可考虑哈希」，但哈希仍可保持稳定联接性；发布材料若不需要关联，删除/改用明确合成值更直接。此句是规则建议，不是 OWASP 的逐字要求。
7. **豁免不能掩盖其余内容。** 回环 host、example domain 或公开作者字段只豁免对应命中，不豁免同一行/同一 URL 中的 token、私有路径和个人数据。
