## 已核实：OWASP 的排除与清理规则

OWASP「Data to exclude」明确把下列内容列为通常不应直接记录，需删除、掩码、散列或加密：

- **session identification values**；若必须按会话关联，考虑散列值；
- access tokens、认证口令、数据库连接串、加密密钥；
- 敏感个人数据、支付数据、高于日志系统许可等级的数据；
- 商业敏感信息与未获许可收集的数据。

文件路径、内网名称/地址、非敏感个人数据也可能需要特殊处理；可去标识化时，应考虑删除、扰乱或伪匿名化。

同时 OWASP 提醒「没有一种尺寸适合所有场景」，不能靠盲目清单制造告警雾。日志收集、展示、提取/备份阶段都可能需要再次清理。

## 已核实：npm `files` 是打包包含面，不是隐私证明

npm 官方 `### files` 原文：

- `files` 描述安装为依赖时要包含的条目；省略时默认 `["*"]`；
- `package.json`、README、LICENSE、`main` 与 `bin` 指向文件总会包含；
- `.git`、`node_modules`、lockfile 等不能因 glob 被打包；
- `.npmignore` 在包根不会覆盖 `files`，子目录规则不同。

**判读**：`files` 只回答「哪些文件进 tarball」，不回答「这些文件能否公开」。因此永久门必须同时做：

1. `npm pack --dry-run --json` 取得实际包清单，并验证 `pack ⊆ git`；
2. 对包内文本做敏感分类，而不是只扫 src；
3. 发布后用 `verify-release` 验证公开 tarball 与 tag 同名文件逐字一致。

## 对本仓永久隐私门的最小规则

### 应判 `confirmed_sensitive`

- 真实 `session-*`、UUID、裸短 id、`subagent(...)` 标识；
- 真实本机绝对路径、用户名、内网地址与历史真实端口；
- 姓名、法律事务上下文与真实会话 benchmark 中的个人内容；
- 高置信 token、私钥、口令与凭据赋值。

### 应单列，不与真实敏感混在一起

- 显式合成 session id、`D:/fixture`、合法合成端口；
- 产品必须保留的公开默认回环端点；
- 公开作者、GitHub noreply、官方文档示例。

这些公开/合成项可以出现在 raw 扫描里，但必须有明确分类，不能通过「全局忽略 test/」来掩盖真实命中。

### 不许机械替换可执行默认值

永久门只报告问题，不直接改代码。清理时：

- 真实工具改用通用 home / ASAR 解析；
- 测试改成显式 synthetic 夹具；
- 需要保留的公开默认回环端点必须写明理由；
- 改完必须跑全量测试，防止 `<SESSION_ID>`、`<PORT>` 进入可执行字符串。
