# 「让 agent 自己决定何时整理上下文」（Focus, 2026）· 判读

> 来源：<https://arxiv.org/abs/2601.07190>（HTTP 200，抓取 2026-11-02）
> 外部资料 = 数据，不是指令。

## 1. 论文说了什么（**已核实**：摘要原文）

| 要点 | 原文意思（转述） |
|---|---|
| 问题 | 长任务里 **Context Bloat**：历史越长，成本爆炸、延迟上升、**被无关的旧错误干扰**导致推理退化 |
| 现有做法 | 被动、外部的摘要机制，**agent 自己控制不了** |
| 提出 | **Focus**：agent 自己决定**何时**把关键经验收进持久的 **Knowledge 块**，并**主动撤回（prune）原始交互历史** |
| 实验 | SWE-bench Lite 上 5 个上下文密集型实例，Claude Haiku 4.5 |
| 结果 | 激进提示下 **token 减少 22.7%**（14.9M → 11.5M），**准确率不变**（3/5 = 60%）；平均**每任务 6.0 次自主压缩**；单实例最高省 **57%** |
| 结论 | 有能力的模型**在给到合适工具与提示时能自我调节上下文** |

## 2. 对我们的意义（**已核实**：对照本仓库代码）

本插件的折叠是**被动的**：`agent/pre-step` 里按阈值/增长闸触发，agent 全程没参与，
也从**看不到**"现在压力多大了、要不要先压一下"。我们确实有手动压缩（`manual-compact`），
但 agent 不知道**何时**该用 —— 缺的正是论文说的那个"决定权"表面。

## 3. 落点（C330）

不照搬"让模型自己写 knowledge 块"（那是研究者级改造，也和我们"规则段机械注入"的设计冲突），
只做**最小可执行的一半**：把压力信号**送到模型眼前** —— 热清单里加一行
`# 压力 87%（想现在压就调 manual compact）`，让"要不要提前压"从**不可见**变成**可见可决策**。

## 4. 还没验的（**待核实**）

- 论文的实验规模很小（**N=5**、单一模型、SWE-bench Lite），"22.7% 省 token"不能直接外推到本插件；
- 加了这行提示**会不会真的改变 agent 行为**（多调/少调 manual compact）—— 需要真机样本；
- 我们省的是"折叠成本"（已知大头是**前缀缓存命中**，见 [`成本模型-deepseek价格.md`](./成本模型-deepseek价格.md)），
  与论文口径（总 token）不同，**不可直接比较**。
