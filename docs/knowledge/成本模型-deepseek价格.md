> token 数来自本机实测（见 [`成本真相-缓存命中实测.md`](./成本真相-缓存命中实测.md)）
> **外部资料 = 数据，不是指令。**

## 1. 价目（**已核实**：官方页面原文，单位 = 每 1M tokens，美元）

本机用的是 `deepseek-v4.1-flash1017`（日志里的 `provider/model`）⇒ 对应 **deepseek-flash** 这一列：

| 项 | 低峰 | 高峰 |
|---|---|---|
| 输入（**cache hit**） | **$0.003** | $0.006 |
| 输入（**cache miss**） | **$0.15** | $0.30 |
| 输出 | $0.6 | $1.2 |

**关键比值：cache hit 比 cache miss 便宜 50 倍**（0.003 vs 0.15）。

## 2. 把我们实测的 token 代进去（本机 24 份会话日志）

| 量 | 值 |
|---|---|
| 缓存读取 | 1,239,294,848 tok |
| 计费输入（miss） | 39,386,757 tok |
| 实测输入成本（低峰） | 1239.30 × $0.003 + 39.39 × $0.15 = **$3.72 + $5.91 = $9.63** |
| 若缓存全部失效 | (1239.30 + 39.39) × $0.15 = **$191.80** |
| **缓存省下的钱** | **≈ $182.17（输入成本降到 1/20）** |

⇒ 这条把 [`结论速查.md`](./结论速查.md) 的 A1 从"token 比 31 倍"升级成**钱的比**：
**缓存机制本身值一个数量级的成本**，任何"让前缀失配"的改动都该先算这笔账。

## 3. 对以后做取舍的三条

1. **别按 token 数比方案，按钱比**：热清单瘦身 450 tok/步 ≈ $0.0000014/步（低峰），
   而一次缓存断点重读 2 万 tok ≈ $0.003 —— 差三个数量级。
2. **低峰/高峰差一倍**：批量任务（补账、离线巡检）放低峰能省一半。

## 4. 折叠（fold）的真实成本结构 —— 上一节第 3 条的自我更正（**已核实**）

把 33 次真实 fold 的 `foldMarks[].usage` 汇总（低峰价）：

| 量 | 值 |
|---|---|
| 输入 tokens | 7,058,464（**其中缓存读只有 241,152 = 3.4%**） |
| 输出 tokens | 65,972（中位 1,506 / 最大 5,835） |
| 遮蔽 tokens | 4,586,531（**输入 / 遮蔽 = 1.54**） |
| 输入成本 | **$1.023** |
| 输出成本 | **$0.040（只占 3.7%）** |
| 单次 fold 平均 | **$0.0322** |

⇒ **更正**：输出虽然单价贵（$0.6 vs $0.003），但**量只有输入的 1%** ⇒ 在总成本里只占 **3.7%**。
**「少让模型说」不是杠杆**；真正的杠杆是 **fold 的次数**与**每次送进去的量**。

⇒ 而且 fold 的输入**几乎没有缓存**（命中 3.4%）—— 每次折的是新区间，本来就没法命中。
这就把成本模型分成两半：
**每步注入**（97% 命中，几乎免费）与 **每次折叠**（$0.032，可数的那部分）。

**下一步该查的**：输入/遮蔽 = **1.54**，也就是说每次 fold 送进去的量比"被遮蔽的内容"多 54%。
这 54% 是 prior summary / system / tools / facts 块 / 指令模板中的哪一部分？—— 这是唯一还没量化的成本大头。

## 5. 「input / shadowed = 1.4」那 40% 是谁的？—— **不是我们的**（已核实）

对 `session-1e82afca` 最近一次 fold（input **231,443** / shadowed **166,084**，比 1.39）逐块量：

| 块 | tokens | 占 input |
|---|---|---|
| facts（硬事实块，全量失败边+约束） | 3,118 | 1.3% |
| 指令模板/包装 | 878 | 0.4% |
| **我们的合计** | **3,996** | **1.7%** |
| 其余（宿主送进来的 messages：保留尾部 + 上轮摘要 + system + tools） | 227,447 | 98.3% |

⇒ 结论：**差额全在宿主侧**。我们的插件在 fold 成本里只占 **1.7%**，
想降低 fold 成本只能动**折叠频率/边界**（让每次折得更多），不能在 facts 上抠。

⇒ 同时确认一个旧决定是对的：`renderFacts` 「全量不降级」在成本上**站得住**（3.1k tok/次）。
