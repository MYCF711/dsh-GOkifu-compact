# 长期记忆反哺压缩：来源、绑定与防过拟合

> 日期：2026-11-09 · 性质：已读原始会话与项目产物的内部判读，不是外部网页结论。
> 来源：`长期记忆系统` 工作区的目标原始多帧会话（会话指纹 `8cc34e32…`），以及该工作区的方案、职责边界、合流契约与实测报告。
> 本文只反哺 `GOkifu-compact` 的压缩职责，不把长期记忆、跨会话检索、RAG 或工具治理搬进来。

## 1. 一句话结论

**压缩要保留“可判定的关系”，不是保留更多词；长期记忆能提供防过拟合与证据分层的经验，但不能替代本会话的原始事件。**

## 2. 可以直接吸收的原则

### 2.1 原始事件优先，摘要不能自证

长期记忆的边界文档明确禁止从压缩摘要再抽取记忆：摘要已是生成物，再次抽取会累积误差。

对压缩的对应要求：

- 原子事实、值、失败原因都必须能回到本次会话的原始事件；
- fold / checkpoint / ledger 里的复制品不能反过来证明原始事实；
- 不能用后文修正或后续成功结果，给较早节点补写“当时已成功”；
- 生成器可以压缩展示，但不能把摘要当作第二轮事实来源。

这与 K-26 的范围、主体、时点、quote、claim 五类审计一致：quote 逐字命中只是必要条件，不能证明 claim。

### 2.2 保“实体 → 最新值”的绑定，不只保 token

长期记忆的合流经验与 K-27 的 KU-01 实证指向同一件事：

- `later-ok` 仍在 compact 中，不代表模型能回答“哪个实体的最新结果”；
- 若 `e-ku01-a` 与 `later-ok` 分处两行，且 `seq=303` 没有实体回指，模型必须猜绑定；
- `retained` 等状态词若未标为状态而非值，会与真实答案竞争；
- 因此 `answerPresentCoverage` 只是 token 覆盖，不是关系覆盖，更不是任务通过率。

**可执行候选**：为值型事实建立“主体 + 证据 seq + 当前值/旧值 + 状态”关系行；被折叠前的 latest 状态必须有回指，状态词不得冒充结果值。先以 KU-01/KU-03 做离线关系覆盖和真实 reader 对照，未达到预注册门槛不启用。

### 2.3 去重不等于合流，合流不等于删源

长期记忆的合流契约要求同作用域、同 kind、同 preconditions、同 validity，且至少两个独立机械口径命中；冲突、反例、不同适用条件一律不合。

对压缩的限制：

- 同一句“超时/失败/已完成”不必然是同一事件；
- 版本号、exit code、路径、主体、时间范围本身可能就是语义，不能当易变噪声抹掉；
- 相同 token 不表示同一事实，失败与恢复必须保留时间顺序；
- 可以做派生视图，但原始节点、失败边、证据链必须可回溯；
- 冲突事实不能靠“选一个更像的”消除，必须并列标出冲突或按发生时间明确新旧。

### 2.4 覆盖、严格命中、可读性、实际收益必须分开

长期记忆报告把“覆盖了源局”与“卡片是否真正给出相关原文”分开；曾出现覆盖 19/19、严格命中 16/19，改渲染后卡片可读性提高但严格口径不提高的情况。

对压缩评测的映射：

1. **coverage**：所需证据是否仍存在于图/上下文；
2. **relation coverage**：证据是否与正确主体、时点、值绑定；
3. **reader outcome**：模型是否答对，不用字符串在场替代；
4. **avoided failure**：是否真的少踩坑，而不是“看起来相关”；
5. **成本/预算**：省 token 是否与上述指标同时成立。

任一层变好都不能用来宣称另一层也变好。K-26 precision、K-2/K-27 真实 reader、格式归一化和 token 节省必须分别报告。

### 2.5 防止“泛相关”比多召回更重要

长期记忆实测中，泛工具词起跳导致大量低相关命中；收窄起跳条件虽提高相关性，却增加零注入。这个代价必须如实保留。

对压缩热清单的映射：

- 不因为某条事实“项目相关”就放入当前热清单；
- 失败边按任务、主体、时点和可操作性保留，不按词频堆砌；
- 省略必须显式给出数量与回证指针；
- 没足够相关证据时宁可省略/零注入，不拿泛相关填满预算；
- 预算不足不能以静默截断约束或值事实来“通过”。

### 2.6 时间、来源与反例是保真的一部分

长期记忆把 `occurredAt` 与 `recordedAt` 分开，并保留反例与失效状态。

对压缩的对应要求：

- “何时发生”与“何时被压缩/记录”不能混用；
- 新 fold 不能消除旧 fold 的失败证据；
- 历史 foldMark 的质量分是修前证据，不能为了门禁清零而回写；
- 后续恢复可以说明“后来恢复”，不能把原来的失败改成成功；
- 对未证实结论保留 UNRESOLVED/PENDING，不把缺证算 GOLD。

## 3. 明确不吸收的方向

以下是长期记忆系统的职责或设想，不能直接塞进压缩：

- 跨会话召回、巨型棋谱、个人画像、长期知识库；
- 让向量相似度或模型主观“重要性”替代原始证据；
- 把成功经验当成无条件可执行的定式；
- 用多个模型投票掩盖缺证或语义冲突；
- 从摘要二次蒸馏摘要，形成自证循环；
- 把记忆文本当作 LoRA、权重记忆或 AGI 记忆已实现的证据。

## 4. 对当前代码/实验的具体反哺

| 优先级 | 候选 | 验证方式 | 通过边界 |
|---|---|---|---|
| P0 | KU 型“主体—最新值”关系行，带 seq 与状态 | KU-01/KU-03 离线绑定检查 + 冻结 reader 对照 | 不靠 alias/改答案/任意样本答对；不默认开启 |
| P0 | 保留冲突、恢复与时间顺序 | 失败→恢复→再失败的 fold 夹具 | 后续恢复不改写原失败；主体与时点可回证 |
| P1 | 将 token coverage 与 relation coverage 分列 | K-2/K-27 报告中增加关系覆盖列 | 不用 answerPresent 冒充任务分数 |
| P1 | 失败/约束/值事实的省略均给回证 | 省略行识别与抹指针反例 | 缺指针即红；普通文本不误判 |
| P1 | 以真实任务避免重复失败为最终验收 | 冻结配对任务，full/compact 对照 | 不只看“摘要更短/相关度更高”；负迁移如实保留 |
