## 已核实

### 1. 评测链：从摘要出问，再从源文作答

QAFactEval 属于 QA-based factual consistency metric。官方 §3.2 把链路拆成四个基本组件，另加问题过滤与可答性处理：

```text
摘要
  → ① Answer Selection：选出待核查的答案/信息单元
  → ② Question Generation：以“所选答案 + 摘要上下文”生成问题
  → ③ Question Answering：让 QA 模型根据输入源文回答问题
  → ④ Answer Overlap：比较“摘要中所选答案”与“QA 模型根据源文给出的答案”
  → ⑤ 过滤与不可答处理
  → ⑥ 对过滤后剩余问题的分数取平均
```

关键细节：

1. **Answer Selection**：原文比较 NER、NP Chunks、Max NP 与 All。它先从摘要选择信息单元，不是先把源文全部信息列完。
2. **Question Generation**：问题同时受所选答案与摘要上下文约束；QG 噪声会让后续 QA 失败，即使摘要本身事实一致。
3. **Question Answering**：QA 的上下文是输入源文。原文比较抽取式与生成式 QA；抽取式回答给出源文片段，生成式回答逐 token 生成。
4. **Answer Overlap**：比较最初所选答案与 QA 输出。原文考察 EM、word F1、LERC 等；LERC 是以问题和上下文为条件的学习型答案重叠评分，不是简单字符串相等。
5. **IsAnsweredSumm Filter**：用摘要自身判断生成的问题是否可答；不可答的问题被过滤，用于降低 QG 噪声与摘要不流畅带来的干扰。
6. **IsAnsweredInput / Answerability Penalty**：若问题不能用输入源文回答，则将答案重叠分记为 0；否则使用正常重叠分。
7. **聚合**：最终分数是问题过滤后剩余问题的平均分。原文本次可读段落未说明“过滤后 0 个问题”应如何处理，本仓候选必须把它单列为不可评分，不能默认记满分。

官方 Table 2 可见的最佳组件组合为：

| 组件 | QAFactEval 组合 |
|---|---|
| Answer Selection | NP Chunks |
| Question Generation | BART-large (QA2D) |
| Question Answering | Electra-large |
| Answer Overlap | LERC (QuIP) |
| Filtering / Answerability | 两者都用 |

这是论文在其实验设置下的组合，不是本仓已安装、已跑通或已校准的依赖清单。

### 2. 它测什么

- 测的是**摘要相对于指定输入源文的事实一致性**：摘要里被选中的信息单元，能否与根据源文得到的回答形成足够重叠。
- 每个问题保留“摘要答案—问题—源文回答—重叠分”的中间结构，因此比只给一个整篇总分更容易定位是哪一类信息不一致。
- 论文摘要声称，QG 与 answerability classification 的选择对性能尤其关键；QAFactEval 在 SummaC factual consistency benchmark 上相对此前 QA-based 指标取得 **14% average improvement**，并超过其最佳 entailment-based 对照。该说法是论文实验结果，未在本仓复跑，也不能改写成本仓收益或百分点承诺。
- 论文还报告 QA 与 NLI 信号可以互补，并构造了学习式组合指标 QAFactEval-NLI；这需要额外训练，不能当成零成本即用品。

### 3. 它不测什么，以及不能怎样解释

1. **不测源文覆盖/事实召回**。问题从摘要生成；源文里重要但摘要漏掉的内容不会自动成为问题。官方 §3.4 对 QuestEval 的讨论也明确指出，从源文生成问题会混入 relevance；QAFactEval 选择的方向更聚焦 factual consistency。
2. **不测脱离来源的客观真理**。它只问“与输入源文是否一致”；源文自身错误、过时或互相冲突时，高分不等于现实为真。
3. **不保证覆盖摘要中的每条事实**。答案选择、QG 与过滤都可能漏掉候选；所以平均分不能证明整篇摘要毫无遗漏或毫无幻觉。
4. **不把“源文不可答”证明为“源文已反驳”**。Answerability Penalty 将不可答记 0，但不可答也可能来自 QA 能力、问题噪声、证据截断或来源缺失；诊断记录必须区分 `not-found` 与 `contradicted`。
5. **不测流畅性、结构完整、压缩率、约束逐字保留、失败边覆盖或截断**。这些要由本仓既有机械指标与单独检查报告。
6. **不是确定性的字符串校验**。QG、QA、LERC 都引入模型误差；英文新闻摘要上的结果不能直接外推到中文工程会话、命令、路径、退出码与失败边。
7. **不能直接搬 SummaC 阈值**。官方 §4.2 说明二分类阈值按各指标在 SummaC 验证集上确定；该阈值不是本仓归档分布的校准结果。

### 4. 与 FActScore 的差异

| 维度 | QAFactEval | FActScore |
|---|---|---|
| 基本单元 | 摘要中选出的 answer / 信息单元及生成问题 | 从生成文本拆出的原子事实 |
| 核心问题 | “根据源文作答，与摘要所选答案是否重叠？” | “这条原子事实是否被指定可靠知识源支持？” |
| 典型链路 | 答案选择 → QG → 源文 QA → 答案重叠 → 过滤/不可答处理 → 平均 | 原子事实拆分 → 逐条 Supported / Not-supported 等判定 → 支持比例 |
| 分数含义 | 过滤后问题的答案重叠平均分，含不可答惩罚语义 | 被知识源支持的原子事实比例，即 factual precision |
| 诊断形态 | 问题级答案对、过滤与可答性状态 | 原子事实级支持标签与知识源证据 |
| 主要盲区 | 摘要未提及的源文事实不进入问题；选择与过滤还会漏候选 | 只测精确率，漏答、少说与拒答不能靠精确率本身发现 |
| 自动化误差面 | QG、QA、答案重叠/可答性分类的复合误差 | 原子事实拆分、检索与支持判断的复合误差 |

结论不是二选一：

- QAFactEval 更适合提供**问题级、可逐题检查的摘要—源文答案对照**。
- FActScore 更适合提供**原子事实级支持比例**。
- 两者都不能替代覆盖、拒答/空摘要、截断与结构指标；对本仓可互补，不可把任一分数命名为完整“摘要质量”。

### 5. 论文实验的适用边界

- 官方 §4.1 的 SummaC 是六个数据集上的二分类事实一致性评测；页面可见数据来自 CNN/DailyMail、XSum 等摘要评测分布，不是本仓编码会话归档。
- 官方 §4.2 的组件选择依赖 SummaC 验证集消融；QAFactEval-NLI 还涉及合成或监督训练。不能把论文最优组件或分类阈值视为跨域免校准配置。
- 本次只完整取得方法与前半实验设置；总体结果、相关性与限制章节未完整取得，因此不引用那些部分的额外数字或结论。

### 6. 本仓现状（静态核对，未改产品）

- `src/rooms/fold-quality.mjs:9-20` 明确是零模型调用的机械字符串匹配，不做语义判断；`constraintRecall`、`failureRecall`、`unknownIds`、`outOfRangeLater` 与结构检查可继续作为并列指标，但不能当作 QAFactEval 或事实正确性的替代。
- `src/engine.mjs:1725-1743` 在机械追加约束与最近访问文件之前单独保存 `modelText`。若做离线比较，模型原文与最终产物必须分开评分，否则机械兜底会被误记为模型能力。
- `scripts/archive-fold.mjs:74-92` 能读取多帧 zstd 原始会话事件，`lastOfflineSummary` 是既有离线归档摘要入口。但 `src/rooms/offline-fold.mjs:267-270,339-364` 表明摘要生产输入会跳过 `tool/result`、保留用户/助手文本并加入压缩后的 `tool/call` 行；**这个生产输入不是完整评测证据闭包**。
- `scripts/graph-audit.mjs:160-187` 的 `loadSessionGraph` 会重放 delta。图适合作机械索引与定位，不应只 `JSON.parse(graph.json)` 把上一回合基线当最新真相，也不应让派生图替代原始证据自证。
- `scripts/compare-models.mjs:1-21,161-175` 提供显式离线实验与逐样本保存的参照，但当前 `assessSummary` 只统计长度、章节与约束 bullet，不含 QA 事实一致性评测。

## 对本仓的明确结论：做

### 一个可落地候选：独立离线 `archive-qa-eval` 小试验（后续另刀）

先做**人工金标引导的 QA shadow 评测**，再决定是否运行官方模型链。默认只读既有归档，输出到独立实验目录，不接入 `summarize()`、`compactRegion()` 或 fold 接受/拒绝逻辑。

1. 选最多 **12 份**既有归档 fold，覆盖失败边、工具证据、多轮 fold、机械追加与截断；类别不存在就记未覆盖，不补造样本。
2. 冻结 `sessionId + fold range`、摘要哈希、`modelText`（若仍有）与最终产物、graph 基线哈希与 delta 回放状态。
3. 证据源回查原始会话闭包：用户/助手消息、`tool/call`、`tool/result`、退出码与实际文件证据。生产摘要的压缩输入只作被评对象上下文，不作唯一真值来源。
4. 每题保存：`selectedAnswer`、问题、`IsAnsweredSumm`、源文回答或 `not-found`、`IsAnsweredInput`、重叠判断/分数、证据 seq/path、备注。人工先建立金标；自动 QG/QA/LERC 后续只能在该金标上校准。
5. 聚合时同时报告选题数、过滤数、源文不可答数、实际计分题数与逐题记录；过滤后 0 题记 `unscorable`。模型原文与最终产物分开，现有约束/失败召回、未知/越界 id、空摘要与截断并列报告，不合成唯一质量总分。

**验收判据：**

- 样本数不超过 12，至少 **3 份双人复核**；所有分歧保留并裁决，标注指南不可重复时停止自动化扩张。
- 每一道进入评测的问题都有完整的答案对、过滤/可答性状态与证据指针；可答题缺证据指针、不可答题缺 `not-found` 原因，均判不通过。
- 每个聚合分都能由逐题记录重算，且同时带 `selected / filtered / unanswerable / scored` 四个计数；0 道计分题不得产生满分。
- 自动链若进入后续实验，必须先报告相对人工金标的逐题错误、聚合偏差方向、调用失败与成本；没有本仓校准结果，不预设论文数字为验收线。
- 小试验阶段保持 **0 次付费评委调用、0 次 fold 热路径接入、0 个 live home 写入**；若未来显式测试本地或付费模型，必须另开离线任务并单独授权与记账。

## 对本仓的明确结论：不做

1. **不把 QAFactEval、FActScore 或任何付费评委默认放进 fold 热路径**，不增加隐式二次生成、自动重试、自动重写或默认开启的付费开关。
2. **不让评测分改变 fold 接受/拒绝行为**，不把评估文本注入热清单，不改现有零模型 `fold-quality` 边界。
3. **不把 QA 重叠分解释为源文覆盖率、客观真理性或完整摘要质量**，不与约束/失败召回、结构和截断指标混成一个分数。
4. **不把摘要生产时裁剪后的输入当完整证据源**，不拿旧摘要或派生图作为自身真值，不用评委参数记忆补证据。
5. **不把源文不可答直接标成矛盾**，不把过滤后零问题当满分，不静默丢弃空摘要、生成失败或截断样本。
6. **不直接移植 SummaC 阈值或论文收益数字**，未在本仓人工金标上校准前，不引入官方模型链作为生产依赖。

## 一句话蒸馏

> QAFactEval 的可借鉴点是“从摘要选题，用源文回答，再比较答案并保留逐题诊断”；它适合作为本仓离线 shadow 评测候选，但不测源文覆盖，也不能替代 FActScore 的原子事实支持比例或本仓现有机械指标，必须先建小样本证据金标，且永远不把未校准付费评委默认塞入 fold 热路径。
