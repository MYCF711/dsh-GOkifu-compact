## 1. 它测了什么（原文事实，**待核实**：我们没有复跑这 18 个模型）

- 评测 **18 个模型**，含 GPT-4.1 / Claude 4 / Gemini 2.5 / Qwen3 等；
- 任务：**扩展版 Needle-in-a-Haystack**（语义匹配而非字面匹配）+ 干扰项 + haystack 结构变化 +
  **LongMemEval**（对话式长期记忆）+ 「重复词」合成任务；
- 结论：**模型并不均匀地使用上下文**；输入越长，表现越不稳定，而且退化方式**不均匀**
  （不是"超过某长度突然崩"，是随长度和内容形态起伏）。

## 2. 四条能直接对应到我们代码的发现

| 原文发现 | 我们这边对应的地方 | 结论 |
|---|---|---|
| **干扰项（distractors）显著拉低表现**，即使任务本身很简单 | 热清单里的「历史」段：与本步无关的旧条目也是干扰项 | ⚠️ 热清单不只是"占 token"，**无关行还在主动伤害准确性** ⇒ 见候选 K-6 |
| **结构影响结果**（结构化 haystack 优于杂乱堆砌） | 我们用 `ROOT USER / CONSTRAINTS / LEARNED / WORKING / OPTIONS` 分节 | ✅ 分节不是排版洁癖，是**有效手段**；继续保留 |
| **needle 与被问问题的相似度**影响召回 | 我们的折叠摘要若与之后的提问用词差异大，召回会掉 | ⚠️ 呼应 K-1（召回优先）：**保留原话（verbatim）比改写更抗漂** —— 我们 `CONSTRAINTS_VERBATIM` 的策略是对的 |
| **LongMemEval（对话记忆）** 是独立难点 | 我们的棋谱就是"跨会话记忆"这一档 | ✅ 与 Anthropic 的"结构化笔记"同向；也说明**评测该按 LongMemEval 的思路做**（多轮、跨会话、时间推理） |

## 3. 一句话判读

> 「长上下文不是免费的容量，是**会主动掉准确率的**东西」——
> 这条把我们的两条设计从"偏好"升级成"必要"：
> ① 折叠要**早**（别等快满了才压）；② 热清单要**只留本步要用的**（无关行是干扰项，不是零成本）。

## 4. 由此立的新候选

- **K-6：热清单「历史」段的干扰项治理** —— 现在历史段按"最近 N 条"排，
  与本步任务（当前路径 / 正在做什么）无关的条目同样是干扰。
  做法候选：历史段按「与本步 WORKING 路径的相似度」排序或过滤，而不是纯时间倒序。
  **卡在哪**：要先能量化"无关历史行"的比例（读 `ledger-budget.json` 与渲染文本），否则又是凭手感。
