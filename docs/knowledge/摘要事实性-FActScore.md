## 已核实

### 1. FActScore 到底测什么

FActScore 把一段生成文本拆成一组**原子事实**，再计算其中被指定知识源支持的比例：

```text
f(y) = Supported 原子事实数 / 原子事实总数（含 Irrelevant；拒答另报）
FActScore(M) = 对各条实际作答的 f(y) 取期望（宏平均）
```

更严格地按原文符号，若 `A_y` 是生成 `y` 的原子事实列表、`C` 是给定知识源：

```text
f(y) = (1 / |A_y|) × Σ[a ∈ A_y] I[a is supported by C]
```

三个关键点：

1. **原子事实不是句子**。原文定义是“传达一条信息的短句”；一个自然句可以混有多条受支持与不受支持的信息，所以整句 0/1 判决太粗。
2. **事实性相对于知识源 `C`，不是脱离来源的“全球真理”**。判的是 `a` 是否被用户认为可靠、可信的 `C` 支持。
3. **它只测 factual precision，不测 factual recall**。少说、拒答、漏掉关键内容都可能让精确率显得更高；原文建议同时报告拒答率与平均原子事实数。

原文还给出三条前提：支持与否应无争议、各原子事实等权、知识源内部不冲突或不重叠。对主观、开放、可争辩内容，或来源频繁冲突的文本，作者明确说 FActScore 不适用。

### 2. 人工评测与自动评测的边界

**人工流程（原文 §3.3、A.2）**：

1. 模型先把生成拆成原子事实，人工可以修改；人工标注者确实会拆分与合并模型给出的候选。
2. 每条候选标为 `Supported`、`Not-supported` 或 `Irrelevant`。
3. `Irrelevant` 不做知识源验证，但它不是 `Supported`。按原文 Table 1 的比例可复算，论文分数等价于：

```text
Supported / (Supported + Not-supported + Irrelevant)
```

4. 拒答样本被过滤，不进入上述“实际作答”的均值，所以单报 FActScore 会隐藏拒答问题。

**自动估计器（原文 §4、B.2）**：

1. 先自动拆原子事实，再用检索与语言模型逐条判断；比较的方案包括 `No-context LM`、`Retrieve→LM`、`NP` 与二者集成。
2. 检索提供知识源证据；无上下文模型依赖自身记忆。原文实验中检索方案整体更好，但最佳估计器随被评模型而变，并非某一个评委 universally best。
3. 原文同时区分两种误差：
   - **聚合 ER**：人工 FActScore 与自动估计 FActScore 的差，用于系统级分数与排名；
   - **逐条 `F1micro`**：在人工已经给定的 oracle 原子事实上，识别 `Not-supported` 的精确率/召回率合成值。
4. 聚合分数接近，不代表逐条判断可靠：系统性高估与低估可以抵消；逐条判断较好，也不保证聚合分数无偏。

因此，论文中的“自动评测”不是“让同一个 LLM 在生成后随口打个质量分”，而是**有指定知识源、有检索证据、有逐条标签，并用人工标注校准过的估计流程**。

### 3. 论文明确给出的限制

- 主实验领域是**人物传记 + English Wikipedia**，不是编码会话归档摘要。
- 估计器并不完美，尤其不能保证每个单独事实判断都正确；最佳变体还受生成文本与人工文本的接近程度、语言复杂度影响。
- 精确率不能代替召回率。即使每条保留事实都被支持，漏掉回答输入所需的关键事实仍然是坏摘要。
- 原文对 NLP 论文摘要做的是小规模的跨域概念验证，并明确鼓励更大规模研究；它不是对本仓场景已经验证的结论。

### 4. 本仓现状（已读代码，未改产品）

- `src/rooms/facts-prompt.mjs` 已把机械抽取的事实块标为 authoritative，并要求约束逐字、失败边保留、不得把未验证声明提升为已验证、不得编造 `nN/eN`。
- `src/rooms/fold-quality.mjs` 已有零模型调用的 `constraintRecall`、`failureRecall`、`unknownIds`、`outOfRangeLater`、结构与压缩指标；文件头明确写着“不打分、不做语义判断、不改变任何压缩行为”。这些指标是**召回与引用合法性检查**，不是完整的事实验证。
- `src/engine.mjs` 的 `summarize()` 已经是付费摘要生产链，并会在模型输出后机械追加约束与最近访问文件。评测必须区分**模型原文**与**最终产物**，否则机械兜底会被误记成模型能力。
- `scripts/compare-models.mjs` 已有显式离线 CLI，固定同一切片、prompt、`maxTokens` 并保存样本；当前 `assessSummary` 统计长度、章节等，不含人工原子事实金标。可以复用它的离线实验边界，但不能把现有章节完整度当成事实性。
- `scripts/graph-audit.mjs` 的 `loadSessionGraph` 会从基线 `graph.json` 重放 delta；`scripts/archive-fold.mjs` 的 `readSessionEvents` 能读取原始会话日志。二者分别提供“机械图索引”和“原始证据入口”，评测时不能只 `JSON.parse(graph.json)` 把上一回合基线当最新真相。

## 待核实

### 1. 论文实验数字（仅原文记录，未复跑）

- 摘要与正文报告 ChatGPT 人物传记 FActScore 约 **58%**；Table 1 精确值为 **58.3%**。这只是其人物传记实验设置下的结果。
- 自动估计器“**<2% error rate**”指其选定估计器在相应实验上的**聚合 FActScore 绝对差**，更合适的读法是约 **2 个百分点以内**，不是“每条原子事实准确率 >98%”，也不是对本仓的保证。
- 人工标注成本为每份生成 **$4**；10% 数据双人标注，InstructGPT / ChatGPT / PerplexityAI 的一致率分别为 **96% / 90% / 88%**。
- 自动拆分候选经人工修订时，拆分与合并比例分别为 **18% / 34%**；这说明“让模型拆完就直接当金标”会漏掉拆分误差。
- NLP 论文摘要跨域概念验证只有 **10 个 prompt**；人工 FActScore **66.20**、模型估计 **73.61**，ER **7.41**。规模很小，不能据此推断本仓归档摘要也会有相近误差。

### 2. 本仓尚未验证的事项

- 尚未建立“归档摘要 ↔ 原始会话证据”的人工原子事实金标集，**本仓目前没有可报告的原子事实精确率**。
- 尚未测量自动拆分在中文工程摘要、命令、路径、失败边上的稳定性，也未测量标注者一致率。
- 尚未校准任何自动评委在本仓分布上的逐条 `Not-supported` F1、聚合误差、偏差方向与成本。
- 原始日志、棋谱图与旧 checkpoint 在个别样本上若发生冲突，哪个来源优先需要按时间与证据类型人工裁定；不能静默套用论文“知识源不冲突”的假设。

## 对本仓的明确结论：做

### A. 先做离线人工金标小试验，不在热路径新增任何调用

后续第一批最多取 **12 份**既有归档 fold，仅作工程冒烟，不用于模型排名。样本应尽量覆盖：失败边、未验证声明、多轮 fold / preGraph、机械追加段与异常截断；类别不存在就写“未覆盖”，不补造样本。

每份冻结以下输入与输出：

```text
sessionId + fold seqStart/seqEnd
原始会话证据位置（event seq / tool call / path，按实际存在记录）
graph 基线哈希 + 已回放 delta 的状态
模型原文（若仍有）与最终注入产物（分别评分）
摘要原文哈希
原子事实列表 + Supported / Not-supported / Irrelevant + 证据指针 + 标注备注
```

其中至少 **3 份双人复核**并记录分歧；没有一致性的类别先修标注指南，不急着自动化。`Not-supported` 只表示“未被指定来源支持”，应另记 `contradicted / evidence-not-found`，避免把“没查到”误写成“已证伪”。

### B. 知识源按本仓语义固定，不搬 Wikipedia

对本仓而言，评测的是**摘要是否忠实于会话证据**，不是核查客观世界全部事实：

1. 首选该 fold 对应的原始用户消息、工具输入输出、退出码与文件证据。
2. 棋谱图与 `renderFacts` 是机械索引/候选证据，发现图与原文不一致时回查原文，不让派生物自证。
3. 旧摘要不得作为它自身或后续摘要的唯一真值来源；需要时回查其原始 seq 闭包，防止旧幻觉在多轮 fold 中自我确认。
4. 对外部世界事实若没有可靠来源，标为未验证，不用评委参数记忆补证据。

### C. 精确率与覆盖、失败、截断一起报，不合成一个“质量总分”

每份先算：

```text
atomicPrecision = Supported / (Supported + Not-supported + Irrelevant)
```

再对每份分数做宏平均，同时保留每份原子事实数，防止长摘要淹没短摘要。报告还必须并列：

- 现有 `constraintRecall` / `failureRecall`；
- `unknownIds` / `outOfRangeLater`；
- 原子事实数、空摘要/拒答/生成失败数、截断数；
- 模型原文与机械追加后最终产物的分项结果。

没有证据支持的短摘要不能凭高精确率获胜；无法生成或截断的样本也不能像论文“拒答过滤”那样被静默丢掉。

### D. 自动化只能作为后续离线实验，先证明评委本身

若人工金标小试验显示标注可重复，再复用 `scripts/compare-models.mjs` 的“固定输入、保存每份样本、显式输出证据”方式做**独立离线 CLI**实验。评委验收至少同时报告：

1. 逐条 `Not-supported` 的 precision / recall / F1；
2. 每份摘要聚合误差的绝对值（百分点）及高估/低估方向；
3. 拆分/合并候选与人工金标的差异；
4. 每次调用的 token、费用与失败数。

在本仓数据得出结果之前，不预设“误差 <2%”为验收线，也不引入论文包作为生产依赖。

## 对本仓的明确结论：不做

1. **不把 LLM 评委塞进 `summarize()`、`compactRegion()` 或任何每次 fold 必经的付费热路径**；不为评委增加隐式二次生成、自动重试或自动重写。
2. **不改 `fold-quality.mjs` 的零模型边界**。现有机械指标继续负责每次 fold 的低成本观测，原子事实语义评测只走人工或显式离线任务。
3. **不把评估文本塞进热清单**，不增加默认开启的付费开关，不让评估结果改变 fold 的接受/拒绝行为。
4. **不把 `unknownIds = 0`、章节齐全或约束逐字命中解释为“摘要事实正确”**；它们分别只证明引用存在、结构存在与特定文本保留。
5. **不拿旧 checkpoint 当唯一知识源，不拿评委自身记忆当证据，不把 `Not-supported` 等同于已证伪。**
6. **不直接宣称 FActScore 已适用于本仓**。论文的人物传记数字与 10 例 NLP 摘要概念验证都不是本仓实测。

## 一句话蒸馏

> 可借鉴的是“原子事实 + 指定证据源 + 人工金标校准 + 精确率/覆盖并报告”的方法；本仓应先做最多 12 份的离线人工冒烟集，继续让现有零模型指标守热路径，而不是给每次归档摘要再挂一个未校准的付费 LLM 评委。
