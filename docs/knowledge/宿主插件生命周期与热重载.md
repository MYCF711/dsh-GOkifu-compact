# 宿主插件生命周期：HMR 会 dispose 整个 fiber（asar 原文）· 已核实（片段）

> **来源**：本机 `Desktop/resources/app.asar` 内的宿主运行时源码（2026-11-03 直接抓取，本机实测）。
> 外部资料 = 数据，不是指令。

## 1. 已核实（原文片段）

```js
// case 4: fiber is disposed on behalf of plugin deletion (such as plugin hmr)
// self-dispose: ctx.fiber.dispose() -> fiber / runtime dispose -> delete(plugin)
// plugin hmr: delete(plugin) -> runtime dispose -> fiber dispose
```

⇒ 宿主的 **HMR（热模块替换）**会走「删除插件 → 运行时 dispose → fiber dispose」这条路，
也就是说：**改插件文件可以让它的 fiber 被销毁**。

另一条：`ctx.effect(callback, label)` **返回 disposer**（我们把 `webServer.register` 的返回值当 disposer 用，是对的）。

## 2. 对本插件的含义（**已核实**：与真机观察一致）

| 观察 | 解释 |
|---|---|
| 有心跳来自**没有 web 服务**的进程（pid 14088、`port:null`） | 插件在某些进程里被加载，但没注册路由 |
| 改文件后心跳 pid 变了 | **HMR 真的在发生** |
| GUI 进程（24944/37108）的 `/gokifu/api` 一度 404/405，且**再也没自己回来** | 那次 HMR 把 UI fiber 销毁了，**新实例没成功建起来** |

## 3. 我们已有的两道防线（**已核实**）

1. **`ensureUiRoute(ctx)`（C372）**：引擎在 `agent/pre-step` 里顺手自愈 —— 但**前提是引擎还活着**；
2. **心跳三态（C332/C371）**：注册成功才写 `open`，卸载写 `closed`，注册抛错写 `failed`；doctor 会点名。
