| # | 结论 | 数字 / 证据 | 谁在保证 |

## B. 已否掉（做过、验过、不成立 —— 比"没试"值钱）

| # | 曾经的想法 | 为什么否掉 |
|---|---|---|
| B1 | 「热清单瘦身」是首要优化 | 97% 走缓存 ⇒ 450 tok/步 是零头（A1） |
| B2 | 翻转 `replace` → `append` 能省钱 | 断点只占 2.6%，而 append 会让 surface 长期背历史清单（A1） |
| B5 | 「少让模型说」能省折叠成本 | 输出只占 fold 成本 **3.7%**（A12）——贵的是输入量与 fold 次数 |
| B6 | 「L4/L5 少列几条失败边」能把超预算压掉 | 契约明令禁止（「连 L5 都超预算时也必须给完整清单」）—— 5 条测试当场拦下（C245 初版，已回滚） |
| B7 | 「压缩标记图例」能省 token | 省 15 token，但渲染输出被 sha 逐字节钉住 ⇒ 6 条守卫变红（C246，已回滚） |
| B8 | 「自适应预算」能消掉超预算 | 对目标会话不触发（floor 213 < 500），且与 C59「超限自报」正面冲突（第 31 轮，已回滚） |
| B9 | 收尾去重（60s 时间窗） | 与 C216「取消归档后再归档必须能重新收尾」同形状；且实测回声只多一次落盘、不多一次模型调用（第 49 轮，已回滚） |
| B3 | 工具结果每步清理 | 单条根本不大（A10） |
| B4 | 为渲染加缓存 | 22 ms 是 CPU、典型会话 <3 ms，失效风险 > 收益（A2） |
